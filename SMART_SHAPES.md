# Smart Shapes — scripting reference

A **smart shape** is a Shape Library item whose visible content is generated by a small
JavaScript script you write, instead of being fixed geometry. The container itself never
draws a box — it's a plain, styleable item (Fill/Stroke/Stroke-width/Text-color/Font all work
on it normally), and your script decides which of the shapes it generates ("children") use
that styling. Built-in examples: an analog clock, a block arrow, a bar chart, a connected countdown
dial, live clock, stopwatch, and ruler.

This file is a reference for **writing** a smart shape's script — by hand, or by handing this
file to an AI assistant along with a description of what you want. It does not cover using the
app as an end user; see [README.md](README.md) for that.

## Quick start

1. Open the shape library → **Actions** → **Add smart shape…**.
2. Pick a starting point from the **Template** dropdown (Clock / Live clock / Stopwatch / Ruler / Number control / Gauge / Arrow / Arc / Timer / Chart /
   Minimal / Blank), or just start typing your own script over it.
3. Give it a name and click **Create**. The new shape appears in the library, ready to place.
4. On the canvas, double-click a placed smart shape to enter its **edit mode** (solid blue
   corner markers) — drag its handles there to change its state. Double-click again, or click
   outside it, to leave.

For a grouped smart shape, the first double-click enters group editing; double-click the
member again to enter its smart-shape controls.

Separate clicks on overlapping shapes cycle through the layers. A double-click or double-tap
keeps the smart shape the gesture started on, so entering its controls does not select a shape
underneath. You can also cycle to a covered smart shape, then double-click to open its controls.

Built-in catalog entries can be placed directly from the expanded library browser. To customize
one, use **Copy to My shapes** first; built-in definitions are read-only, while their category
memberships can be organized. Pinning an entry adds a
reference to the quick popup's working collection and does not create an editable copy.

To edit your library definition, choose **Edit script…** in its browser details (also available
for unpinned entries). The expanded editor shows the entry name in its heading and gives the
remaining space to the script. Rename entries through **Edit details**; the script editor only
changes code. **Save changes** updates that entry and regenerates
its PNG preview. The definition's saved state, dimensions, and appearance are preserved.
`initState()` and `initStyle()` run afresh when placing each instance; saved values supply defaults
for omitted hooks or style fields. Existing canvas instances keep their own scripts and state.
If an entry contains multiple smart shapes, each has a numbered **Edit 1**, **Edit 2**, … action. Export
the library to retain your changes.

## A complete worked example

This is an **adaptation of the Minimal template**: a circle with one draggable radius handle.
Its shared `_layout()` helper clamps the displayed radius whenever the container is resized,
and keeps the drawing, handle, and hit test aligned. The picker’s Minimal template uses the
stored radius directly and only clamps it during a handle drag.

Paste this entire expression into the Script field:

```js
({
  initState(){ return { r: 45 }; },

  // Keep the circle's geometry within the box, even after a resize.
  _layout(state, w, h){
    const maxR = Math.min(Math.abs(w), Math.abs(h)) / 2;
    const minR = Math.min(5, maxR); // Tiny boxes need a radius smaller than 5px.
    const requested = Number.isFinite(state.r) ? state.r : 45;
    const r = Math.max(minR, Math.min(maxR, requested));
    return { cx:w/2, cy:h/2, r, minR, maxR };
  },

  children(state, style, w, h){
    const {cx, cy, r} = this._layout(state, w, h);
    return [{
      type:'ellipse', x:cx-r, y:cy-r, w:r*2, h:r*2,
      color:style.color, size:style.size, strokeOn:style.strokeOn,
      fill:style.fill, fillColor:style.fillColor,
    }];
  },

  handles(state, w, h){
    const {cx, cy, r} = this._layout(state, w, h);
    return [{id:'r', x:cx+r, y:cy}];
  },

  hitEdit(state, lx, ly, w, h){
    const {cx, cy, r} = this._layout(state, w, h);
    return Math.hypot(lx-(cx+r), ly-cy) < 12 ? 'r' : null;
  },

  dragEdit(state, handle, lx, ly, w, h){
    if(handle !== 'r') return state;
    const {cx, cy, minR, maxR} = this._layout(state, w, h);
    const r = Math.max(minR, Math.min(maxR, Math.hypot(lx-cx, ly-cy)));
    return {...state, r};
  },
})
```

Resizing changes the displayed radius without changing saved state. Enlarging the box can restore
the stored radius; dragging the handle saves a new radius. Stroke thickness and the app’s handle
markers can extend beyond the circle’s geometry. See [Bounds](#your-shape-is-responsible-for-its-own-bounds)
for shapes that need all painted content inside the box.

## The script object

The **script** field takes a single JavaScript **expression** — not a series of statements —
that evaluates to an object, conventionally written as an object literal:
`({ children(state, style, w, h){ ... }, ... })`.
It's compiled with `new Function('"use strict";return (' + yourScript + ');')()`, so:

- Both `{ ... }` and `({ ... })` work: the compiler wraps your expression in parentheses.
  Templates use `({ ... })` for clarity.
- No `import`/`export`, no top-level `let`/`const`/`function` declarations outside the object
  expression. Helper functions are fine as **methods** on the object (see `_layout()` in the Timer
  template) — the app always calls your hooks as `def.hookName(...)`, so `this` inside a method
  correctly refers to your own script object.
- **Hooks must return synchronously.** Do not declare hooks `async` or return promises: the
  runtime serializes their immediate return values and does not await them. Use `refreshMs()`
  for periodic updates.
- The only thing your script ever gets handed is plain, already-computed data (state, style,
  width, height, pointer coordinates) — never `ctx`, `document`, or any other app internal.
- Each placed instance has an independent JavaScript environment, including copies using identical
  source. Methods may share helpers through `this`, but globals and object-local mutations are
  disposable caches. Keep durable values in the returned state; Workers expire or can be evicted.

Only `children()` is required for an unversioned smart shape. Optional hooks initialize state or
appearance, define interactions, request live updates, or configure behavior in an HTML export.
The table below describes the original contract, which remains supported. Components explicitly
using `apiVersion:2` extend it as described under [Connected components](#connected-components-api-v2).

| Hook | Called | Arguments | Returns |
|---|---|---|---|
| `initState()` | When creating a definition for its preview, and afresh for each placement | — | a plain, JSON-safe state object |
| `initStyle()` | After `initState()`, when creating a definition and for each placement | — | a partial style/size override (see below) |
| `children(state, style, w, h, editing)` | When inputs change or a refresh is due | current state, resolved style, container width/height, `true` in editor edit mode and in interactive HTML | array of child shape descriptors |
| `refreshMs(state)` | After generating live children, in the same sandbox call | current state | desired refresh interval in milliseconds; `0`, `null`, or `undefined` stops automatic refresh |
| `exportBehavior` or `exportBehavior(state)` | Interactive HTML, after state or size changes and on refresh | current state for the function form | `{move, rotate, resizeWidth, resizeHeight}` booleans, all default `false` |
| `handles(state, w, h, style)` | In editor edit mode and interactive HTML | state, width/height, resolved style | array of `{id, x, y, kind?, editorOnly?}` |
| `hitEdit(state, lx, ly, w, h, style)` | On press in editor edit mode or interactive HTML | state, press position (**local** coords, see below), width/height, resolved style | a handle `id`, or `null`/`undefined` if the press missed every handle |
| `dragEdit(state, handle, lx, ly, w, h, style)` | While dragging a handle (continuously), and once on a zero-movement click | state, the `id` returned by `hitEdit`, current pointer position (local coords), width/height, resolved style | the **new** state object |

State is never mutated in place — `dragEdit` returns a fresh object (`{...state, ...}` is the
usual pattern). A completed click or drag creates one undo entry if its validated state differs.
Quick clicks are processed in input order, including when release precedes the hook reply.
A following nudge or style change keeps a released handle action and its own undo entry. An
unreleased press is cancelled when another edit begins. Escape, undo, tool changes, and document
replacement cancel pending actions. Smart editing tracks one pointer at a time; additional fingers
cannot release or cancel the active finger's press.

Every hook reply is validated before rendering, export, preview generation, or state updates.
`children()` returning `[]` is valid. Invalid individual children are skipped with an error.
If the whole response is rejected, an unversioned shape's live refresh keeps the last valid drawing,
or stays empty if none exists, and reports an error. API v2 components show an unavailable state.
Invalid state updates keep the previous state.
Missing optional hooks return no handles or make no state change.
On static export failure, a cached drawing is used only if its script, state, style, size, and non-editing
mode all match. Otherwise that unversioned smart shape is omitted. Components show an unavailable
drawing or status card; marked authoring controls never enter an exported drawing.

### `initState()`

Returns the state your shape starts with. Called once per placement; `w`/`h` aren't decided
yet at this point, so state can't depend on them (the Minimal template's radius, for example, is
a plain tuned literal, not a fraction of the box).

```js
initState(){ return { value: -45 }; }
```

### `initStyle()` (optional)

Lets a script override the initial style/size of each new placement. Return a partial object;
omitted fields keep the library definition's saved values. When authoring a new definition, those
base values come from the defaults below. Recognized fields, each individually validated (an
unknown/wrong-typed field is just ignored, not rejected):

| Field | Accepted value / clamp |
|---|---|
| `color`, `fillColor`, `textColor` | CSS hex: `#RGB`, `#RGBA`, `#RRGGBB`, or `#RRGGBBAA`; named colors and `rgb()` are not accepted |
| `fill`, `strokeOn` | boolean |
| `size` | 1–60 |
| `fontFamily` | `sans`, `serif`, `mono`, or `cursive` |
| `fontSize` | 6–400, rounded |
| `w`, `h` | 20–2000, rounded |

Every field is still fully adjustable afterward via the ordinary toolbar/resize handles —
`initStyle()` only ever affects the single moment of creation. Example (the Chart template):

```js
initStyle(){ return { fontSize: 12, strokeOn: false, w: 240, h: 160 }; }
```

Without an `initStyle()`, a newly authored definition starts black, unfilled, stroke on, at 180×180,
using the toolbar's current stroke width, font, fill color, and text color. Placements then inherit
that definition's saved style and size.

### `children(state, style, w, h, editing)` (required)

Returns an array of plain **child shape descriptors** — the actual visible content. These are
**never stored in the scene**; they're cached for live rendering and refreshed when script,
state, style, size, or edit mode changes, or when an optional refresh interval expires. Exports
request fresh children. See [Child descriptors](#child-descriptors) below for their shape.

`editing` is `true` only for the one instance currently in interactive edit mode (by identity,
not type) — `false`/`undefined` otherwise, including during PNG/SVG export and the initial HTML
snapshot. Interactive HTML calls it with `true` so operational controls stay visible. Mark
authoring-only child descriptors **and their handles** with `editorOnly:true` to omit them from
all exported drawings and disable their actions in HTML.

### `refreshMs(state)` (optional)

Requests periodic regeneration of this instance's children and edit handles. Existing scripts that
omit this hook keep their ordinary cache behavior. Return a positive, finite number of milliseconds;
the app clamps it to **100–60,000 ms**. Return `0`, `null`, or `undefined` to stop refreshing, for
example when a stopwatch is paused. Invalid values disable refresh and report an error without
discarding valid children. A throwing or unresponsive hook uses the normal sandbox failure/backoff
path, retaining the last valid drawing.

```js
refreshMs(state){ return state.startedAt == null ? 0 : 100; },
```

See [Live updates and exports](#live-updates-and-exports) for timer lifecycle, timestamp-based
state, and the difference between static snapshots and interactive HTML.

### `exportBehavior` or `exportBehavior(state)` (optional)

An object, or a synchronous function returning one, with optional boolean flags `move`, `rotate`,
`resizeWidth`, and `resizeHeight`. All flags default to `false`. The function receives a copy of
state; modifying it does not update the saved instance. Interactive HTML reads these permissions
after state or size changes and on refresh. They do not change editing behavior in SimpleCanvas.
See [HTML export behavior](#html-export-behavior) for examples and creator-only permission controls.

### `handles(state, w, h, style)` (optional)

Returns `[{id, x, y, kind?, editorOnly?}, ...]` — one entry per point `hitEdit`/`dragEdit` can grab, in the
same **local** coordinate frame as `children()` (container's own top-left as origin).
Every interactive ID must be declared here; a script with no handles cannot receive a valid
handle action. The app draws a small solid-blue dot for each `'drag'` handle. It draws no dot
for `'click'`, `'number'`, or `'text'` handles: draw their buttons or labels yourself in `children()`. The four corner
markers indicate edit mode and are not interactive handles.
IDs are unique, nonempty strings of at most 64 characters. `hitEdit()` must return one of these
IDs or `null`/`undefined`. A response can contain at most 128 handles. An optional boolean `editorOnly`
marks handles that are usable only in the editor; interactive HTML never runs them.

`kind` is optional, defaulting to `'drag'` (a continuous drag point, like a resize handle).
Mark it `'click'` for a discrete, one-shot action — an add/delete button, a toggle — rather than
something meant to be dragged around:

```js
handles(state, w, h){
  return [
    { id:'hand', x: cx + Math.sin(a)*r, y: cy - Math.cos(a)*r },   // 'drag' (default)
    { id:'add', x: addBtnX, y: addBtnY, kind:'click' },
  ];
}
```

Without `kind:'click'`, small pointer movements during a press can call `dragEdit` repeatedly
and repeat the action (for example, inserting several new bars from a single tap on "+").
`kind:'click'` makes the app resolve it exactly once, from the original press position, on release.

`kind:'number'` opens a host-owned number-entry dialog on release. Supply a finite numeric `value`
and optional finite `min`, `max`, and positive `step` metadata; `min` must not exceed `max`.
The host validates the entry and, on acceptance, calls `dragEdit` once with the accepted **number
in `lx`**, rather than a pointer coordinate. `ly` is zero; identify this case
by the handle ID. Cancellation leaves state unchanged. Keep domain-specific snapping and validation
in the script's `dragEdit`/`compute` hooks as well. This handle works in editor edit mode and offline
HTML; `editorOnly:true` can restrict it to authoring.

```js
{ id:'entry', x:w/2, y:h/3, kind:'number', value:state.value,
  min:-20, max:40, step:0.25 }
```

`kind:'text'` provides host-owned single-line text entry. Its `value` is a string
of at most 2,000 UTF-16 code units. Optional metadata is integer `maxLength` from 0 to 2,000,
Boolean `required`, and a `placeholder` string of at most 120 characters. Successful Enter or Apply
passes the accepted **string in `lx`**, with `ly` zero. The script validates domain rules before
the dialog closes; a rejected update keeps it open. Cancel, Escape, tab changes, and stale gestures
leave state unchanged. Scripts draw the entry field and receive values; they do not create DOM inputs.

```js
{ id:'entry', x:w/2, y:h/3, kind:'text', value:state.text,
  maxLength:2000, required:false, placeholder:'Enter a message' }
```

Text and number handles can supply an `inline` descriptor to place the host-owned field directly
over the drawn control. Coordinates use the same local frame as `children()` and the rectangle
must fit inside the component. The field follows the component's position and rotation.

```js
{ id:'entry', x:w/2, y:h/2, kind:'text', value:state.text, label:'Message',
  inline:{x:0,y:0,w,h,fontSize:18,mode:'submit',submitButton:true} }
{ id:'B6', x:cellX+cellW/2, y:cellY+cellH/2, kind:'text', value:state.cells.B6 || '',
  label:'Cell B6', ref:'B6', editorOnly:true,
  inline:{x:cellX,y:cellY,w:cellW,h:cellH,fontSize:16,mode:'edit',
    align:'right',navigation:'horizontal',references:true} }
```

`mode` is `submit` (the default) or `edit`. They share placement, focus, validation, and the
editor/HTML implementation, with different commit behavior:

| Interaction | `submit` | `edit` |
| --- | --- | --- |
| Enter | Validate and commit; keep focus for another submission | Validate and commit; finish editing |
| Tab / Shift+Tab | Validate and commit; allow normal focus movement | Validate and commit; move to a neighbouring field when navigation is enabled |
| Click outside | Discard the unsubmitted draft | Validate and commit the edit |
| Escape | Discard the draft | Discard the draft |

`fontSize` is in component units. Optional `align` is `left`, `center`, or `right`.
`submitButton` defaults to visible in submit mode; set it to false to hide it. Edit mode never
shows the button. An optional top-level `label` of at most 100 characters names text or number
fields for assistive technology and dialog entry. Existing handles without `inline` retain dialog
entry. The older Number control uses that numeric dialog. The former top-level `rect`, `fontSize`,
and `align` editing metadata are rejected; place field geometry and styling inside `inline`.

`navigation:'horizontal'` opts into left/right neighbouring inline text or number fields for Tab/Shift+Tab.
An inline text or number handle can set top-level `readOnly:true`. Its native field remains selectable
and copyable, defaults to edit mode, and never calls `dragEdit` or submits a value. In edit mode,
Enter closes it and Tab can navigate normally. It can still be a formula-reference target. Spreadsheet uses this for
connected dataset cells by default; its optional bound-cell editor is described below.
`references:true` enables formula reference picking: when text begins with `=` and the caret
follows `=`, `(`, `,`, `;`, an operator, or a comparison, clicking another text handle in the same
component inserts its top-level `ref` (at most 64 characters, such as `B3`). Dragging across cells
inserts `first:last`; clicking again immediately replaces the inserted reference. Pointed cells
are outlined. These capabilities are optional; an editable title needs neither.

An ordinary accepted edit passes the string or number as `lx` to `dragEdit`, with `ly` zero. The host
validates numbers and text constraints before acceptance; rejected input stays open for correction.
Spreadsheet formula errors are valid saved cell text and are shown in the sheet. Changed state
creates one undo step; saving the same state again does not create another step. Switching tabs,
Undo, or stale component ownership cancels pending entry. Inline editing does not pause simulation;
an existing user pause is respected. `editorOnly:true` keeps spreadsheet cell authoring out of HTML,
while its connected values continue to calculate there.

The handle itself does not emit a pulse. The built-in Text input and Number input use `submit`
mode and implement `submitted` through their state/transition contract, so another accepted entry
with the same value can trigger a consumer again. Do not infer submission from a change to `value`.
[Spreadsheet](examples/spreadsheet.js) uses `edit` mode, horizontal navigation, and reference picking.

### Boolean input switches

An API v2 handle can edit an unconnected Boolean input directly:

```js
{ id:'enabled', kind:'boolean', input:'enabled', value:io.inputs.enabled, x:w-34, y:h-21 }
```

The host validates the declared Boolean input and current value, then toggles the instance's
literal `inputValues` on release. The editor records one undo step; HTML changes remain local to
the reader session. It never calls `dragEdit` or creates a separate state value for the switch.
The host rejects manual changes to a connected input. `io.boundInputs` lists connected input names;
scripts should show the current `io.inputs` value, explain that it is connected, and omit its handle
and hit target when bound. Table sort and Table aggregate follow this contract. Their `showSwitch`
setting hides the control without disabling the input.

### Choice input controls

API v2 `kind:'choice'` handles open a host-owned native selection list over a declared inline box:

```js
{ id:'select', kind:'choice', input:'select', value:io.inputs.select,
  x:140, y:52, inline:{x:0,y:26,w:280,h:52,fontSize:18},
  options:[{value:0,label:'Idle'},{value:1,label:'Running'}] }
```

The target must be an available unconnected numeric input. The host edits `inputValues` directly,
records one editor undo step, and does not invoke `dragEdit`. It rejects stale choices if the source,
current input, or connection changes before acceptance. Escape, clicking outside, or changing tabs
cancels the open control. Reader changes last for the session and reset on page reload.

Supply exactly one of `options` or `table`. Explicit options have unique finite numeric values and
string labels, with at most 1,000 options, 2,000 characters per label, and 500,000 label characters
combined. To use all rows of a connected table without embedding them in a presentation result,
provide `table:{input:'data',labelColumn:'Text'}` instead. The named port must be a table input and
the label column must be a string column; a blank column chooses the first string column. The host
builds options from the full selected row order, assigning indices 0…N−1 and mapping null labels
to empty text. `io.boundInputs` lets scripts hide the manual handle when its numeric input is bound.

### Host-owned table actions

API v2 handles may use `kind:'action'` with one of these bounded descriptors:

```js
{ id:'loadData', kind:'action', x:w/2, y:h-25,
  action:{type:'importDataset', input:'data'} }
{ id:'csv', kind:'action', x:w/4, y:h-30,
  action:{type:'downloadTable', input:'data', format:'csv', filename:'results'} }
```

`input` must name a declared table input. Download format is `csv` or `json`; the host sanitizes
the suggested filename. The script draws the button, declares the handle, and returns its ID from
`hitEdit`. `dragEdit` does not perform these actions. An explicit release opens the host-owned
preview dialog, and its Replace data or Download button performs the final operation. The host
resolves the current connected rows and validates document/instance ownership; scripts receive no
file, DOM, storage, or download access. Pure computation, drawing, and restoration never execute
a click action. Dataset reload uses the separate, explicitly declared trigger contract below.

Dataset enables its import handle only when `allowReaderImport` is true. **Load data…** defaults to
**Keep current columns**: the file must retain existing column keys and types, but may reorder them
or add columns. **Use the file’s columns** replaces the column definitions as well as the records.
This choice is available in the editor whenever file import is enabled; HTML additionally requires
**Allow column changes in HTML export** (`allowReaderColumnChanges`, default false). This setting
does not enable file import by itself.

The preview shows column additions, removals, and type changes, alongside components affected by
the proposed replacement. Deliberate column replacement can leave consumers with configuration
errors; their connections and field selections are retained for correction. Dataset editor follows
the new columns. Spreadsheet keeps its layout and formulas: positional references can read a
different column without producing an error, so the preview also warns authors to review them.
No automatic column mapping or type conversion is performed.

Both modes retain the normal ownership, revision, and table-budget checks. The editor records an
accepted replacement as one undoable change. HTML keeps it only in the current reader session.
Replacement keeps the dataset ID and connections, updates all consumers of that dataset in the
sketch, and allocates fresh row identities. A stale read cannot overwrite a newer accepted revision.
Reload and source Replace/Append/Live actions retain their compatibility checks; selecting the
file's columns is an explicit import-dialog choice, not a persistent schema-changing update mode.
CSV and JSON downloads contain the selected rows in their current order, using
column keys as field names. JSON preserves scalar types and null values. CSV uses comma-separated
fields, CRLF records, standard doubled-quote escaping, and empty cells for nulls; it cannot preserve
every distinction between text, numbers, empty strings, and missing values on reimport. The default
**Spreadsheet-safe** mode prefixes formula-like text cells and headers with an apostrophe; numeric
values remain numeric. **Raw (exact text)** preserves the original text. Both the direct download
dialog and event/trigger-prepared downloads offer this choice. JSON retains the original typed data.
The dialog
previews the result before the user confirms. A paused, partially propagated graph must finish stepping or
resume before downloading, so a file cannot mix intermediate results. These controls are a narrow
local action contract, separate from the component-state [event API](#hybrid-valueevent-ports-event-api-1).

Dataset and Capture row opt in to host-owned result notifications with `eventApi:1`, dedicated
scalar `eventOutputs`, and an `actionEvents` declaration:

```js
// Dataset: accepted import/reload reports the resulting row count.
actionEvents:{importDataset:{success:'loaded',failure:'failed'}},
eventOutputs:{loaded:{type:'number'},failed:{type:'string'}}

// Capture row: successful append reports the zero-based inserted row index.
actionEvents:{appendRow:{success:'captured',failure:'failed'}},
eventOutputs:{captured:{type:'number'},failed:{type:'string'}}
```

The host validates ownership and emits only for the accepted operation or its actionable failure.
An accepted identical file replacement still reports success. Cancelling a dialog, stale work,
ordinary record edits, redraws, and restoration do not emit. Source Replace/Append and Live sync
are not completion producers in this increment. These ports use `eventBindings` when connected
to a receiver; they do not add a current value output or change the existing table/row-count
signals. Route numeric results through Number to text before appending to Memo.

Dataset declares its reload trigger through API v2 metadata:

```js
datasetOwner:'data',
inputs:{data:{type:'table'}, source:{type:'table',optional:true},
  reload:{type:'boolean',default:false}, replace:{type:'boolean',default:false},
  append:{type:'boolean',default:false}},
dataActions(state){return {reload:{type:'reloadDataset', input:'data', trigger:'reload'},
  replace:{type:'replaceTable',input:'data',source:'source',trigger:'replace'},
  append:{type:'appendTable',input:'data',source:'source',trigger:'append'},
  live:{type:'syncTable',input:'data',source:'source',enabled:state.updateMode==='Live'}};},
```

At most eight named declarations are allowed; each name follows port-name rules. The supported types
are `reloadDataset`, `replaceTable`, `appendTable`, `syncTable`, `appendRow`, and `goToTab`.
Table actions require a table `input`; `goToTab` requires a numeric `input` naming the target tab
index and can name a string `parameters` input containing a JSON object, as described below.
Pulse actions name a Boolean `trigger`; `syncTable` instead declares a Boolean `enabled`. Reload has no additional fields; table-copy actions additionally
name their `source` table input; row capture declares the mapping below. Other fields are rejected.
This is not a generic script-effects envelope.
For `reloadDataset`, the host observes a false → true edge only after a healthy live baseline and only while
`state.allowReaderImport === true`. The first complete settlement, pure inspection, historical
replay, reopening, Undo, rewiring, unavailable-input recovery, and enabling reload while already
high establish baselines without requesting file access. At most 64 host data requests can wait in a
document's transient queue. They commit only with their live evaluation and are consumed once after
full settlement; an incomplete paused Step does not dispatch them.

Each Dataset allows one queued or running reload. Further pulses while it is busy do not queue
another read; independent Datasets can read concurrently. Applying their results is serialized
against the latest document data.

Reload rereads only the file previously selected and accepted through **Load data…** for that
instance and table input. The host retains its file handle and delimiter in memory, validates the
new contents and schema, and atomically replaces the data. It does not reuse a stale `File` snapshot.
Browsers with reusable file-picker handles can reread; Safari and ordinary file-input selection
require choosing the file again. Missing or revoked access produces an actionable message and
preserves accepted data. File handles and permissions never enter state, saved files, or HTML.
Changed instance/source ownership and stale asynchronous reads cannot replace current data.

`datasetOwner` names the component's owned table input. The host exposes it as **Owned dataset**
configuration, not a wireable input, and requires one owner per stored table. Its optional incoming
`source` is a normal table connection. Owners must define `compute` and must not define `publish` or
`transition`. The host passes only the owned table to their `compute` inputs and resolved table context;
source and trigger values are sampled separately for declared actions. This keeps stored publication
independent of incoming source and action-trigger availability. Source/trigger dependencies participate
only in explicit action sampling, so a missing source or an owner → transform → owner.source path does
not block stored output. Changing an upstream source or trigger definition re-primes action observation.

`replaceTable` and `appendTable` accept a false → true pulse, then snapshot the complete selected source
after its graph settles for that simulation instant. A source calculation and pulse changing together
therefore use the newly calculated table. An incomplete paused Step cannot dispatch the update. If a
later edit arrives before that instant finishes, the host completes the pending source snapshot against
the committed scene before merging the edit. Once queued, the snapshot stays exact: dispatch never
rereads newer source rows. If Replace and Append rise in the same instant, both updates are rejected.

The host validates destination ownership, revision, schema, and table budgets before committing an
atomic change. Replace keeps the dataset ID and allocates fresh row IDs; it must preserve every existing
column key and type, but may add columns. Append requires exactly the destination's column keys and
types; source columns may be reordered, and values are mapped to destination order. It retains existing
rows and gives new identities to copied rows. The source is never mutated. Source changes without a
pulse have no effect on stored rows in Manual mode. Reopening, Undo, rewiring, and historical replay establish baselines
without copying. The command queue holds at most 64 requests, with one separate bounded error notice
for overflow; queued table snapshots share a 2,000,000-character limit. Failed updates leave stored
output available and show an error through the host.

HTML additionally requires `state.allowReaderUpdates === true`, separately from file-import permission.
The editor uses normal history; reader updates remain local to the session.

`syncTable` is the explicit Live policy: it snapshots the settled Source after a new source
publication, then replaces the destination with the same ownership, schema, revision, queue, and
reader-permission checks. It declares exactly `{type:'syncTable',input,source,enabled}`. Dataset exposes
**Source update mode: Manual / Live**, default Manual. Deliberately enabling Live or changing Source
accepts the current source once; opening, Undo, and historical replay establish a baseline.

Source publication tracking follows output dependencies and stored revisions, not redraws or
component geometry. A successful identical-data source reload propagates through unchanged filters,
sorts, and Spreadsheet results. Editing the destination alone does not refresh its source. The next
source publication overwrites destination edits; a failure preserves the last accepted records and
is consumed once rather than retried forever. A Live source path cannot depend on its destination,
including through other Live datasets. Manual snapshot feedback remains allowed. Queued updates
from conflicting source actions on one owner in the same instant are rejected together.

To capture live scalar values into a stored dataset, declare an `appendRow` action:

```js
inputs:{data:{type:'table'}, capture:{type:'boolean',default:false},
  field0:{type:'string',default:''}, field1:{type:'number',default:0}},
dataActions:{capture:{type:'appendRow',input:'data',trigger:'capture',
  fields:{label:'field0',value:'field1'}}},
```

`dataActions` may also be a function of saved state, as in Capture row. `fields` maps 1–24 dataset
column keys to declared number, string, or Boolean inputs. Keys and types must match the destination
schema; unmapped columns receive null. The target must be a whole stored dataset with a live, unique
Dataset owner, without a `rows` selection; derived tables cannot accept captured rows. A false → true edge samples the scalar values
once. The host queues the request until propagation settles, validates ownership and the current
schema, and commits an atomic append. Several accepted pulses retain their individual sampled rows.
Holding Capture high, pure computation, redraw, restoration, Undo, rewiring, and historical replay
do not append again. An incomplete paused Step cannot dispatch the request.

Capture works in the editor; HTML additionally requires `state.allowReaderCapture === true`, which
defaults off in the built-in. Invalid values, stale ownership, and table limits leave accepted data
unchanged. Requests remain outside component state, and neither `compute` nor `transition` can write
the dataset directly. This uses the same host dataset service as bound-cell editing and replacement.

### `hitEdit(state, lx, ly, w, h, style)` (optional, needed if you have handles)

Given a press position, return the `id` of the handle it landed on (within your own chosen hit
radius), or `null`/`undefined` if it missed everything. Other falsy values (`false`, `0`, `''`)
are invalid. **Coordinates are already local** — `(0,0)` is the container's own top-left, same
frame as `children()`, **not** the same convention `toLocal`
uses elsewhere in the app (which only undoes rotation, not translation) — the app subtracts
`it.x`/`it.y` for you before calling this.

```js
hitEdit(state, lx, ly, w, h){
  return Math.hypot(lx - handX, ly - handY) < 14 ? 'hand' : null;
}
```

### `dragEdit(state, handle, lx, ly, w, h, style)` (optional, needed for state-editing handles)

Given the `id` `hitEdit` returned and the current (local) pointer position, return the new
state. Called continuously while dragging a `'drag'`-kind handle, or exactly once (from the
original press position) for a `'click'`-kind handle or a zero-movement click. A `'number'` handle
uses the accepted numeric entry as `lx`; a `'text'` handle uses the accepted string, as described above.

The [worked example](#a-complete-worked-example) uses the same layout helper in `dragEdit()`
and the drawing hooks to keep its radius within the current box.

Every completed click or drag creates one undo step only if its final validated state differs
from the state at the start of the gesture (compared via `JSON.stringify`). A drag that returns
to its starting value does not create a no-op undo entry.

### Host-owned tab navigation

API v2 can declare an internal tab action alongside existing data-action metadata:

```js
inputs:{page:{type:'number',default:0},parameters:{type:'string',default:'{}'},
  go:{role:'control',type:'boolean',default:false}},
dataActions:{go:{type:'goToTab',input:'page',parameters:'parameters',trigger:'go'}},
// A separately declared action handle enables a direct on-component button:
// {id:'go',kind:'action',x:w/2,y:h/2,
//  action:{type:'goToTab',input:'page',parameters:'parameters'}}
```

A false → true trigger samples the numeric target and parameters and dispatches only after the
graph settles. The target must be a nonnegative integer within the current tab list. The editor
uses current workspace order; the reader uses exported order (a single-tab export has only index 0).
The button acts on an explicit release through the same host checks. Opening or revisiting a tab
with Go already high establishes its baseline, preventing immediate bounce.

`parameters` names a string input containing at most 2,000 UTF-16 units of JSON object text.
String, finite-number, and Boolean values replace matching URL query keys; null deletes a key.
Nested objects/arrays are rejected. The host reserves `page` and sets it from the numeric target;
parameters cannot override it. Other query keys and the existing fragment are preserved. The
resulting query must fit 16,000 UTF-16 units and 128 pairs. Ordinary string outputs, including
selected URL parameter values, retain their 2,000-unit limit.

The host validates target, parameter shape, and bounds before applying the action, then uses
`history.replaceState` to update the current URL without reloading or adding a history entry.
A denied URL update reports an error and leaves the current tab and query unchanged. Successful
navigation updates the runtime query environment and re-evaluates query-aware components throughout
the current execution scope. In Active sketch only mode, inactive sketches read it when revisited;
in Whole workspace mode, every sketch can observe it immediately. A same-tab action can therefore
change parameters and recompute; it is a no-op only when its query is also unchanged.

Neither hook computation nor a script can directly access navigation, history, or the DOM.
`goToTab` stays within the current document and cannot open arbitrary URLs. Query access through
`queryParameters:true` remains read-only; this separate host action owns all permitted updates.
The opening-tab `?page=N` query selects the initial reader tab. Ordinary tab-bar clicks do not
rewrite the URL, and browser Back/Forward or third-party history changes are not a component
navigation contract.

### `contextMenu(state, lx, ly, w, h, style)` (optional)

In editor edit mode, a right-click (Control+click on a Mac) on the shape asks this hook for a
context menu at the clicked point (**local** coordinates, also outside the box, e.g. on editor-only
labels). Return `[{id, label, disabled?}, ...]` (at most 24 entries; `{separator:true}` draws a
divider; ids up to 64 and labels up to 80 characters), or an empty array for no menu. An entry
with `items:[...]` instead of an `id` is a submenu (two levels deep, 128 entries in all). An entry
may add `edit:{handle, select?}`: after its `dragEdit` the host opens that `kind:'text'` handle in
place, with `select:[start, end]` preselected (e.g. a placeholder of a freshly inserted function), or
the number dialog of a `kind:'number'` handle (e.g. a column width). Choosing an
entry calls `dragEdit(state, id, lx, ly, w, h, style)` once with the clicked point, applied as one
undo step, including a v2 `size` result. Menu ids need not be handles. Offline HTML shows no
context menu. [Spreadsheet](examples/spreadsheet.js) uses it to insert and delete columns and rows.

## Connected components (API v2)

A component is a smart shape whose script declares `apiVersion:2`. It exchanges scalar values and compact table references
through host-resolved ports. Scripts receive data and return results; they cannot inspect siblings
or mutate another component. Start from the **Number control** or **Gauge** templates, or open
[the connected example](examples/connected-components.json) as a sketch.

```js
({
  apiVersion: 2,
  inputs: { value: { type: 'number', default: 0 } },
  outputs: { percentage: { type: 'number' } },
  initState(){ return {}; },
  compute(inputs, state){
    return { percentage: Math.max(0, Math.min(100, inputs.value)) };
  },
  children(state, style, w, h, editing, io){
    return [{type:'text', x:0, y:0, w, h,
      text:io.outputs.percentage+'%', textColor:style.textColor,
      font:style.font, strokeOn:false, fill:false}];
  },
})
```

`inputs` and `outputs` are maps of port names to `{type}` descriptors, or synchronous pure
`inputs(state)` / `outputs(state)` functions returning such maps from the current saved state.
This supports author-configured port counts without making port layout depend on live inputs.
Validated capabilities are cached by API marker, exact script source, and saved state; equivalent
instances may share declarations while receiving independent copies. Declaration functions must be
pure: do not use time, randomness, or Worker-local mutations to choose ports or other capabilities.
Changing source or state obtains the corresponding declarations; cache eviction never changes semantics.
Types are `number`, `string`, `boolean`, and `table`; scalar input descriptors may also include
a matching `default`. Table ports carry validated dataset references, described below. A string input
may declare `options`, an array of 1–32 distinct, nonempty strings of at most 2,000 characters each.
Its default, if present, must be one of those options. **Edit…** presents these values as a
dropdown; literal and connected values must match an option. Options apply only to string inputs.
Names start
with an ASCII letter and contain up to 64 letters, digits, or underscores. Reserved object keys
are rejected. A component supports at most 32 inputs and 32 outputs, regardless of their
placement sides. Numbers must be finite; strings are limited
to 2,000 characters. Each port map and ordinary computed output object is limited to 32,000
serialized characters; the bounded derived-table output exception is described below. A sketch
supports at most 128 connected components.
Saved bindings and literal-input maps are each limited to 16,000 serialized characters;
the input dialog rejects changes that would exceed the save/load contract.

Input and output descriptors may declare an optional `label` (1–100 characters) for presentation
in Edit, wiring labels/tooltips, connection choices, and library port details. The object key
remains the port ID used by scripts, saved bindings, and literal values. For example,
`field0:{type:'string',label:'Customer name'}` can be relabelled without changing its connections.
Labels are literal text; an omitted label displays the port ID.

Input and output descriptors may also declare `role:'data'` (the default) or `role:'control'`
for Wiring layout. Data inputs appear on the left and outputs on the right; control inputs
appear on top and outputs below. An optional `side:'left'|'right'|'top'|'bottom'` overrides that
placement for an individual port. For example, these declarations keep the value path horizontal,
put reset above and its completion pulse below, and place a matrix column above without changing
its data role:

```js
inputs: {
  value: {type:'number', default:0},
  reset: {type:'boolean', default:false, role:'control'},
  col0: {type:'boolean', default:false, side:'top'}
},
outputs: {
  value: {type:'number'},
  resetDone: {type:'boolean', role:'control'}
}
```

`role` and `side` affect presentation only. Roles are explicit, not inferred from a Boolean
type or a port's name: Boolean logic-gate operands and results are data. A data output can
drive a control input when their types match, and role/side changes do not alter saved binding
identity or signal evaluation. The host distributes ports along the chosen side of the component
box and transforms them with the instance. There is no custom-coordinate attachment API yet.

An optional `settings` map declares authoring configuration stored in ordinary instance state.
Each descriptor uses a scalar `type` and a required matching `default`; string settings may use
`options`. Numeric settings may add finite `min`, `max`, and positive `step`, with the step grid
anchored at `min` (or zero when omitted). A `label` of at most 100 characters supplies the visible
field name. At most 16 settings are allowed. The host edits and validates these fields in
**Edit…**. Settings are not ports and cannot be bound to live sources.

```js
settings: { channels: { type:'number', default:4, min:2, max:16, step:1, label:'Channels' } },
inputs(state) {
  const ports = {};
  for (let i=0; i<state.channels; i++) ports['in'+i] = {type:'number', default:0};
  return ports;
},
```

A string setting may instead use `format:'choices'` (without `options`) to request an editable
Text/Key row list. Its default and state value are JSON strings encoding arrays of `{text,key?}`;
the host validates at most 64 rows and 2,000 serialized characters, required string text, optional
string keys, and uniqueness of nonempty keys. Add/remove/reorder operations stay in the Edit
dialog's draft until Save. Cancel preserves the original list.

A string setting may use `format:'lines'` to request a multiline field, bounded to 2,000 characters.
The component validates the line syntax. Capture row uses this for its `column:type` mappings.

An optional API v2 `configure(nextState, previousState)` authoring hook handles changes to settings
in **Edit…**, before the host resolves the proposed state's ports. Settings edited as drafts,
such as choice lists, pass through this hook when **Save** is pressed; the author then reviews
the new configuration and presses Save again to apply it. The hook returns `null` to keep
`nextState` unchanged, or `{state, confirm?}` to propose a replacement state. `confirm`, when present,
is a confirmation message of at most 500 characters. The host validates the returned state against
the ordinary JSON and 4,000-character state limits, then asks for confirmation before staging it.
Declining restores the previous draft configuration. **Save** applies the accepted draft as one
undoable change; **Cancel** preserves the original instance. This hook is not called by runtime
transitions or HTML reader interactions and cannot mutate the live drawing while Edit is open.

Initialize setting fields in `initState()` and keep port-defining settings unchanged in
`transition` and interactive reader hooks. Dynamic declarations must be deterministic from state;
they do not authorize mutation during capability inspection. Changing Channels rebuilds the
available ports in the authoring dialog. Bindings to a removed output become unavailable until
reconnected. Runtime-only position changes must not change the declared channel set.

`compute(inputs, state, context)` synchronously returns an object containing exactly the declared outputs
with matching types. A component declaring outputs must provide `compute`, `publish`, or both.
Use `compute` for values derived from current inputs; use `publish(state)` for stored outputs that
must be available before resolving feedback. Treat both as pure computations:
no state changes, actions, or dependence on definition-local mutations. The host evaluates the
graph asynchronously in bounded settling rounds when component state, scripts, or wiring change, and
discards superseded results. Size, style, and presentation refreshes do not recompute values.
`refreshMs` remains a drawing refresh; connected clock outputs require an explicit transition.
The built-in Live clock samples wall time in `transition` and publishes that snapshot through
pure `compute`, keeping its hands, readout, and connected outputs synchronized.

A component may declare top-level `queryParameters:true` to receive the host page's current
runtime query string in `context.query` during `compute` and `transition`, including a leading
`?` when present. The runtime initializes this value from its own `location.search` on opening
and updates it through accepted `goToTab` actions. Query updates re-evaluate declared consumers in
the current execution scope, including on same-tab navigation; Active sketch only mode refreshes
inactive sketches when revisited. The value contains neither
the path nor fragment and exposes no host DOM or network access. Components without the capability
do not receive this field. Editor and reader use their own environment independently. Library
previews and HTML's initial frozen SVG use an empty query, so editor URL values are not baked
into the exported drawing.

The host retains at most 16,001 UTF-16 units of an opening query as a bounded oversize sentinel;
the built-in URL parameter rejects more than 16,000 units or 128 decoded pairs. Custom query
consumers must also validate bounds before producing ordinary typed outputs. Query values are
transient inputs, not saved component state. Reload initializes from the current URL again.
This read capability does not authorize a component to navigate or rewrite a URL; only the
separately declared, validated host navigation action can perform those updates.

An API v2 component may declare `pageSettings` to control the current HTML reader tab's
presentation through typed input values:

```js
pageSettings:{title:'title', showTabs:'showTabs', showWiring:'showWiring',
  showSimulationControls:'showSimulationControls'}
```

The four property names are fixed; their values identify four distinct declared inputs. Title
must map to a String input, and visibility properties to Boolean inputs. These inputs cannot
be optional or accept unknown values. The controller must have `compute` and no outputs,
`publish`, `transition`, dataset ownership, or data actions. A drawing may have at most one
controller; duplicates are graph errors. A persisted `pageSettings:true` item marker helps the
editor prevent duplicate placement, but only a validated script capability grants host effects.

The reader resolves the destination graph, applies workspace defaults followed by sketch overrides,
and then reveals the drawing. Live input changes update the current tab. Missing or unavailable
sketch settings inherit workspace defaults; without valid workspace settings, these are the export's
original title, visible tab bar and simulation controls, and hidden wiring. An empty or whitespace-only
workspace title uses the original title; an explicitly overridden sketch title may be empty. Titles are bounded
by the standard 2,000-UTF-16-unit string limit. Settings never affect the editor's authoring
controls. Mark the controller's drawing children `editorOnly:true` to omit its block from
exports. The built-in does so while retaining labelled connection endpoints in reader wiring.
The host changes only these presentation properties; this capability grants no DOM access.

The optional API v2 `transition(inputs, state, memory, {now, historical, runtimeId, eventInputs})` hook adds explicit stateful,
timed signals. It synchronously returns `{state, memory, nextWakeAt}`. `state` is the next durable
instance state; `memory` is a transient JSON object, isolated per instance and never saved or
exported. Both use the existing 4,000-character state limit and JSON validation. `nextWakeAt`
is an absolute nonnegative timestamp in active-document milliseconds, or `null`/omitted to stop
waking. The host provides monotonic `now`, owns the timer, and clamps wake delays to at least 10 ms.

A top-level `wakePolicy` is either `'queued'` (the default) or `'latest'`. Queued deadlines, such
as Delay transitions, replay in timestamp order after a late browser wake. Each timestamp settles
before the next one, using the last committed drawing snapshot. For example, a clock due at
100 ms samples the data from 100 ms even if data also changes at 200 ms and the browser wakes
at 250 ms. Current external state, input, script, and binding changes are applied after those
already scheduled earlier events; unrelated state-field edits preserve intervening stored changes.

`historical` is true while processing an earlier queued timestamp and false at the current
observed time. Components with `wakePolicy:'latest'` do not wake merely because an old periodic
deadline is due during historical replay, but may still receive a changed input. Their transition
must suppress autonomous expiration when `historical` is true while still handling commands.
The built-in Pulse generator, Trigger, Edge to pulse, Random integer, Sample & hold, and
wall-clock components use this policy to preserve their existing no-catch-up behavior. The replay is capped at 128 historical
timestamps per run; excessive pending work becomes a visible scheduled-backlog error in the
affected branch, recoverable after an input/configuration change. This is separate from the
256-round zero-time settling limit.

A transition may run when an input changes before its deadline: inspect `memory` and `now`
to decide whether to sample. Do not depend on hook-call counts, Worker-local state, or script timers.
Every transition in one round reads the same resolved input snapshot. The host stages results and
publishes them together for the next round, so shared-edge storage cannot sample a producer's
new value prematurely. Reset/clock priority belongs in the component contract; built-in storage
makes reset win over a clock edge. The dedicated SR latch has no clock and treats simultaneous
set/reset as unknown X rather than giving either command priority.

Stateful components can add the pure `publish(state)` hook. It returns the declared outputs from
stored state without needing current inputs, allowing the host to expose those outputs before
resolving feedback. Return exactly the declared output names and types, as for `compute`.
`publish` must not mutate state, sample time, consume edges, or depend on Worker-local memory.
Use `transition` to react to resolved inputs and update durable state. A feedback-compatible
counter therefore publishes its stored count first, then reacts to clock/reset in a later round.

Settling rounds do not advance simulation time. Brief output changes still reach observers even
if the canvas never paints their intermediate value: `reached → reset` can emit true, reset the
counter, then emit false during one event. Positive Delay schedules a later event; zero Delay
stays in the current bounded calculation. The runtime stops a non-settling loop with a visible
error after at most 256 rounds while independent branches remain usable. A run also has a
16,384-hook-call budget. Drawing order and Worker completion order do not choose the result.
The fault remains on the affected group instead of retrying on unrelated edits or clock ticks.
A relevant external input, state, script, or binding change, or a fresh timeline, permits another
settling attempt. An external reset can therefore recover a faulted circuit.
The host persists accepted combinational-cycle outputs
as `signalState` on the item so a gate-built latch retains its bit through save/reload/copy/undo;
scripts do not directly manipulate that field.

The editor and exported HTML provide **Pause / Step / Resume** for the current execution scope. Pause
retains the current snapshot and stops active simulation time. Step advances one propagation
round; when settled it advances to the next scheduled event. The status includes time, round,
and recent signal changes. Pause is session-only: independent per sketch in Active sketch only mode,
or shared by all sketches in Whole workspace mode. Step advances
logical active-document time; wall-clock Live clock, Stopwatch, and Timer still read actual wall
time and are not fast-forwarded. Pure inspection and static exports never advance a paused timeline.
Undo/Redo preserve the tab's Pause setting and simulation time while re-priming transient observation
from the restored drawing.

Only a current evaluation commits state/memory, and an error in one branch does not stop independent
branches. Accepted smart-control changes and timed wakes settle in order. Unfinished drag previews
never consume edges; their committed final value does. Missing inputs, Z, and failed transition or
compute calls clear that instance's transient observation. Replacement objects, changed scripts,
and changed bindings re-prime it; changing a literal input is an ordinary input transition.

In Active sketch only mode, each sketch retains its clock and transient memory across tab switches;
inactive sketches pause and resume on return. Whole workspace mode uses one timeline and continues
processing every sketch, including sketches hidden from the reader tab bar. Hiding the browser page
or opening the editor's Edit dialog pauses interval simulation in either mode.
Saved JSON includes current durable counts/outputs, but reopening, duplicating, or undoing starts
new transient observation. The built-in Counter preserves its saved count in either direction
and seeds an already-high input without counting it. Its held reset follows the input while
holding the mode's baseline, so releasing reset during high does not add or subtract an edge.
Shift registers likewise preserve their durable cells and last `shiftedOut` value while
re-priming pulse observation. Their `shiftedOut` port captures the old final cell on an accepted
rising edge. For shared-pulse cascades, connect current `value` (or `q(N−1)`) to the next register's
data input: all registers sample before any new cells are published. `shiftedOut` remains a
held observation of the last removed cell, not a correction for execution order.
The built-in Delay retains up to 64 queued transitions and emits at most one per propagation round, preserving
short pulses for downstream counters even after a late wake. Changing its seconds resets its queue.
Random integer and Sample & hold sample once on a late wake and schedule their next interval from
that wake. Duration inputs use seconds; the host contract uses milliseconds.

Live clock follows wall time rather than accumulating active-document intervals. It updates while
active and realigns with wall time on return. Fresh transient observation, timezone changes,
missed boundaries, and clock jumps never replay missed pulses. Its `compute` and drawing hooks
read the last settled snapshot without advancing it.

Stopwatch uses transitions only for run/reset commands, with no scheduled transition wake.
Its pure `compute` returns `elapsed: state.elapsedMs / 1000`, the accumulated total last stored
on pause or reset. Starting/resuming leaves that output unchanged. The live display separately
derives the running duration from saved wall timestamps and requests 100 ms presentation
refreshes; these redraws neither update the output nor create periodic autosaves.

Timer uses wall timestamps for a countdown and scheduled transitions to update its settled dial
roughly once per second and clear short pulses. It does not use `refreshMs`. Pure `compute` and
rendering read the settled snapshot without advancing time. Inactivity/reload preserves the
running deadline; missed unit boundaries do not produce catch-up ticks, and expiry is reflected
by `reached` when active evaluation resumes.

Static exports, library thumbnails, and input inspection use only pure `publish`/`compute`, never
`transition`. Offline HTML starts a new timeline from the exported durable state and uses the same
settling and transition contract. Timed changes save state without creating an undo entry on every
tick. Feedback support does not add external actions, a routed-event API, or shared-bus resolution.

A Boolean input or output can declare `unknown:true` to admit the string `'X'` as an explicit
unknown logic value received through a binding or produced by a hook. Defaults and literal
inputs remain true/false. Only opted-in Boolean ports accept X; ordinary Boolean ports do not coerce
it to true. Unknown-aware gates use three-valued logic: `false AND X` resolves false, `true OR X`
resolves true, while `NOT X` remains X. An uninitialized gate-built latch retains X until a definite
set/reset establishes its state. A dedicated SR latch sets Q/notQ to X when set and reset are both
asserted and retains X after release until a definite command. A NOR pair instead drives both
outputs false during that forbidden input; a NAND pair drives both true. Releasing both controls
at once can leave a non-settling loop, which reports an error rather than choosing a bit through
iteration order. Missing sources, script errors, and high-impedance Z remain separate from X. Unknown Boolean
storage exposes X visibly through its output/rendering contract.

A boolean **output** may declare `triState:true` to permit `null` as an explicit high-impedance
value, shown as **Z**. Ordinary boolean outputs still accept only `true` or `false`; numeric and
string ports, input literals, and defaults never accept `null`. The graph validates the declared
output before publishing Z. A component producing Z remains healthy and interactive. A boolean
consumer of Z does not run `compute()` or advance `transition()` until the source drives a value
again. Its pure `publish(state)` output remains available to downstream consumers: a disconnected
data input does not erase a register's stored bit. Components without independent publication remain
unavailable, and a published output that is itself Z still blocks its consumers. Valid bindings to Z
can be saved in **Edit…**, while other
input, type, or non-settling-loop errors still prevent saving. Combinational unavailability propagates
through dependent components in both the editor and exported HTML. Inputs retain one source each; this does not add
shared buses, pull-up/down resolution, or electrical simulation.

The host appends `{inputs, outputs, name, runtimeId, boundInputs}` as the final `io` argument to these v2 hooks.
`name` is the instance name from **Edit…**, or an empty string for unnamed imports. It is
presentation metadata: renaming redraws the instance without changing computed port values.
`boundInputs` is an array of input names connected to another component, used to mark input controls
read-only; input values still come from `io.inputs`.
Built-in API v2 components use it for their captions, falling back to their catalog names
when empty. Text label shows its caption only when **Show name** is enabled.
Captions fit within the shape, with wrapping or truncation for long names, and remain
separate from numeric readouts, state labels, and operation symbols. Spreadsheet uses its full box for the cell grid
and does not draw a caption; its instance name still identifies it in Edit and wiring.

Built-in ordinary numeric labels, including general Spreadsheet cells and numeric dataset/chart
readouts, use up to eight significant digits while preserving exact safe integers. Formatting
belongs only in presentation hooks: `compute`, `publish`, input values, stored state, editable
handle values, and CSV/JSON downloads retain their original numeric precision. The portable
built-ins share the `_number` convention; custom scripts choose their own presentation.
Explicit Spreadsheet formats and dedicated clock or measurement formats retain their chosen
precision. String values are never reformatted as numbers.

```text
children(state, style, w, h, editing, io)
handles(state, w, h, style, io)
hitEdit(state, lx, ly, w, h, style, io)
dragEdit(state, handle, lx, ly, w, h, style, io)
exportBehavior(state, io)
```

`runtimeId` is an opaque, host-generated identifier for the current instance object. It is stable
while that object remains in the current runtime and is also provided to `transition` in its context.
Loading, copying, and history restoration create new objects with new identifiers. It is metadata,
not a port or saved component identity. The typed input built-ins stamp accepted interactions with
this identifier so their first transition can distinguish submissions made while paused from old
queued actions restored from a document. Scripts must not treat it as a secret or an authorization token.

V2 `dragEdit` must return **`{state: newState}`**, optionally with **`size: {w, h}`** (either
field may be omitted; each 20–2000) to resize the container in the same step, for example a
spreadsheet growing by one column. The editor applies the size with the top-left corner fixed, as one
undo step together with the state; offline HTML ignores it. Scripts opting into `eventApi:1` may
also return declared `events` from accepted interactions, as described below. Other effect fields
are unsupported. `initState()` still returns the raw state object.
Unversioned scripts keep returning raw state from `dragEdit`, even when their state happens
to have keys named `state`, `emit`, or `effects`. The runtime never guesses the contract from keys.

Select an instance and click **Edit…** to name it, enter literal inputs, or bind inputs to
compatible outputs in the same sketch. Sources with the same name receive drawing-order and
world-position qualifiers such as `#1 (left)` and `#2 (right)` in the picker. These are display
hints only: instance names and the saved `{uid, port}` binding remain unchanged.

The Edit dialog groups the instance name and configuration separately from data inputs, control
inputs, and the proposed output preview. Its fixed header identifies the component separately
from the editable instance name: an exact built-in script match uses the canonical library name;
otherwise an unambiguous matching single-component library entry supplies its name. Unrecognized
or ambiguous scripts show **Custom component**. This display does not create a library dependency.
Input roles come from the declared `role` metadata;
Boolean values are not automatically controls. The scrollable body keeps **Save** and **Cancel**
available, with fields stacked on narrow screens. This presentation does not change port names,
binding identity, or the paused draft-preview contract.

Configuration and literal inputs share typed property controls, including declared choices,
Boolean values, numeric bounds/steps, and multiline fields. Validation messages are attached to
their fields; Save focuses the first invalid field. Source rows report their selected producer,
paused value or diagnostic, and hybrid value/event mode. Source dropdowns include a filter in
their opened menu. Typing or cancelling preserves the committed source, including a broken
selection that needs repair; choosing a result changes the draft.
Compact **Go to source** and **Disconnect** icons have tooltips; Receiver endpoints use the same
controls. **Disconnect** stages a binding removal. **Go to source** and **Used by** navigation select the
referenced component and ask before discarding a modified inspector draft. Dataset references
identify the table and offer navigation to its owning component when one exists. These helpers
do not change port identity, the single-source rule, or source/value precedence.
Spreadsheet continues to author formulas, ranges, and layout in cells and the cell context menu;
its inspector only binds declared ports and previews their results.

The editor's **Wiring** toggle exposes those same bindings as ports and links only while enabled. It starts off;
drag an output to an input or an input to an output. The host requires exact `boolean`, `number`,
`string`, or `table` type compatibility, permits one output to supply several inputs, and replaces
an input's previous binding in one undo step. Scalar self-feedback uses the existing settling
rules. Dataset ownership settings are not wireable ports. Select a link and use **Disconnect**
or **Delete** to remove it; **Escape** cancels an unfinished drag. Edit remains the place to
configure literals, settings, and dataset ownership.
Double-click or double-tap a component body to enter interactive mode while its wiring stays
visible. Separate clicks still cycle overlapping shapes; ports and links retain their wiring gestures.
Drag a connected input's pin to move that wire to another compatible input. The original wire
is lifted while dragging; a valid drop moves it in one Undo step, replacing an occupied destination
if necessary. Escape, an incompatible drop, or dropping on empty canvas keeps the original connection.
To change the source instead, drag the new output onto the occupied input. Stored Dataset associations
keep their dataset reference when moved.

Directed flow links display Boolean, Number, Text, or Table markers. A Dataset owner's output
publishing its own records directly to a consumer, or a literal table reference to that owner's
records, is shown as a dashed Dataset association. Bindings through Filter, Sort, or Aggregate
remain table flows, as does an owner's incoming `source` connection. Table flows carry current
snapshots, not arriving-row events. The Dataset marker expresses a shared-record association;
it does not infer read/write permissions from the port or component name. Explicit access
metadata is deferred. These link styles do not change runtime evaluation or mutation rules.

Wiring is an overlay derived from component identities, current ports, bindings, and table
ownership. It is not saved as drawing geometry and does not appear in PNG, SVG, or print. The
HTML reader hides it by default; **Sketch settings · Show wiring** exposes a read-only view with
the same port and link conventions. Semantic bindings and table references serialize and execute
independently of visibility. Optional descriptor roles and side overrides control placement; no
script hook or manual port coordinates are needed for this first editor.

Source and literal edits refresh **Output preview** and any graph or validation error after a
short debounce. Pending or unavailable results replace stale output values. The latest edit wins,
without rebuilding the fields or moving keyboard focus. Configuration changes may rebuild dynamic
fields while retaining matching input drafts. This bounded preview
uses pure computation on a temporary proposal; it does not call `transition`, consume edges,
advance timed state, or change the drawing. **Save** validates and commits the proposal;
**Cancel** discards it. It is not a running simulation of proposed temporal configuration.

Deployments can disable component authoring with
`features.smartComponents:false` in `settings.json`; existing components still execute and export.
The flag hides component templates, source editing, Edit, and Wiring, and blocks adding component
library entries. Ordinary smart-shape authoring has its own `smartShapeAuthoring` switch, which
must also be enabled to author components. A binding takes precedence over a saved literal; an
unbound input uses its literal, then its declared default. Missing required inputs, missing
sources/ports, type mismatches, non-settling loops, and failed computations report errors. Failed outputs
are unavailable to consumers; healthy independent components continue working.

### Unavailable drawings

An optional v2 hook keeps a recognizable shape on screen before its inputs are connected:

```text
unavailableChildren(state, style, w, h, editing, io)
```

Here `io` is **`{inputs:{}, outputs:{}, error: message, name}`**. The maps are empty, even if some
inputs are valid; no old or fabricated values are supplied. Use the saved `state` only for
configuration such as a threshold or indicator visibility, and draw a neutral placeholder
for unavailable data. The hook returns child descriptors with the same validation, limits,
and sandbox as `children()`. It does not produce outputs, update state, or request refreshes.

The editor passes its current `editing` flag; static exports and interactive HTML pass `false`
to this hook. For unavailable inputs, the host skips `compute()` and invokes this hook instead
of `children()`. Handles cannot be used. The app draws a status card when no unavailable hook is
available or its drawing fails. A drawing-hook failure also disables component interactions
until a valid drawing recovers. Unsupported scripts still cannot execute either hook.

The built-in logic entries implement this hook with their normal silhouette, **—** values,
amber indicators when enabled, and a short input-status note. The boolean gates are AND, NAND, OR, NOR,
XOR, XNOR, NOT, and Buffer. Compare uses numeric `value` and `b` inputs, a string `operation`
selected from `>`, `≥`, `<`, `≤`, `=`, and `≠`, and a boolean output. B defaults to 70; the operation
defaults to `>`. Both operands can be connected, and equality is exact numeric equality;
[Inverter (×−1)](examples/number-inverter.js) uses numeric input and output. Its computation
is `-inputs.value`, whereas NOT computes `!inputs.value` on a boolean.

[Math](examples/math.js) declares numeric `a` and `b` inputs, a string `operation` input with
`options:['+','−','×','÷','min','max']` and default `'+'`, and numeric `value` output. Choose the operation in
**Edit…**; subtraction and division use `a` as the left operand. Division by zero and nonfinite
results fail computation, leaving outputs unavailable until corrected. Computation errors expose
their message as bounded plain text; other failing hooks retain the generic failure message.

These entries store the indicator preference in `state.showIndicators`, defaulting to `true`.
Missing flags in older state also mean on. With valid inputs, their editor-only **Indicators:
on/off** control changes that instance; the saved setting affects editor and exported drawings.
Green/grey indicators mean true/false, blue means an available number (including zero), and
amber means unavailable. The setting does not change computation or port types.

### Hybrid value/event ports (event API 1)

A hybrid port has a current typed value and may carry discrete occurrences containing that same
value type. Repeated equal submissions are separate events. API v2 scripts opt in with
`eventApi:1`, then add `event:true` to their ordinary input/output descriptors. The same port and
connection serve both paths; consumers without event capability read only the current value.

```js
// A submit-mode inline entry publishes a value and captures each accepted submission.
({
  apiVersion:2,
  eventApi:1,
  inputs:{},
  outputs:{value:{type:'string',event:true}},
  initState(){return {text:''};},
  compute(inputs,state){return {value:state.text};},
  children(){return [];},
  dragEdit(state,handle,value){
    return {state:{...state,text:value},events:[{port:'value',payload:value}]};
  }
})

// An event receiver uses staged state; all changes in the interaction commit together.
({
  apiVersion:2,
  eventApi:1,
  inputs:{content:{type:'string',default:'',event:true}},
  outputs:{text:{type:'string'}},
  initState(){return {text:''};},
  compute(inputs,state){return {text:state.text};},
  children(){return [];},
  onEvent(name,payload,state,io){return {state:{...state,text:payload}};}
})
```

There is one compatible type per hybrid port: `string` (up to 2,000 UTF-16 units), finite `number`,
or `boolean`. There are no implicit conversions; use Number to text before a numeric event feeds
Memo. Objects, arrays, tables, and Dataset associations do not carry events in this increment.
Ports retain their ordinary data/control sides. Wiring marks enabled reception with purple lightning
on the existing port/link. Values-only connections show muted crossed lightning. Accepted events
flash amber for 650 ms; rejected transactions do not flash. Selecting a wire or inspecting a port
shows its session occurrence count and last payload (quoted and truncated to 240 characters).
HTML wiring provides read-only click/focus inspection in a dismissible status panel. These activity
records reset with the tab/runtime and are never persisted or exported as prior activity.
**Edit… → Receive events** controls each capable input:
values and events by default, or values only for a conventional sampled-value connection.

The saved receiving item uses ordinary `bindings`. Optional `eventModes` selects values only:

```json
{
  "uid":"notes",
  "componentApi":2,
  "bindings":{
    "line":{"uid":"message","port":"value"},
    "append":{"uid":"message","port":"submitted"}
  },
  "eventModes":{"line":"value"}
}
```

Each input has one source and outputs may fan out. Connection identity, copying, unresolved
external references, sketch/workspace persistence, and HTML export follow ordinary bindings.
Setting `eventModes.line` to `"value"` prevents incoming events from appending; the separate Append
trigger still samples the current Line value. Omitting the mode (or `"both"`) enables events.

#### Pure transformations and Reprocess

Pure scalar transformations declare one or more driving inputs, event-capable result outputs, and a Boolean
Reprocess input with `event:'command'`. The host reuses `compute`, so value and event calculation
cannot diverge:

```js
apiVersion:2,
eventApi:1,
inputs:{
  text:{type:'string',default:'',event:true},
  start:{type:'number',default:0,role:'control'},
  length:{type:'number',default:1,role:'control'},
  reprocess:{type:'boolean',default:false,role:'control',event:'command'}
},
outputs:{text:{type:'string',event:true}},
eventTransform:{input:'text',outputs:['text'],reprocess:'reprocess'},
compute(inputs){return {text:Array.from(inputs.text).slice(inputs.start,inputs.start+inputs.length).join('')};}
```

Use exactly one of `input:'text'` or `inputs:['a','b']` in `eventTransform`. The latter declares
1–15 distinct existing hybrid inputs; command inputs cannot drive data events. A component with
dynamic ports may declare `eventTransform(state)` instead of a fixed descriptor. It is evaluated
alongside `inputs(state)`, so Text compose returns only its enabled `a` through `h` names.

A driving event substitutes its captured payload into a consistent snapshot of the remaining
inputs. When several declared driving inputs receive related results from the same source
occurrence, the host collects those results and calls `compute` once with all their payloads.
It forwards one occurrence on each declared result output. Inputs without a related arrival
provide their current values; the host does not wait for every connected input to emit. Pure
value dependencies changed by that submission are settled before they are sampled, even when
Receive events is off on the connection. Unrelated values use the snapshot taken for the
occurrence. Ordinary
parameter changes recalculate the current output without emitting an occurrence. Reprocess
samples all current inputs and emits fresh results even when they match the previous result.
A command-capable source such as Trigger uses its event; its accompanying Boolean pulse is not a
second request on that same command connection. Command events accept Boolean `true` or a
payload-free `null`; Boolean `false` is ignored. Turn Receive events off to use the rising-edge
pulse instead. A plain Boolean source also supports false → true Reprocess pulses. Initial high
values establish a baseline; opening a drawing does not itself request reprocessing.

The built-ins following this convention are Text compare/extract/replace/transform/to number,
Number to text, Number function/inverter, Compare, Arithmetic, Clamp, Range map, Text compose,
JSON extract/edit, and Date parse/format/difference. Every enabled Text compose text input
(**A** through **H**, according to its input count) is hybrid: an event on any one combines that
captured string with the current values of the other inputs and emits the composed text.
Related arrivals from separate branches of one submission combine before Compose emits once. A plain
value source such as Live clock can update any of these inputs without creating an event.
Template and separator remain parameters; Reprocess explicitly emits with all current values.
Independent submissions produce separate results, including repeated equal payloads. To combine
independently edited fields on demand, turn Receive events off on their Compose inputs and
connect an Apply button to Reprocess.
Arithmetic uses **A**; Date difference
uses **End**, with Start and Unit as parameters. Dropdown and scalar selectors use the explicit
selection policy below. JSON build emits only on its explicit Emit/Reprocess command and keeps
its fields value-only. Dataset-dependent text lookup and table transforms await
their own event contracts.

#### Application action commands

Boolean control inputs can declare `event:'action'` when a validated `dataActions` declaration
uses that input as its trigger. Ordinary rising Boolean signals continue to work. In event mode,
each scalar/null occurrence requests the action once: Boolean `false` is ignored, while numeric
zero, empty text and null are accepted requests. The occurrence payload does not replace the
action's typed parameters; the host captures those from settled inputs.

The shared dispatcher keeps captured requests owned by their workspace/sketch/component,
independently of the visible sketch. It validates live ownership and permissions before executing,
deduplicates the same accepted request, and bounds pending actions and cascades. Deleting the source
or replacing the workspace cancels stale work. Accepted service actions survive navigation in
Whole workspace mode. Failure notifications are themselves contained so a failing receiver cannot
strand later actions.

Declared completion events include Dataset `loaded`, `replaced` and `appended` row counts;
Capture row `captured` zero-based row index; Go to tab `arrived` zero-based destination index;
Download table `prepared` filename; and `failed` text. Automatic downloads prepare captured content
and expose an explicit **Download** button for browser user activation. `prepared` means ready to
download, not that the browser saved a file. Cancellation and restoration do not emit completions.

#### Delivery and existing triggers

An accepted discrete `dragEdit` interaction may return `events:[{port,payload}, ...]` alongside
`state`. Continuous dragging does not emit. A receiver implements
`onEvent(name,payload,state,io)` and returns `{state,events?}`, or declares `eventTransform` for the
host's pure calculation path. The host validates payloads against the ordinary typed ports.
Pure `compute`, `publish`, rendering, and settings changes do not spontaneously emit events.
Reprocess is an explicit host-observed command, rather than an event inferred from output changes.
Effects and host-action requests are not supported in the event envelope.

A component may declare at most 32 event inputs and 16 event outputs, counting both dedicated
and hybrid ports. A pure transformation still declares at most 15 driving inputs plus Reprocess.
Each hook may emit up to 16 events and 32,000 serialized characters. One interaction permits up to
256 emitted events, 128 receiver deliveries, 256 calculation calls, and 16 propagation hops, under normal Worker and
state limits. Each source occurrence receives a transient host-owned origin that follows its
branches through transformations. Delivery follows event dependencies so pure transformations
see all related arrivals before forwarding a result. Two source occurrences remain separate
origins even if one hook emits both, their payloads match, or they arrive close together; this is
not a timer or debounce. A pure transform's declared result outputs keep their common origin.
Each explicit entry in a custom receiver's returned `events` list starts a child occurrence,
preserving deliberately emitted bursts. Origins are internal routing metadata, not payload
fields or persisted state. A cycle in the event or pure-value dependencies needed to deliver an
occurrence is rejected atomically. Stored state and ordinary value feedback retain their
separate simulation rules.
Receiver hooks see their staged state and a consistent input snapshot;
they should use the payload for the occurrence's data rather than rereading a source signal.
When one origin reaches several inputs of a custom `onEvent` receiver, those commands run in
input declaration order. The receiver's own state accumulates those changes. Its stored
`publish`/`compute` outputs remain fixed for that origin and expose the changed state to the
next occurrence, so another branch cannot observe a partial receiver update.

Delivery stages the initiating edit and receiver states before committing together. Invalid
results, incompatible payloads, or exceeded work budgets reject the interaction. An accepted
interaction is one editor Undo step; Undo/Redo restores outcomes without re-executing events.
Once the source payload and graph snapshot have been captured, an accepted occurrence finishes
atomically even if the browser page becomes hidden. New interactions and interval clocks pause;
follow-up host actions wait until the page is visible again. Whole workspace mode also permits an
accepted occurrence to finish after changing the visible sketch. Active sketch only mode cancels
when leaving the source sketch. Page departure (`pagehide`, including entry into the back/forward
cache), document replacement, editing-ownership loss, replaced participants, and changed wiring
still cancel stale work. Unaccepted source hooks remain cancellable. The dispatch queue is never
serialized. Redraws, ordinary value settling, copying, reload, and HTML restoration do not re-emit
submissions. Accepted user events run while signal simulation is paused; ordinary Boolean pulses
still wait for Step or Resume.

Text input and Number input emit through their hybrid **Value** output while retaining their
queued **Submitted** Boolean pulse. Trigger emits `true` through its hybrid Value output and
retains its timed pulse. Memo's hybrid **Content** replaces stored text on receipt; hybrid **Line**
appends one captured string. Both also retain the current text for the separate Set/Append
Boolean triggers. **Clear** accepts a command event or its existing Boolean trigger. These paths
share the same bounded Memo operations. Connecting both a Line event and a separate Append
trigger is intentionally two requests; turn Receive events off on Line to sample text only.

The **Events and signals** demo compares both Memo styles. **Hybrid transformations** demonstrates
`Hello World → llo`, then `Another Test → oth` with zero-based Start 2 / Length 3. Changing the
range to Start 3 / Length 5 updates the current result to `"ther "` without appending. Reprocess
then emits that current result; a separate trigger samples the same result for a values-only Memo.
Both Memos use Log mode with a ten-line limit. Further appends roll out the oldest lines;
the Scrollbars toggle lets readers explore retained entries.
**Shared event origins** splits one `Anna;Berlin` submission through two extractors, then joins
their outputs into one `Anna / Berlin` Memo line. Repeating the same submission adds another line.
A second example disables events on Compose's Name/City inputs and uses an Apply button connected
to Reprocess, making the boundary between independent edits and one explicit request visible.

#### Selection and signal/event adapters

Dropdown declares hybrid `select` plus command `reprocess`, and hybrid result outputs `index`,
`key`, `text`, and `valid`. Accepted UI choices use the same `compute` result as incoming Select
or Reprocess events, and the four output occurrences share one origin. Ordinary list/table
refreshes or value-only Select changes do not emit. Dataset-backed choice calculation receives
the same table snapshot used for that event; the emitted payloads remain scalar.

Text, Number, and Boolean selectors add `selection:{input:'select',choices:['a','b']}` to their
`eventTransform` descriptor. The Boolean Select input and both data inputs are hybrid. The host
first collects related arrivals and resolves their current values. A data event forwards only
when it belongs to the chosen input; Select and Reprocess events explicitly sample the chosen
value. False is a valid Select payload, not a suppressed command. Pure Select value changes do
not emit. Stepped Number/Boolean selectors similarly forward selected-channel events; a real
Step edge emits the newly selected value and Reprocess samples it. Reset, channel changes, and
restoration are silent. This does not imply waiting for unrelated inputs or event support on
stepped distributors.

[Signal → event](examples/signal-to-event.js) has setting `type:'string'|'number'|'boolean'`, typed
plain `value`, plain Boolean `trigger`, and matching hybrid output `value`. `compute` publishes
the current value; `transition` captures it on an observed false → true Trigger edge. A fresh
runtime, restored high level, or type change primes the baseline without emitting.

[Event → pulse](examples/event-to-pulse.js) has dedicated `eventInputs.receive` accepting
`none`, `boolean`, `number`, and `string`, and plain Boolean output `value`. Each `onEvent`
occurrence advances a token; `transition` consumes new tokens into a bounded queue of 64 pending
pulses. Each pulse is 100 ms high with a minimum 10 ms low gap. Equal payloads, false, empty text,
and null still represent occurrences. Pulse scheduling follows simulation Pause/Step; a fresh
runtime primes the saved token and discards transient pending pulses rather than replaying them.
Events accepted in the current runtime before its first transition, including while paused, are
retained. `io.runtimeId` in `onEvent` and `context.runtimeId` in `transition` identify that runtime;
restored objects receive a different identity. The host supplies both identities.

`context.eventInputs` lists inputs with an active event connection. Stateful components can use
it to avoid sampling a command's Boolean edge as well as handling its event. Value-only inputs
are absent from the list.

Counter and Timer add `event:true` to their existing `reached` output. Simulation transitions may
return `events` alongside `state`, `memory`, and `nextWakeAt`. The host validates the same typed
payload limits as interaction events, settles the current value graph, and then delivers captured
occurrences one batch at a time. Changed receiver state settles before the next batch. A paused
Step may retain pending completion batches until its signal instant settles; an edit at a later
instant first completes already accepted batches against their original scene snapshot. All
staged work remains subject to cancellation, and transient pending batches are never serialized.
Counter emits `true` only on a newly
counted completion edge; Timer emits `true` on a current observed natural deadline. Initial state,
reset, configuration changes, inactive-tab catch-up, and restored scheduling memory do not emit
old completions. A delayed observation in the same active runtime still emits one completion. Their existing level and tick outputs retain their earlier contracts.
If a completion receiver rejects the occurrence, all receivers of that occurrence retain their
prior state and the host reports the delivery failure. The accepted simulation transition
remains intact: a full log cannot reverse a counter increment or restart a completed timer.

The demo's **Selection events** tab joins a city and automatically chosen country under their
shared origin. **Adapters and completion** shows sampled text, repeated events becoming separate
Counter pulses, and Counter/Timer notifications. **Dataset action results** covers the host-owned
notifications described with dataset actions. These tabs enable reader wiring for inspection.

### Saved components

Sketch/workspace format 6 stores embedded datasets alongside items and assets. It retains the API
marker on each component and bindings on the receiving item:

```json
{
  "uid": "gauge",
  "componentApi": 2,
  "componentName": "Gauge",
  "bindings": { "value": { "uid": "number-control", "port": "value" } },
  "inputValues": {}
}
```

This is an excerpt; the item also retains its geometry and state. Native format 6 stores each
distinct script once in a top-level `scripts` dictionary (`s0`, `s1`, …), with each smart item
using a matching `scriptRef`. The source is hydrated before the component runs; live items,
clipboard data and library transfers still contain inline scripts. IndexedDB workspace snapshots
and HTML reader payloads share scripts the same way. Scripts are compared exactly, not by name
or component type, and each instance retains its independent state. State fields named `script`
or `scriptRef` remain ordinary state.

The saved `componentApi` must match the script's `apiVersion`. Unsupported versions keep their
source and saved values but cannot execute. Formats 1–5 with inline scripts remain readable;
older app versions should not be used to edit current connected documents. Malformed pools,
missing references or conflicting inline/reference sources reject the import without changing
the current document. Derived outputs are recomputed, not stored as authoritative data.

Copying, duplicating, or saving a connected selection to the library remaps its internal IDs
as a unit. References outside the selection remain explicitly unresolved, even if a target
sketch contains the same UID. Reconnect those inputs in the dialog. Library placements still
initialize fresh state. Undo/redo restores both state and bindings.

Editor, static exports, library previews, and interactive HTML use the same validated computation
contract. HTML keeps bindings working offline and retains changes across tabs; reopening restores
the exported state. Ordinary bindings stay local; Whole workspace mode can pass values and typed
events through explicit Publish/Receive endpoints. Events do not replay after restoration.
There are no unrestricted external actions.

## Host-managed HTTP operations (integration API 1)

API v2 components opt into `integrationApi:1`. [HTTP source](examples/http-source.js) declares GET;
[HTTP POST](examples/http-post.js) adds a captured JSON body and explicit Send action. Both use the
same host-owned service; Worker scripts stay network-blocked and computation remains pure.

```js
integrationApi: 1,
eventApi: 1,
inputs: {
  url: {type:'string', default:''},
  path: {type:'string', default:'/value'},
  refresh: {type:'boolean', default:false, event:'action'},
  enabled: {type:'boolean', default:true},
  interval: {type:'number', default:5}
},
httpSource(state) {
  return {
    url:'url', path:'path', valueType:state.valueType, timeoutMs:10000,
    automation:{enabled:'enabled', interval:'interval', polling:state.polling === true,
      onChange:state.refreshOnChange === true, debounceMs:250, startup:state.refreshOnStart === true}
  };
},
dataActions: {refresh:{type:'httpGet', trigger:'refresh'}},
eventOutputs: {completed:{type:'string'}, failed:{type:'string'}},
actionEvents: {httpGet:{success:'completed', failure:'failed'}}
```

`url` and `path` name declared string inputs. `valueType` is `number`, `string`, `boolean` or `table`;
`timeoutMs` is bounded to 1,000–30,000 ms. JSON Pointer uses an empty pointer for the root,
`/items/0` for an array entry, and `~0`/`~1` escaping. Lookup uses own properties only.
An omitted method means GET. `compute(inputs,state,context)` reads a transient `context.source`
snapshot: `revision`, `status`, `loading`, `available`, `stale`, `error`, `lastUpdated`, `value`,
`json`, `jsonAvailable` and `httpStatus`. It does not schedule requests or copy response data into source state.

Declare `value` with the selected type, `json` and `error` as strings, `available` and
`loading` as Booleans, and `lastUpdated` as a number. The canonical components also expose
`status`, `stale`, `jsonAvailable` and numeric `httpStatus` (zero before a response). Table mode also
exposes numeric `rowCount`. Unavailable `value`/`json`
ports are withheld independently of placeholder computation results. Optional status wiring
cannot accidentally make missing source data available.

Scalar `value`/`json` use `event:true` for captured successful-response occurrences. Each successful
request also emits `completed` with compact JSON text; each failure emits `failed` with safe
error text. Identical response values still produce distinct events. Consumers may deliberately
store event payloads, for example in a Memo log; the source's own live snapshot remains transient.

### Table response publication

`valueType:'table'` maps the selected JSON value to a validated table. The pointer may select:

- A nonempty array of flat record objects. Columns are inferred from all rows, with first-seen
  key order; missing values become null and all-null columns become text. Non-null types must
  be consistent within each column. Nested objects/arrays in cells are rejected.
- An explicit `{name?,columns:[{key,name?,type}],rows:[...]}` object, using array rows and the
  existing typed-table contract. This form supports zero rows. A bare empty array is rejected
  because it defines no columns; no schema is borrowed from earlier results.

The host gives `compute` the normalized table at `context.source.value` when available.
Publish it using `{value:{table:context.source.value}}`, as for other derived table outputs;
the host assigns a compact runtime reference and immutable table version. The port declaration
is `value:{type:'table',label:'Table'}` without `event:true`. The canonical built-ins additionally
return the number of rows on `rowCount`. Source scripts must not copy the response into their
persistent `state`.

HTTP still bounds the received body to 64 KiB, and table validation applies the shared 32-column,
1,000-row and cell limits. In Table mode, compact JSON longer than 2,000 characters does not
invalidate a valid table. Instead `context.source.jsonAvailable` is false, the graph withholds
`json`, and no JSON hybrid event is emitted. `completed` still emits empty text for that successful
request. Smaller table responses retain the complete compact JSON and ordinary JSON/completion
events. Scalar response mode retains its existing text-limit error behavior.

Table values can feed pure table transforms or views directly. An existing Dataset owner can copy
them using Manual Replace/Append or Live source mode; the source never gains mutation rights to
that stored pool. Completion-triggered actions capture the table from that response, including
through pure transforms, so a subsequent request cannot substitute different rows. Ordinary table
ports do not themselves become hybrid event ports. Stored-copy schema checks, reader permissions,
independent source instances, cancellation and Run isolation remain unchanged.

### GET triggers and scheduling

Use `{type:'httpGet'}` in an action handle for manual Refresh. A declared `dataActions` entry
allows a false → true `refresh` signal or accepted event to request one read. Initial/restored
high values prime the baseline rather than replaying a request.

The optional `automation` descriptor names Boolean `enabled` and numeric `interval` inputs.
`interval` is in seconds, from 1 to 86,400. Boolean flags enable polling, URL/JSON-pointer change
reads and reader startup separately; `debounceMs` ranges from 0 to 10,000. The canonical settings
all default off, with a five-second interval and 250 ms change delay. Polling starts after its
interval in the editor as well as Run/HTML. Startup adds one immediate read per Run/HTML session
and source; importing, reopening or undoing in the editor does not invoke the startup policy.

`enabled:false` gates timer, change, startup and connected Refresh signal/event requests. The
component's direct Refresh button remains available. The shared `features.networkIntegrations`
switch disables every GET/POST regardless of authoring visibility. Configured reads are bounded,
with at most 30 automatic requests per instance in a 10-second window; manual Refresh is separate.
Polls never overlap, and polling/change schedules pause while hidden or simulation is paused.
Resuming does not replay missed intervals. Whole workspace scope keeps sources active when the
visible sketch changes; leaving Active sketch only scope cancels pending delivery.

### Explicit JSON POST

The POST capability names additional string inputs:

```js
httpSource(state) {
  return {method:'POST', url:'url', path:'path', body:'body', idempotencyKey:'idempotencyKey',
    valueType:state.valueType, timeoutMs:10000};
},
dataActions: {send:{type:'httpPost', trigger:'send'}},
actionEvents: {httpPost:{success:'completed', failure:'failed'}}
```

Declare `send` as a Boolean `event:'action'` input and use `{type:'httpPost'}` for the button.
POST does not accept an automation descriptor. Each accepted Send captures URL, body, mapping,
credentials and optional idempotency key. Input changes, polling, startup and restoration never
write. The body must contain valid JSON text within 2,000 characters with finite numeric values;
the host compacts it and sends `Content-Type: application/json`. An optional nonempty key contains
at most 200 printable ASCII characters and becomes `Idempotency-Key`. The endpoint must support
that key for duplicate protection; there is no automatic write retry or exactly-once guarantee.

A 204/205 POST response is successful without mapped data: `status:'ready'`, `available:false`,
`json:''`, and a `completed` event with empty text. The scalar or table remains unavailable and the card
shows Sent. Other successful responses must satisfy JSON/mapping validation. A 2xx response can
therefore yield a response error after the write was accepted; `httpStatus` remains available.
Cancelling, timing out, leaving a sketch or discarding Run cannot undo a server-side action.

### Lifetime, authentication and export

Both methods release the interaction/action queue immediately; network completion happens
independently. Each instance has its own revisions. Changed configuration, superseding GETs,
deletion and scope replacement prevent late responses from attaching to a different instance.
One response groups its hybrid value/JSON outputs and completion notification as one event
origin, so pure branches that reconverge are evaluated together once. Equal later responses
still produce new occurrences.
Static rendering, export generation and library thumbnails never schedule requests. Repainting and Undo
never replay a request edge or Send, although explicitly configured polling can resume afterward.

Response bodies are limited to 64 KiB and compact JSON text ports to 2,000 characters, with the
independent Table-mode availability described above. Finite scalar types,
timeouts and response validation are shared. No automatic retry is performed. HTTP response
snapshots stay outside history/autosave. `{type:'httpCredentials'}` opens the host-owned Credentials
dialog for no authentication, Bearer or HTTP Basic; credentials stay outside state and scripts.
Including selected credentials in a saved artifact is a separate per-export choice and does not
turn on polling/startup. Component/library/sketch copies omit credentials.

Run inherits session credentials into an independent host store and service lifetime; returning
discards local results and cancels pending delivery. Relative URLs use the parent editor URL;
exported HTML resolves them from its own URL. The opaque Run origin requires endpoint CORS for
`Origin: null`. Its iframe delegates `local-network-access`, `local-network` and `loopback-network`
permissions so supporting browsers can ask. User/deployment decisions can still deny access;
there is no proxy or `allow-same-origin` bypass. JSON POST and Idempotency-Key may require a CORS
preflight, which the server must permit. Custom column/field mapping, nested-record flattening and
saved offline source snapshots remain future extensions. MQTT connections, subscriptions and explicit
publishing are described below.

## Host-managed MQTT connections, subscriptions and publishing (integration API 1)

[MQTT Config](examples/mqtt-config.js) declares a host-owned connection. Its descriptor names
ordinary URL/client-ID inputs and an opt-in reader startup policy:

```js
mqttConfig(state) {
  return {url:'url', clientId:'clientId', startup:state.connectOnStart === true};
}
```

The required Config outputs are `connected:boolean`, `status:string` and `error:string`.
`compute(inputs, state, context)` reads those transient values from `context.source`. Action handles
use `{type:'mqttConnect'}`, `{type:'mqttDisconnect'}` or `{type:'mqttCredentials'}`. Connect captures
the current inputs. Draft changes do not silently reconnect. Credentials and client objects are
host-owned, never passed into Workers or stored in component state.

[MQTT Subscribe](examples/mqtt-subscribe.js) declares a typed reading:

```js
mqttSource(state) {
  return {topic:'topic', path:'path', format:state.format, valueType:state.valueType};
}
```

`format` is `text` or `json`; `valueType` is `number`, `string` or `boolean`. The host reference is
`item.mqttBinding = {sketchId, componentUid}` and is edited by the Config picker. It is not an
ordinary string port and is never resolved by display name. Transfer/duplication remaps the
reference only when its target travels with the copy. Missing targets remain visibly unavailable.
Cross-sketch references require Whole workspace execution.

Subscribe's outputs are `value` of the declared type, `json:string`, `available:boolean`,
`stale:boolean`, `error:string`, `lastUpdated:number`, `status:string`, and `topic:string`.
The built-in declares hybrid `value`/`json` outputs with `eventApi:1`. The host injects transient
readings through `context.source` and withholds unavailable data outputs before downstream
computation. Text mode has no JSON document; JSON mode returns the complete compact JSON plus
its mapped scalar. Source snapshots never enter authored state, history or autosave.

All retained messages and the first valid message per subscription/reconnect establish a current
value without emitting an event. Later live messages deliver captured values with one shared
origin per message, so equal messages remain distinct occurrences and reconverging pure branches
recombine once. Explicit consumers may store payloads, for example a Memo log.

Config uses manual connection by default, optional Run/HTML startup, clean MQTT sessions and
QoS 0 subscriptions. Different Config instances own separate connections; consumers of the same
Config share one. The runtime allows 16 connections, 64 KiB transport/payload buffering and
2,000-character text/JSON outputs. More than 60 messages/second on one connection disconnects it
visibly until another Apply / Connect. Blank client IDs are unique per Config/document session; duplicate explicit
IDs within an active document are rejected. Reconnect backs off with a bounded delay. Explicit
Disconnect retires connection intent; hidden/paused suspension preserves intent for resume.
Leaving an Active sketch execution scope retires its connection and requires Connect on return;
Whole workspace mode retains it across visible-sketch changes. Closing/replacing the workspace
retires all generations and rejects late messages.

The browser client is bundled in `index.html` and copied into self-contained HTML exports; it
never loads from a CDN. `networkIntegrations:false` disables connections. Run retains its isolated
origin and owns independent connections/credentials. Brokers must accept the WebSocket origin
(including Run's opaque origin where appropriate); browser network permissions still apply.
Credentials use the same explicit per-artifact inclusion choice as HTTP. Offline command replay
and saved reading snapshots are outside this increment.

[MQTT Publish](examples/mqtt-publish.js) uses the same `mqttBinding` Config reference:

```js
mqttPublish(state) {
  return {topic:'topic', payload:'payload', format:state.format,
          retain:state.retain === true, timeoutMs:state.timeoutSeconds * 1000};
}
```

`topic` and `payload` name string inputs. The topic must be an exact, nonempty MQTT topic; publish
wildcards are rejected. `format` is `text` (default) or `json`; JSON is parsed and compacted before
transmission. Retain defaults to false; acknowledgement timeout defaults to 10,000 ms and is bounded
from 1,000 to 30,000 ms. The built-in declares a Boolean control input `send` with `event:'action'`,
`dataActions:{send:{type:'mqttPublish',trigger:'send'}}`, and a `{type:'mqttPublish'}` action handle.
Only accepted explicit actions publish. Workers receive no socket or transport capability.

The dispatcher captures the resolved Config, topic, payload, format and Retain choice when accepting
Send. Pending sends do not block ordinary graph processing. The Config must already be connected;
disconnected sends fail immediately. At most one send per Publish component is pending. Later topic/
payload edits prepare the next Send; definition/descriptor or Config-reference changes retire pending
work. Input edits,
restoration, Undo, rendering, retained readings and reconnect do not send or replay captured commands.
MQTT Publish has no offline command queue and never retries automatically.

The host supplies `context.source` with `loading`, `status`, `error` and `lastPublished` (epoch ms).
Statuses are `idle`, `sending`, `ready`, `error`, `cancelled` and `disabled`. `ready` and a new
`lastPublished` mean **broker acknowledged** via QoS 1 PUBACK, never device execution. Its declared
`actionEvents:{mqttPublish:{success:'completed',failure:'failed'}}` uses string event outputs:
`completed` carries the captured transmitted payload (compact JSON in JSON mode), and `failed`
carries the error. Equal successful messages produce separate events. Transient results stay out
of source state/history/autosave unless an explicit consumer stores them.

QoS 1 can duplicate delivery. Timeout, disconnect or cancellation cannot prove the broker did not
receive a command; unknown outcomes must be surfaced instead of silently retried. Retiring or
replacing a document rejects late acknowledgements. A device acknowledgement belongs on a separate
response subscription and can carry its own command identifier. Pausing/hiding suspends MQTT and
fails unacknowledged sends with an unknown outcome. Failure events are buffered while hidden and
delivered once visible; resuming never replays the send. Already-issued detached HTTP requests can
instead finish while hidden.

## Embedded table data

`table` ports retain a compact `{datasetId}` reference or `{datasetId, rows:[0, 3, 7]}` selection.
A direct reference to another sketch's shared Dataset also carries its owning `sketchId`; the host
validates that owner in Whole workspace mode. Retain this field when forwarding such a reference.
Omitting `rows` selects every row; `rows:[]` is an empty result. Selected indices refer to the
original dataset, are unique integers, and retain their given order. A filter therefore returns
references to its incoming dataset without duplicating row contents in state or saved output.
Each reference is validated against the host's document pool before publication or use.
Stored row identities remain stable across value edits and sorting. The host remaps explicit saved
row selections after deletion or replacement; removed rows disappear from the selection.
Table-valued settings and combinational table feedback cycles are not supported. An explicit
Dataset owner → transform → owner.source path is allowed in Manual mode: only a Replace or Append pulse writes
the settled source snapshot back to stored records.

A table output may instead return `{table:{name, columns, rows}}` to produce a new table, as
Table aggregate does. Only declared table outputs accept this envelope. The host validates it with
the same row/column/cell/table limits as imported data and replaces it with a compact `datasetId`
reference before publication. These tables belong to the evaluation, never to component state or
the persisted source pool. Each returned table version is immutable: unchanged content keeps its
reference, while changed content receives a new runtime-only ID. Prior versions remain available
while current outputs, previous-round input snapshots, or their producing output still reference
them; unused versions are reclaimed during propagation and between evaluations. This preserves
consistent round snapshots during Step and replay without adding a version field to table ports.

The runtime supports at most 128 distinct table-producing outputs and 2,000,000 serialized
characters across all live table versions, separately from the embedded source pool. A temporary
old/new overlap counts toward that limit. An output object containing derived tables is limited to
500,000 UTF-8 bytes across all of its outputs. Exceeding a limit produces a recoverable component
error. Downstream snapshots, filters, sorts, charts, and downloads resolve derived references
exactly like source references. Opening or exporting a
saved document recomputes derived tables; references must be obtained from connections rather
than retained as literal dataset selections.

String port descriptors may declare `columnOf:'data'` to name a table input whose columns should
appear in their **Edit…** dropdown, and `columnType:'number'` to restrict choices to numeric
columns. These are ordinary string values and can still be connected to string outputs. A blank
value retains the component's default behavior (all rows or automatic column selection).

A sketch's `datasets` object maps stable IDs to normalized tables:

```json
{
  "results": {
    "name": "Sailing results",
    "columns": [
      {"key":"Boat", "name":"Boat", "type":"string"},
      {"key":"Points", "name":"Points", "type":"number"}
    ],
    "rows": [["Aurora", 3], ["Borealis", null]],
    "rowIds": ["r0", "r1"],
    "revision": 0,
    "nextRowId": 2
  }
}
```

Columns have unique nonempty keys and nonempty display names, with a type of `string`, `number`, or
`boolean`. Null cells represent missing data. Numbers are finite and integer values must be safe
integers; text cells contain at most 2,000 UTF-16 code units. Limits are 32 columns, 1,000 rows,
500,000 serialized characters per dataset, and 16 active datasets / 2,000,000 serialized characters
per sketch. CSV/TSV/JSON source files are limited to 1,000,000 characters. Unsupported imports fail
before replacing a document or a previously accepted dataset.

The document owns one current revision per dataset ID. Optional stored metadata is `rowIds`, a
unique identity for every row; `revision`, a nonnegative safe integer; and `nextRowId`, the next
monotonic row identity number. A plain imported table implicitly starts at revision 0 with rows
`r0`, `r1`, and so on; its first mutation materializes the metadata. Deleted identities are not reused,
and whole-table replacement allocates new identities. Append, update, delete, and replace commands
validate the complete proposed revision before committing. Update/delete address row IDs, and an
expected revision rejects stale edits. These are host operations, not script-callable write APIs.

Accepted revisions are immutable. Undo snapshots share the prior table objects alongside their scene
snapshots, and the signal timeline retains its committed dataset pool for historical replay. Editing
a dataset invalidates dependent graph results even when component state and bindings are unchanged.
The current pool, history, and replay therefore cannot accidentally resolve one ID to the wrong revision.

`compute(inputs, state, context)` receives resolved input snapshots in `context.tables`, keyed by
input port name. `transition` receives the same map in its existing context. Each snapshot has
`{name, columns, rows, rowIndices, rowCount, datasetId, revision, rowIds, editable}`: `rows` contains
the selected full cell values, `rowIndices` maps them to original dataset indices, and `rowIds`
contains the matching stable identities. Stored data has `editable:true` only with a live, unique
Dataset owner; ownerless and derived snapshots have `editable:false`. Derived snapshots have null row identities. Table payloads are limited to 2,000,000
serialized characters per computation call and 16,000,000 across one evaluation; exceeding either
budget produces a recoverable component error. Computation and presentation hooks must not copy
row data into state or memory; the explicit authoring import hook below is a bounded exception.

Owned snapshots also include `owner:{uid,input,name}` so a view can identify the component responsible
for the stored table. This metadata describes current graph ownership; it is not a writable record.

Presentation hooks receive bounded snapshots under `io.tables.inputs` and `io.tables.outputs`,
keyed by port. They contain the first 24 selected rows, with string cells longer than 160 characters
truncated for display; `rowCount` still reports the full selection. Computation always receives the
complete selection. API v2 components can opt into `tablePresentation:'full'` to receive complete
input snapshots in presentation hooks as well. Output snapshots remain previews, and the combined
presentation payload still has a 2,000,000-character budget. Spreadsheet opts in so displayed formulas,
cell editing, and published outputs use identical values. `inputs` and `outputs` themselves remain
compact references. The host caches these views with the settled graph.

### Table transforms and storage

Table filter, Table sort, and Table aggregate use the same table-port contract regardless of where
they appear in a flow:

```text
Source    → transforms → Dataset                (prepare stored records)
Dataset   → transforms → Dataset editor / chart (present current records)
Dataset A → transforms → Dataset B              (store an independent result)
```

Transforms do not mutate their inputs or own stored records. Filter and Sort retain the source
dataset reference and selected row identities. If that source has a healthy owner, an enabled view
can edit/delete the original record through the transformed selection; append requires a whole
stored table. Applying Filter or Sort to a derived table does not make it editable.

Aggregate publishes new calculated rows with no source row identity. Its result is read-only until
a Dataset copies it into owned storage, assigning independent row identities. Edits to this copy
never propagate upstream. Manual destinations accept Replace/Append pulses; Live destinations replace
their records on a source publication, overwriting local edits. Editing a destination does not count as a refresh of its own incoming source. If another Dataset
consumes that destination, those edits are new publications for that downstream consumer.

Table flow means successive current snapshots, not arriving-row events. Each aggregate calculation
covers its current input selection. It does not retain event history or implement time windows;
explicit Capture row actions can accumulate scalar samples in a Dataset first.

### Bound dataset cell editors

An API v2 inline text handle can declare a host-owned cell edit instead of calling `dragEdit`:

```js
{id:'B2',kind:'text',value:'3',x:150,y:45,
 inline:{x:100,y:30,w:100,h:30,fontSize:14,mode:'edit'},
 datasetCell:{input:'data',datasetId:'results',rowId:'r0',column:'Points',revision:0}}
```

`datasetCell` contains `input`, `datasetId`, `rowId`, `column`, and `revision`, with an optional
Boolean `reader` permission. Its input must
still resolve to the same stored dataset and include the row; the revision must match the snapshot
from which the editor opened. The handle must use `kind:'text'`, `inline.mode:'edit'`, and cannot be
read-only. The host validates the live Dataset owner and column type, then commits one update. It uses the stable row identity,
so editing a filtered or sorted view updates the correct source record. Aggregate results remain
read-only. A stale edit is rejected rather than silently applied to a different revision.

Text is literal, including leading `=`. Numeric entry accepts a finite supported number, Boolean
entry accepts `true` or `false`, and an empty numeric/Boolean entry means null; empty text stays an
empty string. This path never evaluates a spreadsheet formula or invokes `dragEdit`. In HTML the
handle must also be reader-visible, and either `datasetCell.reader` or `state.allowReaderEdit`
must be true. Spreadsheet's INPUT access `2` sets `datasetCell.reader:true` for that range;
access `1` only allows editor writes, while omitted access or `0` is read-only. Dataset editor
keeps its separate **Allow reader edits** setting. Headers and absent/derived cells stay read-only,
and ordinary formulas remain local.

### Dataset record controls and view layout

[Dataset editor](examples/data-table.js) evolves the existing Data table into a records view. Its
schema and row count follow the input; its zero-based `startRow` and `startColumn` inputs page through
all accepted data. Unbound page controls edit those actual inputs; bound controls display the linked
position. It requests full table presentation and draws at most 12 rows × 8 columns, keeping cell,
row, and navigation handles below the 128-handle limit. **Edit dataset records** (`editDataset`) and
**Allow reader edits** (`allowReaderEdit`) both default false.

Record actions use `kind:'action'` handles with these descriptors:

```js
{type:'appendDatasetRow',input:'data',datasetId:'results',revision:0}
{type:'deleteDatasetRow',input:'data',datasetId:'results',revision:0,rowId:'r0'}
```

An explicit click commits directly through the host. It validates the current owner, table input,
record-edit setting, dataset ID, and revision; HTML also checks reader permission. Append requires a
whole stored table and creates one all-null record. Delete validates that the row identity still
belongs to the displayed selection. Filtered/sorted views can edit/delete source records but cannot
append. Derived or ownerless tables stay read-only. Editor actions create one Undo entry; reader
actions are session-local. Stale controls cannot retarget another record. Cell text is always literal.

Spreadsheet remains an authored cell grid. Dataset rows do not change its dimensions, formulas, or
formatting. Its optional linked rectangle and DATA/COLUMN/ROWS functions consume records; formulas
and other cell metadata stay on the sheet instance. A1 references to a linked area follow visible
positions, not stable record identities. Use Dataset editor for dynamic record editing.

New Spreadsheet instances start with an empty 6×6 grid and no formula-declared ports. The example
workspace supplies demonstration values and formulas explicitly. A standalone declaration
`INPUT("data",A1:C6[,start][,access])` maps a named table input into a rectangle. Put the declaration
outside the mapped range; its first row shows headers, with at least one record row beneath it.
`start` defaults to 0 and may be a nonnegative integer, a cell expression, or `INPUT("startRow")`.
Access defaults to `0` (read-only); `1` permits editor writes; `2` also permits HTML reader writes.
Several nonoverlapping rectangles may consume independent inputs. Their declaration cells remain
editable when invalid, and errors explain out-of-bounds, occupied, overlapping, or self-containing
ranges. Invalid declarations must not silently publish partial results or hide their authored cells.
Structure edits before/after a linked area preserve reference mapping; edits that alter the area's
mapped row or column structure are rejected. Change its INPUT formula deliberately to resize it.

Spreadsheet publishes a calculated range through `OUTPUT(range,"name"[,type,type,...])`, one
named table output port per declaration. Every result range includes a header row and at least one
data row; header cells may be literal or calculated. Types are inferred from non-null values or
set per column with `0` auto, `1` number, `2` string, and `3` Boolean. Type names are also accepted;
a single comma-separated type string is supported. INPUT and DATA scalar types use the same codes,
with `0`/omitted meaning number. For example, `OUTPUT(D1:E4,"Readings",2,1)` publishes three records.
A single-cell argument such as `OUTPUT(A2,"value",1)` remains a scalar output, not a table.
Header keys must be unique; linked headers preserve their source key, display name, and type where
possible. The derived table contains evaluated scalar/null values only. Blank cells become null,
literal empty strings stay strings, and formula/type errors reject the entire result. INPUT/OUTPUT
range declaration cells are blank in calculations and outputs; editor-only markers identify them.
Range references follow permitted structure edits. A linked rectangle contributes the current page;
whole-column calculations can still use COLUMN. Consumers can read results directly, or a Dataset
can store them with Replace/Append or Live mode. Formulas and formatting stay on the sheet.

### Formula and connection authoring

Spreadsheet declares table areas and outputs in cell formulas. **Insert function → Datasets**
in the cell context menu inserts a formula for inline editing; authors choose the declaration cell
and edit its name, range, start, access, or column types there. The Edit inspector retains the fixed
component type, editable instance name, bindings for already-declared named inputs, and output
previews. It does not duplicate formula authoring in a separate range editor. The HTML reader
consumes the saved formulas and their access permissions.

An optional `configurationError(state)` function returns `null` for valid configuration or a plain
error message of up to 500 characters. Capabilities retain this diagnostic so the graph reports it
before checking saved connections. Invalid spreadsheet declarations therefore keep their useful
cell-addressed error even when a previous dataset assignment is still present; repair handles remain available.

### Authoring imports and copies

An optional API v2 `importTable(state, table, w, h)` authoring hook returns `{state}` or `{state,size}`,
using the same validated state and size limits as `dragEdit`. It enables **Copy dataset to editable
cells** beside table inputs in **Edit…**. The host passes the complete selected table snapshot,
including the selected row order, only after an explicit click. It stages the returned state and size;
connected sources use the published snapshot frozen when Edit opened, not a draft computation preview.
**Save** applies one undoable change and removes assignments to inputs the new state no longer declares.
**Cancel** discards the copy. The hook cannot modify the source dataset or access files; the HTML
reader does not expose this authoring action.
Existing dataset selection and CSV/TSV/JSON import previews supply the source. Spreadsheet replaces its
grid with a literal copy, removes its former formula declarations, and rejects data exceeding its
grid or state budget.

The author creates an empty typed table through **New dataset…** or imports CSV/TSV/JSON through a
table input's **Edit…** controls. Creation names the dataset and its nullable typed columns; it
is staged until **Save**, just like import. CSV/TSV offers **Automatic**,
**Comma**, **Semicolon**, and **Tab** delimiter choices. Automatic detection respects quoted cells and warns
when the choice is ambiguous; changing the choice refreshes the typed-column and row preview.
Type inference is independent of the delimiter: decimal-comma values remain strings. Physically blank
lines are ignored; quoted empty cells, delimiter-only records, and whitespace content remain rows.
Imports stay provisional until **Save**, and **Cancel** discards them. Dataset selectors include local
tables and, in Whole workspace mode, datasets whose owners enable **Show in workspace catalog**.
Turning this off hides an owner from new choices without breaking existing references. Ordinary
connection selectors still allow one typed output per input. Copies and library entries carry only their
referenced tables, remapping dataset IDs if another document already uses an ID for different data.
Duplicating or pasting a Dataset owner always allocates an independent stored table. Copying only a
consumer within the same document retains its current shared reference; cross-document copies and
library placement carry the required data. The persisted `datasetOwner` hint is derived from validated
script capabilities, so copying can retain these semantics without executing a script in the copy path.
Undo/redo retains immutable prior revisions; saved JSON and HTML omit history-only tables.
HTML contains the same dataset services and table runtime and works offline. Imports, bound edits,
and capture each have their own opt-in reader control. Accepted reader changes are session-local;
reload restores the embedded snapshot. The editor autosaves accepted changes. Download table exports
current rows as CSV or JSON; it does not save reader changes back into the HTML or an editable workspace.

Built-ins are [Dataset](examples/data-source.js), [Capture row](examples/capture-row.js), [Table filter](examples/table-filter.js),
[Table sort](examples/table-sort.js), [Table aggregate](examples/table-aggregate.js),
[Dataset editor](examples/data-table.js), [Data bar chart](examples/data-bar-chart.js), and
[Download table](examples/data-download.js).
Table filter supports typed comparisons and empty checks; a blank column passes all rows. Dataset editor
pages over at most 12 rows and eight columns; Data bar chart shows at most 24 bars, one per row, including
negative values. Both report bounded views without modifying the table. The **Embedded data**
example connects a Text input to a boat-name filter, then drives a table and chart from its output.
The **Reader data and results** example loads or reloads race results, sorts them by boat name,
aggregates points per boat, and downloads the alphabetical report. Its chart uses automatic columns
so the original rows also render when aggregation is bypassed. This tab also enables **Allow column
changes in HTML export**: load a file with different columns, choose **Use the file’s columns**, and
review the affected components before accepting. **Dataset action results** keeps the default
restriction, so its reader only offers **Keep current columns**.
The **Shared dataset** example connects captured scalar readings, a bound editable Spreadsheet,
and additional views to one stored dataset. The **Dataset** component owns that table; rows are stored
once in the document. **Source to dataset** demonstrates a separate incoming table/filter, explicit
Replace/Append pulses, and independently editable destination rows. A provider supplies candidate data;
it does not own the destination. File import remains an owner convenience. **Live dataset editor** demonstrates refresh overwriting
a working copy; **Spreadsheet result tables** materializes calculated values into another editable
Dataset. Tab 26, **Views and stored results**, uses one source to compare an editable filtered/sorted
view, a read-only aggregate, and an independently editable Manual copy of that aggregate. Edit through
the view to update the source and total; click **Copy current total** (a Replace pulse), then edit the
copied total to leave both unchanged. A later source edit updates the views but leaves the stored copy
alone until **Copy current total** is clicked again.
Coordinated current-record controls and calculated dataset columns remain future extensions.
HTTP Table responses already feed direct flows or Dataset's Source input. HTTP and MQTT also supply transient
scalar readings and compact JSON text; it does not create a second stored Dataset model.

Table sort accepts `column` and `direction` (`ascending` or `descending`); blank `column` preserves
input order. Sort is stable, nulls are last in both directions, and text is case-insensitive unless
its `caseSensitive` setting is enabled. Table aggregate accepts `group`, numeric `value`, and
`operation` (`count`, `sum`, `average`, `min`, or `max`). Blank `group` summarizes the entire table;
otherwise groups retain first-appearance order, including a null group. Text group keys are
case-sensitive. Count includes all rows.
Numeric operations skip nulls; an all-null group sums to zero and has null average/min/max.
The output has an optional `group` column with the selected group's label/type and a numeric
`result` column. Aggregate tables are runtime outputs, recomputed from saved source tables and
settings, rather than component state or new persisted source datasets.

Sort and Aggregate declare `enabled:{type:'boolean',default:true}` and a `showSwitch` Boolean
setting defaulting to true. Disabled transforms return the incoming table reference and row count
unchanged, before applying their sort/group/value choices. Bypassing Aggregate therefore restores
the original columns rather than returning grouped columns; downstream selectors must accommodate
that schema. Their optional switches follow the Boolean input-handle contract above.

Dataset's `allowReaderImport` setting enables explicit file replacement and its declared
`reload` trigger. **Load data…** defaults to **Keep current columns**; **Use the file’s columns**
is also available in the editor, and in HTML when `allowReaderColumnChanges` is true. Reload
always requires the currently accepted column keys and types; extra columns are allowed. The file chooser,
column policy, delimiter selection, preview, and acceptance belong to the host. Download table takes table `data`
and string `filename` inputs. Its CSV/JSON controls work in the editor and HTML reader, acting only
on an explicit click followed by confirmation; runtime
re-evaluation, restore, and retries never request a download. See the host-owned table action contract above.

### Component index convention

All component indices and indexed ports are zero-based: valid positions run from `0` to `N−1`.
This includes selected table/list rows, stepped channels (`in0`, `out0`), storage taps (`q0`),
and matrix rows/columns (`row0`, `col0`, `r0`, `c0`). Dropdown defaults to index 0; missing selections
and lookup results use `index:-1` with `valid:false` or `found:false`. Counts such as Channels,
Stages, row counts, and line counts remain quantities, with their existing limits. Stable choice
keys are independent of indices. There is no configurable index base or migration layer.
Spreadsheet notation is an explicit domain exception: A1 row references, VLOOKUP column numbers,
and MID character positions start at 1. It does not change the zero-based component signal contract.

### Choice lists and text lookup

[Dropdown](examples/dropdown.js) and [Text lookup](examples/text-lookup.js) share two sources.
Their `source` setting is `list` (default) or `dataset`. In list mode, `choices` is a JSON string
containing an ordered array of `{text, key}` rows. The host's Edit dialog presents editable rows,
not JSON; authors can add, remove, and reorder choices. Limits are 64 rows and 2,000 serialized
characters for the entire list. Text may repeat; nonempty keys must be unique. Empty keys mean
that no stable key was supplied. Changing source leaves the saved list intact.

Dataset mode adds `data:{type:'table'}`, `textColumn` and optional `keyColumn` string inputs with
column selectors for the table. Both columns must have string type; null text/key cells become
empty strings. Blank `keyColumn` means no keys. All selected rows are available, in selection order,
within the existing table limits; no 24-row presentation preview is used to build the choices.
Sorting or filtering upstream changes index positions, while keys remain attached to their rows.

Dropdown has numeric `select` (default 0) and outputs `index`, `key`, `text`, and `valid`. The native
on-canvas dropdown edits the literal Select input only when unbound; connected Select is read-only.
Boolean `showArrow` defaults true; false produces a plain text display without a selection handle.
A valid zero-based integer position returns that row. An invalid position returns
`{index:-1,key:'',text:'',valid:false}` without snapping or clamping.

Text lookup takes string `text` (default empty) and outputs `index`, `key`, and `found`.
Boolean `caseSensitive` defaults true and `trim` defaults false. It normalizes the incoming value
and labels according to those settings and returns the first match. No match returns
`{index:-1,key:'',found:false}`. Empty text can match an empty label. The **Choices and text lookup**
workspace tab demonstrates both sources, automatic selection, and shared forward/reverse mapping.

## The `style` object

Passed to every hook that takes a `style` argument — the container's own **currently resolved**
style, exactly what the toolbar's Fill/Stroke/Stroke-width/Text-color/Font controls currently
show for this instance:

| Field | Meaning |
|---|---|
| `color` | stroke/line color |
| `fillColor` | fill color |
| `fill` | boolean — is Fill on |
| `strokeOn` | boolean — is Stroke on |
| `textColor` | text color |
| `size` | stroke width |
| `dash` | `'solid'`, `'tight'`, or `'wide'`; unset also means solid |
| `fontFamily`, `fontSize`, `font` | the container's own font settings (`fontFamily` is `sans`, `serif`, `mono`, or `cursive`; `font` is the ready-to-use CSS font string) |

Use `presetColors` instead of a hard-coded color list/count whenever your shape's design

bar count off this, so it never silently drifts out of sync with the real palette).

## Child descriptors

Each entry `children()` returns is a plain object describing one shape, in **local
coordinates** — `(0,0)` is the container's own top-left, `(w,h)` its bottom-right. The app
shifts every child into world coordinates for you; never add the container's own `x`/`y`
yourself. Every child needs a supported `type` and its required geometry:

| Type | Geometry and type-specific fields |
|---|---|
| `rect`, `ellipse` | Required `x`, `y`, `w`, `h` |
| `line` | Required `x1`, `y1`, `x2`, `y2` |
| `arrow` | Line geometry, plus optional `hs`, `he`, `hsStyle`, `heStyle` (see [Arrowheads](#arrowheads)) |
| `path` | Required `points`: at least one `{x,y}` point. Optional `mode`: `'pen'` (default), `'marker'` (translucent), or `'brush'` (chisel stroke) |
| `text` | Required `x`, `y`, `w`, `h`, `text`; optional `font`, `fontFamily`, `fontSize`, `plainText`, and `align` (`'left'`, `'center'` (default), or `'right'`) |
| `polygon` | Required `points`: `{x,y}` points with optional Bézier controls or arcs. `closed` defaults to `true` and requires at least three points; `closed:false` requires at least two. Optional `fillRule`: `'nonzero'` (default) or `'evenodd'`. Open polygons also support arrowheads |

### Shared fields and defaults

| Field | Accepted values and effect |
|---|---|
| `color`, `fillColor`, `textColor` | CSS hex strings: `#RGB`, `#RGBA`, `#RRGGBB`, or `#RRGGBBAA`; named colors and `rgb()` are not accepted |
| `size` | Stroke width from 0 to 60, including fractions |
| `fill` | Boolean; defaults to `false`. Applies to boxes, ellipses, and closed polygons |
| `strokeOn` | Boolean; defaults to `true`. Controls outlines and visibility of line/arrow strokes |
| `dash` | `'solid'`, `'tight'`, or `'wide'`. Omitted inherits the container's pattern; set `'solid'` explicitly for a continuous stroke. Applies to outlines and line/arrow/polygon strokes |
| `editorOnly` | Boolean; defaults to `false`. When `true`, omitted from SVG, PNG, print, thumbnails, and interactive HTML |

`path` children use `color`, `size`, and their own `mode`; they do not use `fill`, `strokeOn`,
or `dash`. A text child’s `fill`, `fillColor`, `strokeOn`, `size`, and `dash` style its box.
For a label without a box, set `strokeOn:false, fill:false` explicitly. Text itself uses
`textColor`, falling back to `color` if no text color is available.

### Text fonts

Use `font:style.font` to follow the container's current font. Alternatively, specify
`fontFamily:'sans'` and `fontSize:16` directly. Family keys are `sans`, `serif`, `mono`, and
`cursive`; they select the app's predefined system-font stacks. A text child without font settings
uses 16px sans, not the container's font.

The validator rebuilds `font` from a supported family and a size from 0 to 400. A pixel size in
`font` takes precedence over `fontSize`; an explicit `fontFamily` selects the family. Otherwise,
only a recognized app font stack in `font` preserves its family; arbitrary CSS family names fall
back to `sans`. A leading `italic` and a leading weight of `bold` or `100`–`900` are retained;
the default weight is 600. Use the family keys instead of hand-writing font stacks.

Text beginning with a bare `---` first line uses the app's Markdown renderer, just like ordinary
text boxes; see [Text formatting](README.md#text-formatting-and-copying) for supported Markdown syntax.
Set `plainText:true` on a text child to display that marker and all content literally. Use this for
user-entered or connected text that should never opt into Markdown formatting.

### Arrowheads

`hs` and `he` are booleans enabling the start and end heads. An `arrow` defaults to no start
head and an enabled end head. An open `polygon` defaults to neither. `hsStyle` and `heStyle`
accept `'open'` (default), `'filled'`, `'open-inverted'`, or `'filled-inverted'` independently.
Use `hs:false` or `he:false` to remove a head; `'none'` is not a valid style value. Closed
polygons and `line` children do not draw heads.

### Bézier points

In a `polygon`, the segment from point `a` to the next point `b` uses `a.c1` as its outgoing
cubic control point and `b.c2` as its incoming control point. Each control is an absolute
`{x,y}` in the same local coordinate frame as the points, not an offset. Omitted controls
use their associated endpoint; with neither control, the segment is straight.

```js
{type:'polygon', closed:false, points:[
  {x:0, y:60, c1:{x:30, y:0}},
  {x:120, y:60, c2:{x:90, y:120}},
]}
```

An `arcTo` on `a` takes precedence over Bézier controls for that segment; see
[Arcs](#arcs-in-a-polygon-child). Use `polygon` for explicit curves: `path` children smooth
their `{x,y}` samples as freehand strokes and do not render these controls or arcs.

### Style inheritance — read this before your shape renders invisible

Only `color`, `textColor`, `size`, and `dash` are inherited onto a child **automatically** — a
child descriptor that omits them gets the container's own current value for free. **`fill`,
`fillColor`, and `strokeOn` are deliberately *not* auto-inherited.** Font settings are not
auto-inherited either; use `font:style.font` for text children. Reference `style.fill`,
`style.fillColor`, `style.strokeOn` explicitly on any child you want to follow the toolbar's own
Fill/Stroke toggles:

```js
children(state, style, w, h){
  return [{
    type:'ellipse', x:0, y:0, w, h,
    color: style.color, size: style.size,          // inherited anyway, but explicit is fine too
    fill: style.fill, fillColor: style.fillColor,   // must be explicit
    strokeOn: style.strokeOn,                        // must be explicit
  }];
}
```

Why: `strokeOn` means something different per type — for a `rect`/`ellipse` it's "show an
outline," but for a `line` it's "is this visible **at all**." Explicit opt-in lets a script
keep essential geometry visible when the toolbar's Stroke toggle is off. The container never
draws its own box, regardless of `strokeOn`; newly authored definitions start with Stroke on.
A **hard-coded** child (Clock's face outline, say) can set `strokeOn:true` and ignore the toggle.

### Your shape is responsible for its own bounds

Children are **never clipped** to the container box — `w`/`h` are inputs, not enforced bounds.
Clamping state only in `dragEdit()` is insufficient: the user can resize the container afterward
without dragging a script handle. Derive effective geometry from the current `w`/`h` in a shared
layout helper, and use it in `children()`, `handles()`, `hitEdit()`, and `dragEdit()` as in the
[worked example](#a-complete-worked-example). Ratios stored in state are another useful option
for geometry that should scale with the box.

Keep lower bounds compatible with tiny containers: a fixed 5px minimum radius cannot fit a box
less than 10px wide. If all painted content must fit, reserve room for stroke thickness, arrowheads,
and labels too. Outside children are otherwise allowed and included in cropped exports, while the
container's selection rectangle and rotation pivot keep their original geometry.

## Arcs in a polygon child

A `polygon` point may carry an optional `arcTo: {cx, cy, r, a1, a2}` — "the segment **leaving**
this point is a circular arc to the next point, not a straight line." Angles are in radians: `0` is
straight up (12 o'clock), increasing **clockwise** — the same convention a clock hand's own
angle math uses, *not* canvas/SVG's native 0-is-3-o'clock convention (the app converts at the
render/export boundary; your script never needs to think about it).

Sketched as a standalone helper below for clarity — in a real script this logic lives as a
`children()`-only local step (or a method on your own script object, like Timer's `_layout()`),
because the Script field expects one expression returning the script object:

```js
// A filled pie wedge from angle a1 to angle a2, radius r, centered at (cx, cy):
function wedge(cx, cy, r, a1, a2, style){
  const start = { x: cx + r*Math.sin(a1), y: cy - r*Math.cos(a1), arcTo: { cx, cy, r, a1, a2 } };
  const end   = { x: cx + r*Math.sin(a2), y: cy - r*Math.cos(a2) };
  return {
    type:'polygon', closed:true, fill:true, strokeOn:false,
    color: style.fillColor, fillColor: style.fillColor,
    points: [ {x:cx, y:cy}, start, end ],   // center -> arc start -> (arc) -> arc end -> back to center
  };
}

// The bow alone (no center point, not filled): drop the center point and set closed:false --
// points: [ start, end ], closed:false
```

A closed `[center, arcStart(with arcTo), arcEnd]` triple draws a genuine pie wedge (`M → L → A →
L → Z`); dropping the center point and `closed:false` draws just the bow itself. Both the Arc
and Timer templates use this. If your sweep can reach a **full turn** (2π), clamp it a hair
short (`Math.min(sweep, 2*Math.PI - 0.0001)`) — SVG's arc command can't represent an exact full
circle (start and end coincide), which would otherwise break your shape's own SVG/HTML export
even though it renders fine on canvas.

## HTML export behavior

The editor's **Run** toolbar button uses this same reader on an isolated workspace copy. It is
not another script execution mode: `editorOnly`, `exportBehavior`, bound-cell access, Dataset
reader permissions, Workspace/Sketch settings, event delivery, and result downloads follow the
HTML contract below. The authoring simulation is suspended while preview runs. **Return to editing**
destroys the copy without adopting its state, data, layout or query changes; each run captures a
fresh snapshot. Result files explicitly downloaded during preview remain available.

Preview initially receives the editor URL's query parameters and follows the same initial-sketch
precedence as export. Navigation updates preview-local parameters, never the editor's browser URL.
Reader title changes appear in the preview header without changing the editor's browser title.
The preview frame has a separate opaque origin and cannot read the authoring page's DOM or storage.
The persistent return control belongs to the editor outside that frame, so a reader cannot hide it
through Sketch settings. No preview state is written back through the component API.
Preview imports use a regular file chooser; choose the file again to read subsequent disk changes.
Native reload handles are unavailable in the isolated frame, while a standalone export can retain
them where supported. Markdown links open separately with `noopener`.

Multi-tab readers accept `?page=N` to select the opening tab, using a zero-based index. Missing,
invalid, or out-of-range values use the configured Workspace settings initial sketch when available,
otherwise the first tab. Plain exports use the first tab as their fallback.
Clicking another tab does not change the URL. Additional parameters remain available to declared
query consumers, for example `drawing.html?page=1&name=Anna`. Query input is read locally and
works for an exported file opened from disk as well as a hosted HTML document.

An HTML export is one offline file containing the drawing, scripts, saved state, sandbox, and runtime.
Scripted controls work directly, without double-clicking to enter edit mode. Ordinary shapes and
smart-shape containers stay fixed by default. There is no unrestricted resizing.
Authors can independently enable moving a smart shape by its body, rotating it using the round
handle above it, changing its width from a right-edge handle, and changing its height from a
bottom-edge handle. The rotation handle appears after clicking the shape and hides when another
shape or the page is clicked, **Escape** is pressed, or the tab changes. Scripted controls still
respond to the first click.
The corresponding flags are `move`, `rotate`, `resizeWidth`, and `resizeHeight`. Width and height
changes regenerate children with the new `w` and `h`; they do not stretch the rendered drawing.
For example, a ruler extends at its original tick spacing. Each resize preserves the opposite edge,
including after rotation. Hold **Shift** while rotating to snap to absolute **15° increments**,
matching the editor, including the shape's original own and group rotation. Releasing Shift without
moving the pointer keeps the last angle when the gesture ends.

Set permissions once in the script object:

```js
exportBehavior: { move:true, rotate:true, resizeWidth:true },
```

Or derive them from saved state, allowing the creator to configure each placed instance:

```js
exportBehavior(state){
  return { move:state.allowMove === true, rotate:state.allowMove === true,
    resizeWidth:state.allowExtend === true };
},
```

Missing flags are `false`; supplied flags must be booleans. The function receives a copy of state
and cannot mutate the saved instance. `initState()` and `initStyle()` are not called when an HTML
file opens: it resumes the exported state, style, and dimensions. State, movement, rotation, and
dimension changes in the page are kept in memory across exported tab switches; reopening/reloading
restores the export.
Only the visible sketch regenerates its drawing. Whole workspace mode continues component evaluation
in every sketch; Active sketch only mode pauses inactive sketches. Both drawing refreshes and interval
simulation stop while the browser document is hidden, with the accepted-event exception described above.

For creator-only permission controls, mark **every visual child and its matching handle**:

```js
// Within children(), usually guarded by `if(editing)`:
{type:'text', x:0, y:h+6, w, h:24, text:'Allow moving', editorOnly:true},
// Within handles():
{id:'allowMove', x:w/2, y:h+18, kind:'click', editorOnly:true},
```

Keep normal `hitEdit()`/`dragEdit()` logic for that ID; the editor runs it normally. Exported
renderers filter marked children, and HTML rejects marked handle IDs even if `hitEdit()` returns
them. Marking a child does not automatically mark its handle. Unmarked operational controls such
as stopwatch Start/Pause or ruler units remain available. The ruler example demonstrates both
permission toggles, off by default, with undo and sketch/workspace persistence. Its single
**HTML: move / rotate** toggle binds both `move` and `rotate` to `state.allowMove`;
**HTML: extend** controls width separately.

The same Worker isolation, timeouts, reply validation, and network restrictions apply in HTML.
A transient sandbox failure retries after a three-second backoff, retaining its original diagnostic.
Unversioned shapes keep their last valid drawing; API v2 components show an unavailable drawing.
Permanent configuration/connection errors wait for a relevant change rather than repeatedly retrying
the whole graph. Unchanged valid reader drawings can be reused until their requested refresh is due.
If JavaScript is disabled or unavailable, the initial SVG remains visible. The HTML contains the
original shape source; `editorOnly` filters presentation and interaction, not source-code access.

### Live updates and exports

The app owns one refresh timer for the active document and stops it while the browser document is
hidden. Returning to a document refreshes live readings. Removing a shape or replacing its script
cancels its drawing scheduling; changing tabs moves drawing refreshes to the newly visible sketch.
Component simulation has the separate execution-scope rules above. Refreshes only redraw: they never mutate state, add undo
entries, or autosave. Interactive controls remain available when smart-shape authoring is disabled.

Derive readings from timestamps (`Date.now()` or `new Date()`), rather than incrementing counters
on each call. Redraws can be delayed, and Worker-local variables are disposable. Store a stopwatch's
accumulated elapsed time and start timestamp in state; Start/Pause/Reset are ordinary `dragEdit`
actions. The shipped API v2 Stopwatch also accepts run/reset commands through `transition`.
Its display continues elapsed time across tab switches, backgrounding, and reloads, while its
single `elapsed` output retains the last paused total until the next pause/reset. It starts
stopped when placed afresh.

PNG, SVG, printing, and library thumbnails request fresh children once without starting refresh timers
or invoking `refreshMs`. HTML includes an initial frozen SVG and then runs the smart shapes in an
isolated runtime, including `refreshMs`, while its tab is visible. JSON sketches and workspaces
retain the script and state, so live shapes resume when opened in SimpleCanvas.

## Fixed units and physical printing

[Ruler](examples/ruler.js) and [Drill template](examples/drill-template.js) both use
**96 canvas px = 1 inch = 25.4 mm**. Resizing the ruler changes how far its scale extends; it never
stretches the unit spacing. Its edit-mode unit control cycles cm/mm, inches, and px. Fine divisions
are omitted on exceptionally long rulers to stay within the child budget, preserving the scale.
The `_scales` definitions in the example can be changed to make custom scales. The drill template
uses the same conversion for hole diameter and offsets; resizing changes its hole spacing.

SVG exports have matching physical dimensions and viewBox dimensions, including fractional pixels.
Print SVG at **Actual size / 100%**, without fitting to the page. Default PNG exports are 2× resolution:
**192 image pixels represent one inch**, so place/print at 192 pixels per inch for the same scale.
Cropping includes margins and outside labels; do not treat the complete image width as the ruler's
marked length. The app's **File → Print** preview defaults to **Actual size (100%)** and **Landscape**,
with paper selection, orientation, margins, an oversize warning, and an optional 50 mm reference mark. Print uses a frozen
SVG snapshot with edit controls removed. Choose the same paper and orientation, **100% / Actual
size**, no extra margins, and no headers/footers in the browser print dialog; its settings and the printer driver can
still rescale output. Check a known division on a printed template before use.

## Constraints and sandbox

- **Script length**: 64,000 characters. **State**: 4,000 characters once `JSON.stringify`'d.
  Both are enforced at execution as well as load. Oversized state updates are rejected, not
  truncated. State contains only JSON data, has at most 16 levels, and cannot use the keys
  `__proto__`, `prototype`, or `constructor`. The longest shipped example is below this limit.
  A missing saved state defaults to `{}`; a supplied invalid state rejects that imported item.
- **Result limits:** 1,000 children, 20,000 points across the whole result, 2,000 characters per
  text child and 20,000 total text characters. A serialized reply is limited to 512 KiB. Geometry
  must contain finite numbers between -1,000,000 and 1,000,000. Negative local coordinates and
  signed box dimensions are allowed; finite negative arc radii normalize to zero. Stroke sizes
  range from 0 to 60, including fractional sizes. Text fonts are rebuilt from supported families
  and a size between 0 and 400. Colors use CSS hex notation; flags must be booleans. Unknown child
  fields are discarded, an invalid child is skipped with an error, and an exceeded result budget
  rejects the whole result rather than truncating it. Renderer guards remain in place.
- **Sandboxed.** A smart shape's script is real JavaScript, but it never runs in the page's own
  scope — every hook (including `compute`, drawing, interaction, and initialization hooks) is
  called inside an instance-owned Worker created by a trusted hidden `srcdoc` frame with
  `sandbox="allow-scripts"` and no same-origin permission. Its restrictive Content Security Policy
  blocks network connections and external scripts, including native prototype API calls and
  dynamic module imports. The Worker inherits that policy from its local Blob source. Script source
  is sent as data; it is never inserted into the frame's HTML. The opaque origin separates it from
  the app's storage, and a Worker exposes no page DOM. The frame and main app exchange messages over
  a dedicated MessageChannel. The trusted manager binds replies to their originating Worker and
  active request; a script's echoed identifiers cannot target another instance. Requests wait in a
  trusted queue, with one dispatched at a time. Worker startup has a separate two-second deadline;
  the 250 ms hook deadline begins after that Worker's startup, so queue wait does not consume it.
  Each realm also has a nonrenewable 250 ms lifetime from its first dispatched call. Successful
  replies do not extend it: an idle realm terminates on expiry; an active hook finishes or hits its
  existing request deadline, then the realm retires before its reply is delivered. This bounds
  background timers and Promise/async continuations scheduled after a successful return.
  A timeout terminates only that instance's Worker and preserves healthy queued work. Transient failures
  retry after a three-second backoff without requiring another user interaction; the original failure
  remains visible during that wait. Permanent API/configuration errors wait for a relevant change.
  Browser-level memory exhaustion is not a resource quota this boundary
  can enforce. The app remains one HTML file and supports hosted and local use.
- Workers start lazily. At most four instance Workers remain resident; the least recently used idle
  Worker is terminated before its slot is assigned a fresh realm. A resident Worker reuses only its
  own instance's compiled definition until its lifetime expires. Initialization, authoring and non-live previews/exports use
  temporary owners, retired when their operation ends. Accepted event deliveries also use temporary
  owners so hiding the browser page cannot retire an already accepted transaction. App-owned state survives eviction, save/load,
  and undo/redo; eviction does not rerun initialization. Live drawing/handle caches and execution
  owners are retired when their item leaves the corresponding drawing/execution scope or its script is replaced. Late
  replies cannot recreate removed entries or commit state from an old source generation.
- **Document resources:** image assets are limited to 16 MiB each and 64 MiB of distinct referenced
  images per sketch. Imports and transfers validate the destination budget before applying changes.
  Sketch names and library-entry names are limited to 120 characters. These are document/library
  limits; scripts still cannot return image children or access stored assets directly.
- Children cannot be nested smart shapes, tables, or asset-referencing images. Use the documented
  primitives above. Bézier controls (`c1`/`c2`) and polygon arcs (`arcTo`) are preserved.

## Library catalog and snapshots

The small shape popup keeps the **Working collection** heading and shows pinned shortcuts.
The optional expanded browser offers a **Source** filter for **Built-in** and **My shapes**,
search, and categories initially including Controls, Logic, Displays, Tools & time, Data, and Drawing.
**Collapse library** closes the browser; **Actions** in either pane opens the same **Library actions**
surface on desktop and mobile. Entries can be placed directly or pinned in the working collection
for later use. A filled pin means the entry is in that collection; an outline pin means it is
outside. The pin toggles membership, as do **Pin to working collection** / **Unpin from working collection**
in the details. Unpinning leaves its definition and placed objects unchanged. Built-ins offer
**Copy to My shapes**; personal entries offer **Duplicate**. Both create and pin an independent
personal definition. **Edit details** updates a
user entry's name, description, and search **Keywords** without changing its script.

Categories are named tags with multiple memberships per entry. Users can create, rename, and
remove categories and organize both built-in and personal entries. Removal only removes the
category and its memberships; shapes, pins, and other categories remain. Empty categories persist,
and entries without category tags appear as **Uncategorized**.
The entry's **Edit categories…** dialog can create a **New category…** while selecting memberships.

Library format 2 retains the self-contained `shapes` definition table and stable entry IDs.
An entry's `categoryTags` string array stores its category memberships; legacy single `category`
values migrate on import. Top-level `categories` records named tags, including empty categories,
and `builtinCategoryTags` stores organization overrides for built-in entries. Existing `tags`
remain search keywords, labelled **Keywords** in the UI. `workingCollection` records pinned entry IDs.
Built-in definitions supply their own `categoryTags` defaults, including multiple memberships.
An explicit `builtinCategoryTags` entry takes precedence, including an empty array. Restoring or
exporting unchanged defaults does not turn them into a personal override.
Library-entry IDs are separate from the UIDs of canvas items and component bindings. Renaming
or categorizing an entry therefore does not change a placed component's connections.
Older flat `{shapes:[...]}` libraries remain readable and initially include every imported
entry in the working collection. Export includes every user entry and the definitions needed by saved references,
including snapshots of kept built-ins; an import must not silently substitute a newer definition.
Library import replaces personal entries, pins, and category organization while retaining built-in
definitions. Export retains category registrations and built-in overrides as well as entries.

Individual entry transfer uses **Export shape…** in browser details or compact Actions and
**Import shape…** under Library actions. A `name.shape.json` file has the envelope
`{app:'SimpleCanvasShape', version:1, shape:<complete entry snapshot>}`. The snapshot retains
regular/smart/component items, grouped items and internal bindings, category memberships,
keywords, description, preview, and source metadata. Import adds an editable personal entry with
a fresh ID and unique name and pins it, including when the exported entry was built-in.
It does not replace the library. **Import library…** remains whole-library replacement, and
**Export library…** downloads the full library; exporting one shape does not clear its unexported status.
References to objects outside the transferred entry remain unresolved until reconnected after placement.
Individual shape imports use the same authoring guards and missing-script-preview consent as
library imports.

The catalog does not change the component API or placement lifecycle. Each placement clones its
definition, remaps internal component bindings, and initializes smart state and style. Existing
canvas instances and exported HTML retain their own definition snapshots. Personal library changes
and imports are saved automatically to IndexedDB, including full definitions/scripts, inert PNG
previews, Working collection pins, categories, and built-in category overrides. Built-in references
use canonical IDs and the installed definitions on restore; personal scripts are retained. The saved library
belongs to the current browser/profile and site/application URL path and survives reloads or closing
the tab. Sketch autosave and workspace files remain separate: workspace JSON saves all sketch tabs,
including placed smart-shape scripts, state, and bindings, but not the library.

A restored personal library takes precedence over the hosted `shapes-library.json` starter; a changed
starter cannot silently replace it. Loading an unchanged starter alone does not cache it as a personal
library. The first library edit or import enables persistence of that collection. Restoring stored
entries and thumbnails does not execute scripts; missing smart previews retain their existing
explicit-consent requirement.

The unexported-change indicator tracks the last library export, independently of browser saving.
Leaving the page warns only when browser saving is pending or failed. A visible failure banner
provides **Retry** and **Export library…** while preserving the current in-memory library. Exports
are portable backups and sharing files, not a requirement for reload persistence. Clearing site
data or ending a private browsing session may remove the browser copy, so retain an exported backup
for collections that must be kept.

Deployment switches continue to separate authoring from use. `shapeLibrary:false` skips the library,
its starter, and its browser storage. `shapeLibraryManagement:false` disables catalog changes and
pins and bypasses personal storage, keeping the fixed deployment starter in use. Adding smart definitions to the working
collection or copying them into My shapes requires `smartShapeAuthoring`, and API v2 definitions also
require `smartComponents`. The browser and direct placement remain available when management or
authoring is disabled. Those switches do not disable existing controls, connections, or HTML
playback. They do not grant network access to component scripts.

## Library previews

Library exports include a 128×128 PNG thumbnail and a versioned fingerprint of its source items.
The fingerprint detects stale previews; it does not certify a library's source or safety. PNG
headers, dimensions, and size are checked on import, and decoding failures become missing previews.
Ordinary shape previews are generated automatically. A missing imported smart-shape preview displays a
placeholder until you approve script execution. Opening an automatically loaded library asks once;
declining still lets you use the library. **Generate missing previews…** offers the choice again.
Automatic preview creation or recovery does not mark the library as having unexported changes.
Newly authored or replaced entries regenerate previews. Personal browser saves and library exports
retain generated PNGs, so restored/imported entries can display them without running scripts. Placing/editing a smart shape still runs
its hooks inside the sandbox. Built-in previews ship with the app. Renaming, categorizing,
tagging, or keeping an entry does not require a new picture; changing its drawing or script does.

A selection can combine ordinary shapes and components. If a component's input source is outside
the selection, its copied binding stays unresolved and the preview draws its unavailable state
alongside the other shapes. A component without `unavailableChildren()` uses the host status card;
missing inputs alone do not prevent thumbnail generation. Drawing-hook failures still report an error.

Thumbnails and cropped SVG/PNG exports include painted children outside the container, including
outside labels and thick outlines. The editable container and rotation pivots keep their geometry.

- [Text label](examples/text-label.js): string `value` input (default empty) and matching `value` output.
  It wraps and truncates the visible preview while preserving the complete output; incoming content
  renders literally, including leading `---` and HTML-looking text. It starts as plain text with
  no frame; normal `strokeOn`, `color`, `size`, and `dash` styling can add an outline, and `fill`
  controls its background. Boolean `showName` and `showHints` (both false) optionally add its instance caption
  and empty/truncated-text guidance. Input errors remain visible.
- [Memo](examples/memo.js): string `content`/`line` inputs (default empty), Boolean
  `set`/`append`/`clear` and `showScrollbar` inputs (default false), and stored `text`/numeric `lineCount` outputs.
  Its signal commands require a false-to-true transition. A high input at startup establishes a baseline;
  it does not change saved contents. Simultaneous rising edges prioritize Clear, then Set, then Append.
  Set replaces the buffer; Append inserts a separating newline only after an existing logical line;
  Clear produces empty text and zero lines. Appending an empty string creates a blank line, so empty
  `text` may have `lineCount:1`. CRLF and lone CR normalize to LF. `maxLines` is 1–1,000 (default 100)
  and `maxLength` is 1–2,000 UTF-16 units (default 2,000). Updates exceeding either limit or the 4,000-character
  serialized-state budget retain the complete previous buffer and show a notice.
  Optional **Log mode** (`logMode`, false) changes Append: exceeding Maximum lines drops the oldest
  logical lines and keeps the newest ones, including when an incoming block alone exceeds the limit.
  Character and storage limits apply to that retained text; if it still does not fit, the whole
  append is rejected without losing existing content. Set keeps its normal limit checks.
  Enabling Log mode or lowering a limit alone never truncates stored content.
  The preview shows the latest wrapped lines, and the full retained string
  remains available from `text`. The compact text area uses the available height; optional Boolean
  `showCounts` and `showHints` (both false) add line/visible-character counts and empty/truncated-text
  guidance. The character count uses grapheme segmentation, separately from the storage limit;
  an older browser without `Intl.Segmenter` explicitly labels a UTF-16-unit count instead.
  Rejected-update notices and input errors stay visible when those options are off.
  The **Show scrollbar** control input (`showScrollbar`, false) adds a vertical scrollbar when
  the wrapped text overflows. Set its literal in Edit or connect a Boolean output to show and hide it.
  Hiding it preserves the reading position for when it is shown again.
  In interactive mode, drag its thumb or click the track to read earlier text; the same controls work
  in HTML exports. Appends follow the latest text while at the bottom and preserve the reading
  position after scrolling up. Log eviction preserves the text being read until it leaves the log,
  then starts at the oldest retained line. Scrolling back to the bottom restores following; successful Set and
  Clear commands reset it. Scrolling only changes the view, never the stored text, outputs, or events.
  Text still wraps, so no horizontal scrollbar is needed.
  Hybrid `content` and `line` ports accept captured strings to set or append immediately.
  Hybrid `clear` accepts commands; values-only mode retains conventional trigger sampling.
  These paths use the same bounded operations. Convert numbers through Number to text first.
  Connecting a Line event plus a separate Append trigger requests two operations.
- [Seven-segment display](examples/seven-segment-display.js): authoring Input mode selects
  `number` (default) or `segments`. Number mode requires integer `value` in 0–9; segments mode
  exposes boolean `a`…`g` inputs, all default false. Both modes include boolean `decimalPoint`
  (false) and `enable` (true). Fixed boolean outputs `a`…`g` and `decimalPoint` describe the visible
  segments after enable is applied; disabling sets every output false. The drawing uses the
  conventional segment positions, the instance caption, dim off segments, and amber unavailable
  segments. Mode changes alter input declarations, not output names or types.
- [LED matrix (8×8)](examples/led-matrix.js): authoring Input mode selects `boolean` (default),
  `rows`, or `columns`. Boolean mode exposes `row0`…`row7` and `col0`…`col7`, all default false;
  each LED is the AND of its row and column, with every active crossing shown. Row 0 is topmost
  and column 0 leftmost. Rows mode exposes numeric `r0`…`r7` (default 0), each an integer in
  0–255; `r0` is the top row, bit 7 (128) is leftmost, and bit 0 (1) rightmost. A row byte of 129 lights
  both ends, 255 lights every LED, and 0 lights none. Columns mode exposes numeric `c0`…`c7`
  (default 0), with the same 0–255 integer range; `c0` is leftmost, bit 7 is topmost, and bit 0
  bottommost. All modes include boolean `enable` (default true) and fixed numeric outputs
  `r0`…`r7` and `c0`…`c7`, reporting the visible row and column bytes simultaneously using
  those same bit orders. Disabling publishes sixteen zeros. Mode-specific input names keep
  Boolean ports distinct from numeric row/column bytes. The named display computes directly
  from current inputs, with no scan cycle or persistent frame buffer. In Wiring, Boolean and
  numeric column inputs explicitly use `side:'top'`, and column-byte outputs use `side:'bottom'`;
  row inputs stay left and row-byte outputs right. These column ports remain data ports.
  `enable` declares `role:'control'` and appears on top in all modes.
- [Compare](examples/compare.js): two live numeric operands and six selectable comparison operators.
- [Inverter (×−1)](examples/number-inverter.js): numeric negation, distinct from boolean NOT.
- [Math](examples/math.js): two numeric inputs and selectable arithmetic, minimum, or maximum.
- [Clamp](examples/clamp.js): limit a number to inclusive `min`/`max` bounds.
- [Range mapper](examples/range-map.js): linear input/output range conversion, clamped by default;
  increasing input bounds and reversed output bounds are supported.
- [Number function](examples/number-function.js): absolute value, nearest integer, floor, or ceiling.
  Nearest-integer rounding uses JavaScript's `Math.round` rule: half values toward positive infinity.
- [Selector (number)](examples/selector-number.js) and
  [Selector (Boolean)](examples/selector-boolean.js): false chooses A, true chooses B; both inputs
  must be available. The graph eagerly resolves every declared input; selection never suspends
  the unselected source.
- [Stepped switch (number)](examples/stepped-selector-number.js) and
  [Stepped switch (Boolean)](examples/stepped-selector-boolean.js): `in0`…`in(N−1)` route to `value`.
  Unbound channels default to 0/false; all declared channels still require valid values.
- [Stepped distributor (number)](examples/stepped-distributor-number.js) and
  [Stepped distributor (Boolean)](examples/stepped-distributor-boolean.js): required `value` routes
  to one of `out0`…`out(N−1)`; inactive outputs are 0/false.
  Both stepped families have a Channels setting (2–16, initially 4), boolean `pulse` and `reset`
  inputs, and numeric `position` output. Every rising pulse advances 0…N−1 and wraps; held reset
  selects 0 and tracks the pulse. Saved position survives restoration without a phantom step.
  Changing Channels resets position to 0 and re-primes, using durable `configuredChannels` to
  detect the change even if transient memory was cleared.
- [Shift register (Boolean)](examples/shift-register-boolean.js) and
  [Shift register (number)](examples/shift-register-number.js): a Stages setting (1–16, initially
  4), required typed `value`, and boolean `pulse`/`reset` inputs (both default false). Each rising
  pulse shifts one snapshot of the old cells: data enters `q0`, old `q0` enters `q1`, and so on.
  Dynamic outputs `q0`…`q(N−1)` expose every cell; `value` aliases current `q(N−1)`. `shiftedOut` captures
  old `q(N−1)` on that edge and holds it between edges. For a shared-pulse cascade, wire `value`
  (or `q(N−1)`) to the next register's `value` and share pulse/reset. Every register samples the same
  pre-edge snapshot. Numbers must be finite; they need not be integers.
  Reset clears cells and `shiftedOut` to false/0. Held reset tracks pulse so release-high does
  not shift; manual Reset works in editor and reader. Changing Stages clears storage and
  re-primes pulse detection. Reload/copy/undo preserve storage and start fresh observation;
  library placement initializes empty cells. Each cell is drawn individually alongside the
  instance name, with optional indicators. Stored-output publication supports feedback connections.
- [SR latch](examples/sr-latch.js): Boolean `set`/`reset` controls and unknown-aware `q`, `notQ`,
  and `value` outputs. Starts X; a definite command sets/clears the stored bit, neither holds it,
  and simultaneous set/reset produces X. Cross-connected NOR/NAND gates are also supported.
- [D latch](examples/d-latch.js): unknown-aware `d`, Boolean `enable`/`reset`; follows data while
  enabled, otherwise holds. Reset clears Q. Outputs are `q`, `notQ`, and `value`.
- [D flip-flop](examples/d-flip-flop.js): captures unknown-aware `d` on a rising Boolean `clock`;
  `reset` wins and clears Q. An initial/held-high clock does not invent another edge.
- [Register (Boolean)](examples/register-boolean.js) and
  [Register (number)](examples/register-number.js): typed `value`, `pulse`, `enable`, and `reset`;
  rising pulse captures when enabled and reset clears. Boolean starts X, number starts zero.
- [Ring counter](examples/ring-counter.js): 1–16 Stages, rising `clock`, `enable`, and `reset`;
  outputs `q0`…`q(N−1)` and zero-based `position`. Reset selects q0; one bit circulates every N clocks.
- [Johnson counter](examples/johnson-counter.js): same settings/controls, starts all false;
  advances an inverted-tail sequence over 2N positions. Outputs `q0`…`q(N−1)`, `value` (q(N−1)), and `position`.
- [Decoded decade counter](examples/decade-counter.js): 4017-style logical model with `clock`,
  `enable`, `reset`, ten outputs `q0`…`q9`, `position`, and `carry` high for positions 0–4.
  Reset selects q0. All clocked storage samples together before any state is published.
- [Trigger](examples/trigger.js): a pushbutton producing a 100 ms boolean pulse per click;
  queued presses have a 10 ms low gap. Transient observation prevents replay after restoration.
- [Live clock](examples/live-clock.js): string `timezone` input, default `local`, also accepting
  IANA names such as `Europe/Berlin`, `America/New_York`, and `UTC`. Invalid zones make the
  component visibly unavailable. Five fixed outputs expose boolean `second`, `minute`, `hour`,
  and `halfDay` pulses, plus string `time` in `HH:mm:ss` format. Each observed consecutive wall
  second produces a nominal 100 ms `second` pulse; `minute` also pulses at second 00, `hour` at
  minute/second 00, and `halfDay` at noon/midnight in the selected zone. All hands, the readout,
  and outputs use one per-second transition snapshot. Initial/reloaded instances and timezone
  changes prime all pulses false; missed boundaries and clock jumps are not replayed. Active-tab
  updates realign to wall time after inactivity, independently of paused interval timing.
  Static exports/inspection use pure `compute` on the last settled state; HTML continues live.
  The instance caption and optional LEDs labelled 1s, 1m, 1h, and 12h identify the clock and its
  pulses. Connect `second` to Counter's `value`; the string `time` is incompatible with the
  existing numeric Value label.
- [Stopwatch](examples/stopwatch.js): boolean `run` and `reset` inputs and one numeric `elapsed`
  output in seconds, including milliseconds. A change to run=true starts/resumes; a change to
  run=false pauses and stores the accumulated duration. `elapsed` is the last paused total,
  held unchanged while running; reset clears it to zero and stops. Manual Start/Pause and Reset
  remain available in editor and reader. The latest manual action persists until `run` changes,
  while held reset overrides both. The display uses `HH:mm:ss.mmm` with 100 ms refreshes while
  running, derived from wall timestamps so time continues across tabs, backgrounding, and reload.
  There is no live elapsed output, tick transition, or periodic autosave. `compute` reads only
  durable `elapsedMs`; command transitions and accepted manual actions update timing state.
  Fresh placement starts stopped and includes the new ports; existing instances retain their
  embedded scripts. Connect `elapsed` to a numeric Value label for a published stopped result.
- [Timer](examples/timer.js): the existing red-wedge template and built-in entry now use API v2.
  Authoring settings select Unit (`minutes` by default, or `seconds`) and Starting duration
  (0–60, default 45). The dial hand also edits starting duration; top means 0, with 60 entered
  through Edit. Unit/duration edits refill and stop. Boolean `run`/`reset` inputs default false:
  run edges start/resume or pause, and held reset refills/stops and overrides manual controls.
  Manual Start/Pause and Reset remain available; the latest action persists until a run edge,
  and reset release alone never starts. Zero stops the timer and holds boolean `reached` true.
  Explicit Start or a new run rising edge at zero refills/restarts once; held run never repeats.
  Boolean `tick` pulses for nominally 100 ms at each observed whole configured unit elapsed.
  Wall timestamps preserve running time across hidden tabs and reloads; missed boundaries are
  never replayed, fresh observation clears stale tick state, and hidden expiry sets reached on
  return. Transitions settle the dial roughly once per second; pure compute/rendering and static
  exports retain that snapshot. The instance caption and optional LEDs accompany the dial.
- [Pulse generator](examples/pulse-generator.js): boolean output with period `seconds` (0.02–3,600),
  high time `width`, and `enable`. High and low time are each at least 0.01 seconds. Starts low,
  first pulse after a full period; disable or timing changes restart low. Late wakes advance one
  phase from the wake time without a burst of missed periods.
- [Edge to pulse](examples/edge-pulse.js): rising, falling, or either observed edge produces a pulse
  of `seconds` (0.01–3,600). Initial level is primed without a pulse. Up to 64 waiting pulses have
  a minimum 10 ms low gap; reconfiguration/restoration discards pending pulses and re-primes.
- [Delay](examples/delay.js): preserve boolean transitions with a configured delay in seconds.
- [Counter](examples/counter.js): boolean `value` and `reset`; string `direction` with options
  `up`/`down` (default `up`); numeric `start` and `threshold` (both default 3, nonnegative safe
  integers). Up starts/resets at zero, increments per rising edge, and publishes `reached` when
  `count >= threshold`. Down starts/resets at start, decrements per rising edge, clamps at zero,
  and publishes `reached` when `count === 0`; threshold does not determine down-mode completion.
  Changing direction, or start while down, restarts and re-primes without counting that evaluation.
  Threshold changes and start changes while up keep the current count. Reload/copy/undo preserve
  the saved count and prime edge memory without replay. Held reset tracks the input; release
  during high does not count. Manual Reset uses the same baseline in editor and HTML. The drawing
  shows the direction arrow, an up-mode ≥ threshold or down-mode zero target, and the down start.

  configured duration, with fixed typed ports.
- [Tri-state buffer](examples/tri-state-buffer.js): boolean data and active-high enable; outputs

## Asking an AI to write one for you

Paste this file (or its relevant sections) as context, then describe the shape you want,
including: what it should look like, what state (if any) it should carry, what
should be draggable, and whether it should follow the toolbar's own Fill/Stroke colors or use
fixed colors of its own. Include whether it needs live updates or interactive HTML controls.
Ask explicitly for the output to be **one script**, in the exact object
literal form these templates use, with synchronous hooks. The result should paste directly into
the Script field without instructions, a diff, or a `<script>` tag.
