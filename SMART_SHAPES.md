# Smart Shapes — scripting reference

A **smart shape** is a Shape Library item whose visible content is generated by a small
JavaScript script you write, instead of being fixed geometry. The container itself never
draws a box — it's a plain, styleable item (Fill/Stroke/Stroke-width/Text-color/Font all work
on it normally), and your script decides which of the shapes it generates ("children") use
that styling. Built-in examples: an analog clock, a block arrow, a bar chart, a manually set countdown
dial, live clock, stopwatch, and ruler.

This file is a reference for **writing** a smart shape's script — by hand, or by handing this
file to an AI assistant along with a description of what you want. It does not cover using the
app as an end user; see [README.md](README.md) for that.

## Quick start

1. Open the **Shape Library** panel → **Manage** → **Add smart shape…**.
2. Pick a starting point from the **Template** dropdown (Clock / Live clock / Stopwatch / Ruler / Number control / Gauge / Arrow / Arc / Timer / Chart /
   Minimal / Blank), or just start typing your own script over it.
3. Give it a name and click **Create**. The new shape appears in the library, ready to place.
4. On the canvas, double-click a placed smart shape to enter its **edit mode** (solid blue
   corner markers) — drag its handles there to change its state. Double-click again, or click
   outside it, to leave.

For a grouped smart shape, the first double-click enters group editing; double-click the
member again to enter its smart-shape controls.

Built-in catalog entries can be placed directly from the expanded library browser. To customize
one, use **Copy to mine** first; built-in definitions are read-only. Pinning an entry adds a
reference to the quick popup's working collection and does not create an editable copy.

To edit your library definition, choose **Manage → Edit** beside its name, or **Edit source…**
in its browser details (also available for unpinned entries). The authoring
dialog opens with its existing name and script; **Save changes** updates that entry and regenerates
its PNG preview. The definition's saved state, dimensions, and appearance are preserved.
`initState()` and `initStyle()` run afresh when placing each instance; saved values supply defaults
for omitted hooks or style fields. Existing canvas instances keep their own scripts and state.
If an entry contains multiple smart shapes, each has a numbered **Edit 1**, **Edit 2**, … action. Export
the library to retain your changes.

## A complete worked example

This is an **adaptation of the Minimal template**: a circle with one draggable radius handle.
Its shared `_layout()` helper clamps the displayed radius whenever the container is resized,
and keeps the drawing, handle, and hit test aligned. The picker’s Minimal template uses the
stored radius directly and only clamps it during a handle drag.

Paste this entire expression into the Script field:

```js
({
  initState(){ return { r: 45 }; },

  // Keep the circle's geometry within the box, even after a resize.
  _layout(state, w, h){
    const maxR = Math.min(Math.abs(w), Math.abs(h)) / 2;
    const minR = Math.min(5, maxR); // Tiny boxes need a radius smaller than 5px.
    const requested = Number.isFinite(state.r) ? state.r : 45;
    const r = Math.max(minR, Math.min(maxR, requested));
    return { cx:w/2, cy:h/2, r, minR, maxR };
  },

  children(state, style, w, h){
    const {cx, cy, r} = this._layout(state, w, h);
    return [{
      type:'ellipse', x:cx-r, y:cy-r, w:r*2, h:r*2,
      color:style.color, size:style.size, strokeOn:style.strokeOn,
      fill:style.fill, fillColor:style.fillColor,
    }];
  },

  handles(state, w, h){
    const {cx, cy, r} = this._layout(state, w, h);
    return [{id:'r', x:cx+r, y:cy}];
  },

  hitEdit(state, lx, ly, w, h){
    const {cx, cy, r} = this._layout(state, w, h);
    return Math.hypot(lx-(cx+r), ly-cy) < 12 ? 'r' : null;
  },

  dragEdit(state, handle, lx, ly, w, h){
    if(handle !== 'r') return state;
    const {cx, cy, minR, maxR} = this._layout(state, w, h);
    const r = Math.max(minR, Math.min(maxR, Math.hypot(lx-cx, ly-cy)));
    return {...state, r};
  },
})
```

Resizing changes the displayed radius without changing saved state. Enlarging the box can restore
the stored radius; dragging the handle saves a new radius. Stroke thickness and the app’s handle
markers can extend beyond the circle’s geometry. See [Bounds](#your-shape-is-responsible-for-its-own-bounds)
for shapes that need all painted content inside the box.

## The script object

The **script** field takes a single JavaScript **expression** — not a series of statements —
that evaluates to an object, conventionally written as an object literal:
`({ children(state, style, w, h){ ... }, ... })`.
It's compiled with `new Function('"use strict";return (' + yourScript + ');')()`, so:

- Both `{ ... }` and `({ ... })` work: the compiler wraps your expression in parentheses.
  Templates use `({ ... })` for clarity.
- No `import`/`export`, no top-level `let`/`const`/`function` declarations outside the object
  expression. Helper functions are fine as **methods** on the object (see `_layout()` in the Timer
  template) — the app always calls your hooks as `def.hookName(...)`, so `this` inside a method
  correctly refers to your own script object.
- **Hooks must return synchronously.** Do not declare hooks `async` or return promises: the
  runtime serializes their immediate return values and does not await them. Use `refreshMs()`
  for periodic updates.
- The only thing your script ever gets handed is plain, already-computed data (state, style,
  width, height, pointer coordinates) — never `ctx`, `document`, or any other app internal.
- Each placed instance has an independent JavaScript environment, including copies using identical
  source. Methods may share helpers through `this`, but globals and object-local mutations are
  disposable caches. Keep durable values in the returned state; idle Workers can be evicted.

Only `children()` is required for an unversioned smart shape. Optional hooks initialize state or
appearance, define interactions, request live updates, or configure behavior in an HTML export.
The table below describes the original contract, which remains supported. Components explicitly
using `apiVersion:2` extend it as described under [Connected components](#connected-components-api-v2).

| Hook | Called | Arguments | Returns |
|---|---|---|---|
| `initState()` | When creating a definition for its preview, and afresh for each placement | — | a plain, JSON-safe state object |
| `initStyle()` | After `initState()`, when creating a definition and for each placement | — | a partial style/size override (see below) |
| `children(state, style, w, h, editing)` | When inputs change or a refresh is due | current state, resolved style, container width/height, `true` in editor edit mode and in interactive HTML | array of child shape descriptors |
| `refreshMs(state)` | After generating live children, in the same sandbox call | current state | desired refresh interval in milliseconds; `0`, `null`, or `undefined` stops automatic refresh |
| `exportBehavior` or `exportBehavior(state)` | Interactive HTML, after state or size changes and on refresh | current state for the function form | `{move, rotate, resizeWidth, resizeHeight}` booleans, all default `false` |
| `handles(state, w, h, style)` | In editor edit mode and interactive HTML | state, width/height, resolved style | array of `{id, x, y, kind?, editorOnly?}` |
| `hitEdit(state, lx, ly, w, h, style)` | On press in editor edit mode or interactive HTML | state, press position (**local** coords, see below), width/height, resolved style | a handle `id`, or `null`/`undefined` if the press missed every handle |
| `dragEdit(state, handle, lx, ly, w, h, style)` | While dragging a handle (continuously), and once on a zero-movement click | state, the `id` returned by `hitEdit`, current pointer position (local coords), width/height, resolved style | the **new** state object |

State is never mutated in place — `dragEdit` returns a fresh object (`{...state, ...}` is the
usual pattern). A completed click or drag creates one undo entry if its validated state differs.
Quick clicks are processed in input order, including when release precedes the hook reply.
A following nudge or style change keeps a released handle action and its own undo entry. An
unreleased press is cancelled when another edit begins. Escape, undo, tool changes, and document
replacement cancel pending actions. Smart editing tracks one pointer at a time; additional fingers
cannot release or cancel the active finger's press.

Every hook reply is validated before rendering, export, preview generation, or state updates.
`children()` returning `[]` is valid. Invalid individual children are skipped with an error.
If the whole response is rejected, an unversioned shape's live refresh keeps the last valid drawing,
or stays empty if none exists, and reports an error. API v2 components show an unavailable state.
Invalid state updates keep the previous state.
Missing optional hooks return no handles or make no state change.
On static export failure, a cached drawing is used only if its script, state, style, size, and non-editing
mode all match. Otherwise that unversioned smart shape is omitted. Components show an unavailable
drawing or status card; marked authoring controls never enter an exported drawing.

### `initState()`

Returns the state your shape starts with. Called once per placement; `w`/`h` aren't decided
yet at this point, so state can't depend on them (the Minimal template's radius, for example, is
a plain tuned literal, not a fraction of the box).

```js
initState(){ return { value: -45 }; }
```

### `initStyle()` (optional)

Lets a script override the initial style/size of each new placement. Return a partial object;
omitted fields keep the library definition's saved values. When authoring a new definition, those
base values come from the defaults below. Recognized fields, each individually validated (an
unknown/wrong-typed field is just ignored, not rejected):

| Field | Accepted value / clamp |
|---|---|
| `color`, `fillColor`, `textColor` | CSS hex: `#RGB`, `#RGBA`, `#RRGGBB`, or `#RRGGBBAA`; named colors and `rgb()` are not accepted |
| `fill`, `strokeOn` | boolean |
| `size` | 1–60 |
| `fontFamily` | `sans`, `serif`, `mono`, or `cursive` |
| `fontSize` | 6–400, rounded |
| `w`, `h` | 20–2000, rounded |

Every field is still fully adjustable afterward via the ordinary toolbar/resize handles —
`initStyle()` only ever affects the single moment of creation. Example (the Chart template):

```js
initStyle(){ return { fontSize: 12, strokeOn: false, w: 240, h: 160 }; }
```

Without an `initStyle()`, a newly authored definition starts black, unfilled, stroke on, at 180×180,
using the toolbar's current stroke width, font, fill color, and text color. Placements then inherit
that definition's saved style and size.

### `children(state, style, w, h, editing)` (required)

Returns an array of plain **child shape descriptors** — the actual visible content. These are
**never stored in the scene**; they're cached for live rendering and refreshed when script,
state, style, size, or edit mode changes, or when an optional refresh interval expires. Exports
request fresh children. See [Child descriptors](#child-descriptors) below for their shape.

`editing` is `true` only for the one instance currently in interactive edit mode (by identity,
not type) — `false`/`undefined` otherwise, including during PNG/SVG export and the initial HTML
snapshot. Interactive HTML calls it with `true` so operational controls stay visible. Mark
authoring-only child descriptors **and their handles** with `editorOnly:true` to omit them from
all exported drawings and disable their actions in HTML.

### `refreshMs(state)` (optional)

Requests periodic regeneration of this instance's children and edit handles. Existing scripts that
omit this hook keep their ordinary cache behavior. Return a positive, finite number of milliseconds;
the app clamps it to **100–60,000 ms**. Return `0`, `null`, or `undefined` to stop refreshing, for
example when a stopwatch is paused. Invalid values disable refresh and report an error without
discarding valid children. A throwing or unresponsive hook uses the normal sandbox failure/backoff
path, retaining the last valid drawing.

```js
refreshMs(state){ return state.startedAt == null ? 0 : 100; },
```

See [Live updates and exports](#live-updates-and-exports) for timer lifecycle, timestamp-based
state, and the difference between static snapshots and interactive HTML.

### `exportBehavior` or `exportBehavior(state)` (optional)

An object, or a synchronous function returning one, with optional boolean flags `move`, `rotate`,
`resizeWidth`, and `resizeHeight`. All flags default to `false`. The function receives a copy of
state; modifying it does not update the saved instance. Interactive HTML reads these permissions
after state or size changes and on refresh. They do not change editing behavior in SimpleCanvas.
See [HTML export behavior](#html-export-behavior) for examples and creator-only permission controls.

### `handles(state, w, h, style)` (optional)

Returns `[{id, x, y, kind?, editorOnly?}, ...]` — one entry per point `hitEdit`/`dragEdit` can grab, in the
same **local** coordinate frame as `children()` (container's own top-left as origin).
Every interactive ID must be declared here; a script with no handles cannot receive a valid
handle action. The app draws a small solid-blue dot for each `'drag'` handle. It draws no dot
for `'click'` or `'number'` handles: draw their buttons or labels yourself in `children()`. The four corner
markers indicate edit mode and are not interactive handles.
IDs are unique, nonempty strings of at most 64 characters. `hitEdit()` must return one of these
IDs or `null`/`undefined`. A response can contain at most 128 handles. An optional boolean `editorOnly`
marks handles that are usable only in the editor; interactive HTML never runs them.

`kind` is optional, defaulting to `'drag'` (a continuous drag point, like a resize handle).
Mark it `'click'` for a discrete, one-shot action — an add/delete button, a toggle — rather than
something meant to be dragged around:

```js
handles(state, w, h){
  return [
    { id:'hand', x: cx + Math.sin(a)*r, y: cy - Math.cos(a)*r },   // 'drag' (default)
    { id:'add', x: addBtnX, y: addBtnY, kind:'click' },
  ];
}
```

Without `kind:'click'`, small pointer movements during a press can call `dragEdit` repeatedly
and repeat the action (for example, inserting several new bars from a single tap on "+").
`kind:'click'` makes the app resolve it exactly once, from the original press position, on release.

`kind:'number'` opens a host-owned number-entry dialog on release. Supply a finite numeric `value`
and optional finite `min`, `max`, and positive `step` metadata; `min` must not exceed `max`.
The host validates the entry and, on acceptance, calls `dragEdit` once with the accepted **number
in `lx`**, rather than a pointer coordinate. `ly` is zero; identify this case
by the handle ID. Cancellation leaves state unchanged. Keep domain-specific snapping and validation
in the script's `dragEdit`/`compute` hooks as well. This handle works in editor edit mode and offline
HTML; `editorOnly:true` can restrict it to authoring.

```js
{ id:'entry', x:w/2, y:h/3, kind:'number', value:state.value,
  min:-20, max:40, step:0.25 }
```

`kind:'text'` opens the same dialog with a single-line text field instead. Supply the current
text as a string `value` (at most 2,000 characters) and an optional `label` (at most 100
characters, default **Text**) for the field. On acceptance the host calls `dragEdit` once with
the accepted **string in `lx`** (possibly empty); `ly` is zero. Cancellation leaves state
unchanged. The script must validate and bound the text itself, and keep the resulting state within
the 4,000-character limit. Like `kind:'number'`, it works in editor edit mode and offline HTML.

Add a local `rect` (`{x, y, w, h}`, same frame as `children()`) to edit **in place** instead: the
host lays a single-line field exactly over that rectangle, rotated with the shape. Enter applies and
continues in the text handle directly below, Shift+Enter above, Tab to the right, Shift+Tab to the
left (neighbours are found from the handles' rects); clicking elsewhere applies and stops, Escape
discards the field being typed. Every applied field calls `dragEdit` once and is its own undo step.
An optional `fontSize` (in the shape's units) sets the field's text size, so it matches the drawn
text; without it the size follows the rect's height. An optional `align` (`'left'` default, `'center'`, `'right'`) aligns the typed text.
[Spreadsheet](examples/spreadsheet.js) uses one in-place text handle per cell for its formulas.

```js
{ id:'B6', x:cellX+cellW/2, y:cellY+cellH/2, kind:'text', value:state.cells.B6 || '',
  label:'Cell B6', rect:{x:cellX, y:cellY, w:cellW, h:cellH} }
```

### `hitEdit(state, lx, ly, w, h, style)` (optional, needed if you have handles)

Given a press position, return the `id` of the handle it landed on (within your own chosen hit
radius), or `null`/`undefined` if it missed everything. Other falsy values (`false`, `0`, `''`)
are invalid. **Coordinates are already local** — `(0,0)` is the container's own top-left, same
frame as `children()`, **not** the same convention `toLocal`
uses elsewhere in the app (which only undoes rotation, not translation) — the app subtracts
`it.x`/`it.y` for you before calling this.

```js
hitEdit(state, lx, ly, w, h){
  return Math.hypot(lx - handX, ly - handY) < 14 ? 'hand' : null;
}
```

### `dragEdit(state, handle, lx, ly, w, h, style)` (optional, needed if you have handles)

Given the `id` `hitEdit` returned and the current (local) pointer position, return the new
state. Called continuously while dragging a `'drag'`-kind handle, or exactly once (from the
original press position) for a `'click'`-kind handle or a zero-movement click. A `'number'` handle
uses the accepted numeric entry as `lx`, as described above.

The [worked example](#a-complete-worked-example) uses the same layout helper in `dragEdit()`
and the drawing hooks to keep its radius within the current box.

Every completed click or drag creates one undo step only if its final validated state differs
from the state at the start of the gesture (compared via `JSON.stringify`). A drag that returns
to its starting value does not create a no-op undo entry.

## Connected components (API v2)

A component is a smart shape whose script declares `apiVersion:2`. It exchanges scalar values
through host-resolved ports. Scripts receive data and return results; they cannot inspect siblings
or mutate another component. Start from the **Number control** or **Gauge** templates, or open
[the connected example](examples/connected-components.json) as a sketch.

```js
({
  apiVersion: 2,
  inputs: { value: { type: 'number', default: 0 } },
  outputs: { percentage: { type: 'number' } },
  initState(){ return {}; },
  compute(inputs, state){
    return { percentage: Math.max(0, Math.min(100, inputs.value)) };
  },
  children(state, style, w, h, editing, io){
    return [{type:'text', x:0, y:0, w, h,
      text:io.outputs.percentage+'%', textColor:style.textColor,
      font:style.font, strokeOn:false, fill:false}];
  },
})
```

`inputs` and `outputs` are maps of port names to `{type}` descriptors, or synchronous pure
`inputs(state)` / `outputs(state)` functions returning such maps from the current saved state.
This supports author-configured port counts without making port layout depend on live inputs.
Types are `number`,
`string`, and `boolean`; input descriptors may also include a matching `default`. A string input
may declare `options`, an array of 1–32 distinct, nonempty strings of at most 2,000 characters each.
Its default, if present, must be one of those options. **Inputs…** presents these values as a
dropdown; literal and connected values must match an option. Options apply only to string inputs.
Names start
with an ASCII letter and contain up to 64 letters, digits, or underscores. Reserved object keys
are rejected. Each side supports at most 32 ports. Numbers must be finite; strings are limited
to 2,000 characters. Each port map and computed output object is limited to 32,000 serialized
characters. A sketch supports at most 128 connected components.
Saved bindings and literal-input maps are each limited to 16,000 serialized characters;
the input dialog rejects changes that would exceed the save/load contract.

An optional `settings` map declares authoring configuration stored in ordinary instance state.
Each descriptor uses a scalar `type` and a required matching `default`; string settings may use
`options`. Numeric settings may add finite `min`, `max`, and positive `step`, with the step grid
anchored at `min` (or zero when omitted). A `label` of at most 100 characters supplies the visible
field name. At most 16 settings are allowed. The host edits and validates these fields in
**Inputs…**. Settings are not ports and cannot be bound to live sources.

```js
settings: { channels: { type:'number', default:4, min:2, max:16, step:1, label:'Channels' } },
inputs(state) {
  const ports = {};
  for (let i=1; i<=state.channels; i++) ports['in'+i] = {type:'number', default:0};
  return ports;
},
```

Initialize setting fields in `initState()` and keep port-defining settings unchanged in
`transition` and interactive reader hooks. Dynamic declarations must be deterministic from state;
they do not authorize mutation during capability inspection. Changing Channels rebuilds the
available ports in the authoring dialog. Bindings to a removed output become unavailable until
reconnected. Runtime-only position changes must not change the declared channel set.

`compute(inputs, state)` synchronously returns an object containing exactly the declared outputs
with matching types. It is required when outputs are declared. Treat it as a pure computation:
no state changes, actions, or dependence on definition-local mutations. The host evaluates the
graph asynchronously in dependency order when component state, scripts, or wiring change, and
discards superseded results. Size, style, and presentation refreshes do not recompute values.
`refreshMs` remains a drawing refresh; it does not turn a clock into a connected time source.

The optional API v2 `transition(inputs, state, memory, {now})` hook adds explicit stateful,
timed signals. It synchronously returns `{state, memory, nextWakeAt}`. `state` is the next durable
instance state; `memory` is a transient JSON object, isolated per instance and never saved or
exported. Both use the existing 4,000-character state limit and JSON validation. `nextWakeAt`
is an absolute nonnegative timestamp in active-document milliseconds, or `null`/omitted to stop
waking. The host provides monotonic `now`, owns the timer, and clamps wake delays to at least 10 ms.
It invokes `transition` before pure `compute`, so downstream components see the staged next state.
A transition may also run when an input changes before its deadline: inspect `memory` and `now`
to decide whether to sample. Do not depend on hook-call counts, Worker-local state, or script timers.

Only a current evaluation commits state/memory, and an error in one branch does not stop independent
branches. Accepted smart-control changes and timed wakes settle in order. Unfinished drag previews
never consume edges; their committed final value does. Missing inputs, Z, and failed transition or
compute calls clear that instance's transient observation. Replacement objects, changed scripts,
and changed bindings re-prime it; changing a literal input is an ordinary input transition.

Each document retains its own clock and transient memory across tab switches. Inactive/hidden
documents pause, as does the editor's Inputs dialog; the same instances resume on return.
Saved JSON includes current durable counts/outputs, but reopening, duplicating, or undoing starts
new transient observation. The built-in Counter preserves its saved count in either direction
and seeds an already-high input without counting it. Its held reset follows the input while
holding the mode's baseline, so releasing reset during high does not add or subtract an edge.
Shift registers likewise preserve their durable cells and last `shiftedOut` value while
re-priming pulse observation. Their `shiftedOut` port captures the old final cell on an accepted
rising edge. Connect that port to the next register's data input when sharing a pulse: ordinary
stage outputs already contain the producer's staged next state when the consumer evaluates.
This supports an acyclic cascade; it does not change the graph's rejection of feedback loops.
The built-in Delay retains up to 64 queued transitions and emits at most one per settle, preserving
short pulses for downstream counters even after a late wake. Changing its seconds resets its queue.
Random integer and Sample & hold sample once on a late wake and schedule their next interval from
that wake. Duration inputs use seconds; the host contract uses milliseconds.

Static exports, library thumbnails, and input inspection call only `compute`, never `transition`.
Offline HTML starts a new timeline from the exported durable state and uses the same transition
contract. Timed changes save state without creating an undo entry on every tick. This extension
keeps the graph acyclic; it does not add events, actions, feedback loops, or shared-bus resolution.

A boolean **output** may declare `triState:true` to permit `null` as an explicit high-impedance
value, shown as **Z**. Ordinary boolean outputs still accept only `true` or `false`; numeric and
string ports, input literals, and defaults never accept `null`. The graph validates the declared
output before publishing Z. A component producing Z remains healthy and interactive. A boolean
consumer of Z does not run `compute()` or receive a fabricated value; it remains unavailable until
the source drives true or false again. Valid bindings to Z can be saved in **Inputs…**, while other
input, type, or cycle errors still prevent saving. This status propagates through dependent
components in both the editor and exported HTML. Inputs retain one source each; this does not add
shared buses, pull-up/down resolution, or electrical simulation.

The host appends `{inputs, outputs, name}` as the final `io` argument to these v2 hooks.
`name` is the instance name from **Inputs…**, or an empty string for unnamed imports. It is
presentation metadata: renaming redraws the instance without changing computed port values.
Every built-in API v2 component uses it as the visible caption, falling back to its catalog name
when empty. Captions fit within the shape, with wrapping or truncation for long names, and remain
separate from numeric readouts, state labels, and operation symbols.

```text
children(state, style, w, h, editing, io)
handles(state, w, h, style, io)
hitEdit(state, lx, ly, w, h, style, io)
dragEdit(state, handle, lx, ly, w, h, style, io)
exportBehavior(state, io)
```

V2 `dragEdit` must return **`{state: newState}`**, optionally with **`size: {w, h}`** (either
field may be omitted; each 20–2000) to resize the container in the same step, for example a
spreadsheet growing by one column. The editor applies the size with the top-left corner fixed, as one
undo step together with the state; offline HTML ignores it. No other envelope fields are supported;
events and effects are not part of v2. `initState()` still returns the raw state object.
Unversioned scripts keep returning raw state from `dragEdit`, even when their state happens
to have keys named `state`, `emit`, or `effects`. The runtime never guesses the contract from keys.

Select an instance and click **Inputs…** to name it, enter literal inputs, or bind inputs to
compatible outputs in the same sketch. Deployments can disable component authoring with
`features.smartComponents:false` in `settings.json`; existing components still execute and export.
The flag hides component templates, source editing, and input controls, and blocks adding component
library entries. Ordinary smart-shape authoring has its own `smartShapeAuthoring` switch, which
must also be enabled to author components. A binding takes precedence over a saved literal; an
unbound input uses its literal, then its declared default. Missing required inputs, missing
sources/ports, type mismatches, cycles, and failed computations report errors. Failed outputs
are unavailable to consumers; healthy independent components continue working.

### Unavailable drawings

An optional v2 hook keeps a recognizable shape on screen before its inputs are connected:

```text
unavailableChildren(state, style, w, h, editing, io)
```

Here `io` is **`{inputs:{}, outputs:{}, error: message, name}`**. The maps are empty, even if some
inputs are valid; no old or fabricated values are supplied. Use the saved `state` only for
configuration such as a threshold or indicator visibility, and draw a neutral placeholder
for unavailable data. The hook returns child descriptors with the same validation, limits,
and sandbox as `children()`. It does not produce outputs, update state, or request refreshes.

The editor passes its current `editing` flag; static exports and interactive HTML pass `false`
to this hook. For unavailable inputs, the host skips `compute()` and invokes this hook instead
of `children()`. Handles cannot be used. The app draws a status card when no unavailable hook is
available or its drawing fails. A drawing-hook failure also disables component interactions
until a valid drawing recovers. Unsupported scripts still cannot execute either hook.

The built-in logic entries implement this hook with their normal silhouette, **—** values,
amber indicators when enabled, and a short input-status note. The boolean gates are AND, NAND, OR, NOR,
XOR, XNOR, NOT, and Buffer. Compare uses numeric `value` and `b` inputs, a string `operation`
selected from `>`, `≥`, `<`, `≤`, `=`, and `≠`, and a boolean output. B defaults to 70; the operation
defaults to `>`. Both operands can be connected, and equality is exact numeric equality;
[Inverter (×−1)](examples/number-inverter.js) uses numeric input and output. Its computation
is `-inputs.value`, whereas NOT computes `!inputs.value` on a boolean.

[Math](examples/math.js) declares numeric `a` and `b` inputs, a string `operation` input with
`options:['+','−','×','÷','min','max']` and default `'+'`, and numeric `value` output. Choose the operation in
**Inputs…**; subtraction and division use `a` as the left operand. Division by zero and nonfinite
results fail computation, leaving outputs unavailable until corrected. Computation errors expose
their message as bounded plain text; other failing hooks retain the generic failure message.

These entries store the indicator preference in `state.showIndicators`, defaulting to `true`.
Missing flags in older state also mean on. With valid inputs, their editor-only **Indicators:
on/off** control changes that instance; the saved setting affects editor and exported drawings.
Green/grey indicators mean true/false, blue means an available number (including zero), and
amber means unavailable. The setting does not change computation or port types.

### Saved components

Sketch format 4 stores the API marker on each component and bindings on the receiving item:

```json
{
  "uid": "gauge",
  "componentApi": 2,
  "componentName": "Gauge",
  "bindings": { "value": { "uid": "number-control", "port": "value" } },
  "inputValues": {}
}
```

This is an excerpt; the item also retains its normal geometry, script, and state. The saved
`componentApi` must match the script's `apiVersion`. Unsupported versions keep their source and
saved values but cannot execute. Formats 1–3 remain readable; older app versions should not be
used to edit connected documents. Derived outputs are recomputed, not stored as authoritative data.

Copying, duplicating, or saving a connected selection to the library remaps its internal IDs
as a unit. References outside the selection remain explicitly unresolved, even if a target
sketch contains the same UID. Reconnect those inputs in the dialog. Library placements still
initialize fresh state. Undo/redo restores both state and bindings.

Editor, static exports, library previews, and interactive HTML use the same validated computation
contract. HTML keeps bindings working offline and retains changes across tabs; reopening restores
the exported state. There are no cross-tab bindings, table values, events, or external actions.

## The `style` object

Passed to every hook that takes a `style` argument — the container's own **currently resolved**
style, exactly what the toolbar's Fill/Stroke/Stroke-width/Text-color/Font controls currently
show for this instance:

| Field | Meaning |
|---|---|
| `color` | stroke/line color |
| `fillColor` | fill color |
| `fill` | boolean — is Fill on |
| `strokeOn` | boolean — is Stroke on |
| `textColor` | text color |
| `size` | stroke width |
| `dash` | `'solid'`, `'tight'`, or `'wide'`; unset also means solid |
| `fontFamily`, `fontSize`, `font` | the container's own font settings (`fontFamily` is `sans`, `serif`, `mono`, or `cursive`; `font` is the ready-to-use CSS font string) |
| `presetColors` | the toolbar's own color-swatch palette, as an array of hex strings, in its declared display order |

Use `presetColors` instead of a hard-coded color list/count whenever your shape's design
depends on "however many colors the toolbar actually offers" (the Chart template sizes its max
bar count off this, so it never silently drifts out of sync with the real palette).

## Child descriptors

Each entry `children()` returns is a plain object describing one shape, in **local
coordinates** — `(0,0)` is the container's own top-left, `(w,h)` its bottom-right. The app
shifts every child into world coordinates for you; never add the container's own `x`/`y`
yourself. Every child needs a supported `type` and its required geometry:

| Type | Geometry and type-specific fields |
|---|---|
| `rect`, `ellipse` | Required `x`, `y`, `w`, `h` |
| `line` | Required `x1`, `y1`, `x2`, `y2` |
| `arrow` | Line geometry, plus optional `hs`, `he`, `hsStyle`, `heStyle` (see [Arrowheads](#arrowheads)) |
| `path` | Required `points`: at least one `{x,y}` point. Optional `mode`: `'pen'` (default), `'marker'` (translucent), or `'brush'` (chisel stroke) |
| `text` | Required `x`, `y`, `w`, `h`, `text`; optional `font`, `fontFamily`, `fontSize`, and `align` (`'left'`, `'center'` (default), or `'right'`) |
| `polygon` | Required `points`: `{x,y}` points with optional Bézier controls or arcs. `closed` defaults to `true` and requires at least three points; `closed:false` requires at least two. Optional `fillRule`: `'nonzero'` (default) or `'evenodd'`. Open polygons also support arrowheads |

### Shared fields and defaults

| Field | Accepted values and effect |
|---|---|
| `color`, `fillColor`, `textColor` | CSS hex strings: `#RGB`, `#RGBA`, `#RRGGBB`, or `#RRGGBBAA`; named colors and `rgb()` are not accepted |
| `size` | Stroke width from 0 to 60, including fractions |
| `fill` | Boolean; defaults to `false`. Applies to boxes, ellipses, and closed polygons |
| `strokeOn` | Boolean; defaults to `true`. Controls outlines and visibility of line/arrow strokes |
| `dash` | `'solid'`, `'tight'`, or `'wide'`. Omitted inherits the container's pattern; set `'solid'` explicitly for a continuous stroke. Applies to outlines and line/arrow/polygon strokes |
| `editorOnly` | Boolean; defaults to `false`. When `true`, omitted from SVG, PNG, print, thumbnails, and interactive HTML |

`path` children use `color`, `size`, and their own `mode`; they do not use `fill`, `strokeOn`,
or `dash`. A text child’s `fill`, `fillColor`, `strokeOn`, `size`, and `dash` style its box.
For a label without a box, set `strokeOn:false, fill:false` explicitly. Text itself uses
`textColor`, falling back to `color` if no text color is available.

### Text fonts

Use `font:style.font` to follow the container's current font. Alternatively, specify
`fontFamily:'sans'` and `fontSize:16` directly. Family keys are `sans`, `serif`, `mono`, and
`cursive`; they select the app's predefined system-font stacks. A text child without font settings
uses 16px sans, not the container's font.

The validator rebuilds `font` from a supported family and a size from 0 to 400. A pixel size in
`font` takes precedence over `fontSize`; an explicit `fontFamily` selects the family. Otherwise,
only a recognized app font stack in `font` preserves its family; arbitrary CSS family names fall
back to `sans`. A leading `italic` and a leading weight of `bold` or `100`–`900` are retained;
the default weight is 600. Use the family keys instead of hand-writing font stacks.

Text beginning with a bare `---` first line uses the app's Markdown renderer, just like ordinary
text boxes; see [Text formatting](README.md#text-formatting-and-copying) for supported Markdown syntax.

### Arrowheads

`hs` and `he` are booleans enabling the start and end heads. An `arrow` defaults to no start
head and an enabled end head. An open `polygon` defaults to neither. `hsStyle` and `heStyle`
accept `'open'` (default), `'filled'`, `'open-inverted'`, or `'filled-inverted'` independently.
Use `hs:false` or `he:false` to remove a head; `'none'` is not a valid style value. Closed
polygons and `line` children do not draw heads.

### Bézier points

In a `polygon`, the segment from point `a` to the next point `b` uses `a.c1` as its outgoing
cubic control point and `b.c2` as its incoming control point. Each control is an absolute
`{x,y}` in the same local coordinate frame as the points, not an offset. Omitted controls
use their associated endpoint; with neither control, the segment is straight.

```js
{type:'polygon', closed:false, points:[
  {x:0, y:60, c1:{x:30, y:0}},
  {x:120, y:60, c2:{x:90, y:120}},
]}
```

An `arcTo` on `a` takes precedence over Bézier controls for that segment; see
[Arcs](#arcs-in-a-polygon-child). Use `polygon` for explicit curves: `path` children smooth
their `{x,y}` samples as freehand strokes and do not render these controls or arcs.

### Style inheritance — read this before your shape renders invisible

Only `color`, `textColor`, `size`, and `dash` are inherited onto a child **automatically** — a
child descriptor that omits them gets the container's own current value for free. **`fill`,
`fillColor`, and `strokeOn` are deliberately *not* auto-inherited.** Font settings are not
auto-inherited either; use `font:style.font` for text children. Reference `style.fill`,
`style.fillColor`, `style.strokeOn` explicitly on any child you want to follow the toolbar's own
Fill/Stroke toggles:

```js
children(state, style, w, h){
  return [{
    type:'ellipse', x:0, y:0, w, h,
    color: style.color, size: style.size,          // inherited anyway, but explicit is fine too
    fill: style.fill, fillColor: style.fillColor,   // must be explicit
    strokeOn: style.strokeOn,                        // must be explicit
  }];
}
```

Why: `strokeOn` means something different per type — for a `rect`/`ellipse` it's "show an
outline," but for a `line` it's "is this visible **at all**." Explicit opt-in lets a script
keep essential geometry visible when the toolbar's Stroke toggle is off. The container never
draws its own box, regardless of `strokeOn`; newly authored definitions start with Stroke on.
A **hard-coded** child (Clock's face outline, say) can set `strokeOn:true` and ignore the toggle.

### Your shape is responsible for its own bounds

Children are **never clipped** to the container box — `w`/`h` are inputs, not enforced bounds.
Clamping state only in `dragEdit()` is insufficient: the user can resize the container afterward
without dragging a script handle. Derive effective geometry from the current `w`/`h` in a shared
layout helper, and use it in `children()`, `handles()`, `hitEdit()`, and `dragEdit()` as in the
[worked example](#a-complete-worked-example). Ratios stored in state are another useful option
for geometry that should scale with the box.

Keep lower bounds compatible with tiny containers: a fixed 5px minimum radius cannot fit a box
less than 10px wide. If all painted content must fit, reserve room for stroke thickness, arrowheads,
and labels too. Outside children are otherwise allowed and included in cropped exports, while the
container's selection rectangle and rotation pivot keep their original geometry.

## Arcs in a polygon child

A `polygon` point may carry an optional `arcTo: {cx, cy, r, a1, a2}` — "the segment **leaving**
this point is a circular arc to the next point, not a straight line." Angles are in radians: `0` is
straight up (12 o'clock), increasing **clockwise** — the same convention a clock hand's own
angle math uses, *not* canvas/SVG's native 0-is-3-o'clock convention (the app converts at the
render/export boundary; your script never needs to think about it).

Sketched as a standalone helper below for clarity — in a real script this logic lives as a
`children()`-only local step (or a method on your own script object, like Timer's `_layout()`),
because the Script field expects one expression returning the script object:

```js
// A filled pie wedge from angle a1 to angle a2, radius r, centered at (cx, cy):
function wedge(cx, cy, r, a1, a2, style){
  const start = { x: cx + r*Math.sin(a1), y: cy - r*Math.cos(a1), arcTo: { cx, cy, r, a1, a2 } };
  const end   = { x: cx + r*Math.sin(a2), y: cy - r*Math.cos(a2) };
  return {
    type:'polygon', closed:true, fill:true, strokeOn:false,
    color: style.fillColor, fillColor: style.fillColor,
    points: [ {x:cx, y:cy}, start, end ],   // center -> arc start -> (arc) -> arc end -> back to center
  };
}

// The bow alone (no center point, not filled): drop the center point and set closed:false --
// points: [ start, end ], closed:false
```

A closed `[center, arcStart(with arcTo), arcEnd]` triple draws a genuine pie wedge (`M → L → A →
L → Z`); dropping the center point and `closed:false` draws just the bow itself. Both the Arc
and Timer templates use this. If your sweep can reach a **full turn** (2π), clamp it a hair
short (`Math.min(sweep, 2*Math.PI - 0.0001)`) — SVG's arc command can't represent an exact full
circle (start and end coincide), which would otherwise break your shape's own SVG/HTML export
even though it renders fine on canvas.

## HTML export behavior

An HTML export is one offline file containing the drawing, scripts, saved state, sandbox, and runtime.
Scripted controls work directly, without double-clicking to enter edit mode. Ordinary shapes and
smart-shape containers stay fixed by default. There is no unrestricted resizing.
Authors can independently enable moving a smart shape by its body, rotating it using the round
handle above it, changing its width from a right-edge handle, and changing its height from a
bottom-edge handle. The rotation handle appears after clicking the shape and hides when another
shape or the page is clicked, **Escape** is pressed, or the tab changes. Scripted controls still
respond to the first click.
The corresponding flags are `move`, `rotate`, `resizeWidth`, and `resizeHeight`. Width and height
changes regenerate children with the new `w` and `h`; they do not stretch the rendered drawing.
For example, a ruler extends at its original tick spacing. Each resize preserves the opposite edge,
including after rotation. Hold **Shift** while rotating to snap to absolute **15° increments**,
matching the editor, including the shape's original own and group rotation. Releasing Shift without
moving the pointer keeps the last angle when the gesture ends.

Set permissions once in the script object:

```js
exportBehavior: { move:true, rotate:true, resizeWidth:true },
```

Or derive them from saved state, allowing the creator to configure each placed instance:

```js
exportBehavior(state){
  return { move:state.allowMove === true, rotate:state.allowMove === true,
    resizeWidth:state.allowExtend === true };
},
```

Missing flags are `false`; supplied flags must be booleans. The function receives a copy of state
and cannot mutate the saved instance. `initState()` and `initStyle()` are not called when an HTML
file opens: it resumes the exported state, style, and dimensions. State, movement, rotation, and
dimension changes in the page are kept in memory across exported tab switches; reopening/reloading
restores the export.
Only the visible tab refreshes, and refreshes stop while the browser document is hidden.

For creator-only permission controls, mark **every visual child and its matching handle**:

```js
// Within children(), usually guarded by `if(editing)`:
{type:'text', x:0, y:h+6, w, h:24, text:'Allow moving', editorOnly:true},
// Within handles():
{id:'allowMove', x:w/2, y:h+18, kind:'click', editorOnly:true},
```

Keep normal `hitEdit()`/`dragEdit()` logic for that ID; the editor runs it normally. Exported
renderers filter marked children, and HTML rejects marked handle IDs even if `hitEdit()` returns
them. Marking a child does not automatically mark its handle. Unmarked operational controls such
as stopwatch Start/Pause or ruler units remain available. The ruler example demonstrates both
permission toggles, off by default, with undo and sketch/workspace persistence. Its single
**HTML: move / rotate** toggle binds both `move` and `rotate` to `state.allowMove`;
**HTML: extend** controls width separately.

The same Worker isolation, timeouts, reply validation, and network restrictions apply in HTML.
A failing script keeps its last drawing (initially the frozen SVG) and retries after a backoff.
If JavaScript is disabled or unavailable, the initial SVG remains visible. The HTML contains the
original shape source; `editorOnly` filters presentation and interaction, not source-code access.

### Live updates and exports

The app owns one refresh timer for the active document and stops it while the browser document is
hidden. Returning to a document refreshes live readings. Removing a shape, replacing its script,
or changing tabs cancels its scheduling. Refreshes only redraw: they never mutate state, add undo
entries, or autosave. Interactive controls remain available when smart-shape authoring is disabled.

Derive readings from timestamps (`Date.now()` or `new Date()`), rather than incrementing counters
on each call. Redraws can be delayed, and Worker-local variables are disposable. Store a stopwatch's
accumulated elapsed time and start timestamp in state; Start/Pause/Reset are ordinary `dragEdit`
actions. The shipped stopwatch continues elapsed time across tab switches and reloads, and starts
stopped when placed afresh.

PNG, SVG, printing, and library thumbnails request fresh children once without starting refresh timers
or invoking `refreshMs`. HTML includes an initial frozen SVG and then runs the smart shapes in an
isolated runtime, including `refreshMs`, while its tab is visible. JSON sketches and workspaces
retain the script and state, so live shapes resume when opened in SimpleCanvas.

## Fixed units and physical printing

[Ruler](examples/ruler.js) and [Drill template](examples/drill-template.js) both use
**96 canvas px = 1 inch = 25.4 mm**. Resizing the ruler changes how far its scale extends; it never
stretches the unit spacing. Its edit-mode unit control cycles cm/mm, inches, and px. Fine divisions
are omitted on exceptionally long rulers to stay within the child budget, preserving the scale.
The `_scales` definitions in the example can be changed to make custom scales. The drill template
uses the same conversion for hole diameter and offsets; resizing changes its hole spacing.

SVG exports have matching physical dimensions and viewBox dimensions, including fractional pixels.
Print SVG at **Actual size / 100%**, without fitting to the page. Default PNG exports are 2× resolution:
**192 image pixels represent one inch**, so place/print at 192 pixels per inch for the same scale.
Cropping includes margins and outside labels; do not treat the complete image width as the ruler's
marked length. The app's **File → Print** preview defaults to **Actual size (100%)** and **Landscape**,
with paper selection, orientation, margins, an oversize warning, and an optional 50 mm reference mark. Print uses a frozen
SVG snapshot with edit controls removed. Choose the same paper and orientation, **100% / Actual
size**, no extra margins, and no headers/footers in the browser print dialog; its settings and the printer driver can
still rescale output. Check a known division on a printed template before use.

## Constraints and sandbox

- **Script length**: 50,000 characters. **State**: 4,000 characters once `JSON.stringify`'d.
  Both are enforced at execution as well as load. Oversized state updates are rejected, not
  truncated. State contains only JSON data, has at most 16 levels, and cannot use the keys
  `__proto__`, `prototype`, or `constructor`. The longest shipped example is below this limit.
  A missing saved state defaults to `{}`; a supplied invalid state rejects that imported item.
- **Result limits:** 1,000 children, 20,000 points across the whole result, 2,000 characters per
  text child and 20,000 total text characters. A serialized reply is limited to 512 KiB. Geometry
  must contain finite numbers between -1,000,000 and 1,000,000. Negative local coordinates and
  signed box dimensions are allowed; finite negative arc radii normalize to zero. Stroke sizes
  range from 0 to 60, including fractional sizes. Text fonts are rebuilt from supported families
  and a size between 0 and 400. Colors use CSS hex notation; flags must be booleans. Unknown child
  fields are discarded, an invalid child is skipped with an error, and an exceeded result budget
  rejects the whole result rather than truncating it. Renderer guards remain in place.
- **Sandboxed.** A smart shape's script is real JavaScript, but it never runs in the page's own
  scope — every hook (including `compute`, drawing, interaction, and initialization hooks) is
  called inside an instance-owned Worker created by a trusted hidden `srcdoc` frame with
  `sandbox="allow-scripts"` and no same-origin permission. Its restrictive Content Security Policy
  blocks network connections and external scripts, including native prototype API calls and
  dynamic module imports. The Worker inherits that policy from its local Blob source. Script source
  is sent as data; it is never inserted into the frame's HTML. The opaque origin separates it from
  the app's storage, and a Worker exposes no page DOM. The frame and main app exchange messages over
  a dedicated MessageChannel. The trusted manager binds replies to their originating Worker and
  active request; a script's echoed identifiers cannot target another instance. Requests wait in a
  trusted queue, with one dispatched at a time. Worker startup has a separate two-second deadline;
  the 250 ms hook deadline begins after that Worker's startup, so queue wait does not consume it.
  A timeout terminates only that instance's Worker and preserves healthy queued work. Failed live
  drawings retain their last valid children and retry after a three-second backoff without requiring
  another user interaction. Browser-level memory exhaustion is not a resource quota this boundary
  can enforce. The app remains one HTML file and supports hosted and local use.
- Workers start lazily. At most four instance Workers remain resident; the least recently used idle
  Worker is terminated before its slot is assigned a fresh realm. A resident Worker reuses only its
  own instance's compiled definition. Initialization, authoring and non-live previews/exports use
  temporary owners, retired when their operation ends. App-owned state survives eviction, save/load,
  and undo/redo; eviction does not rerun initialization. Live drawing/handle caches and execution
  owners are retired when an item leaves the active document or its script is replaced. Late
  replies cannot recreate removed entries or commit state from an old source generation.
- Children cannot be nested smart shapes, tables, or asset-referencing images. Use the documented
  primitives above. Bézier controls (`c1`/`c2`) and polygon arcs (`arcTo`) are preserved.

## Library catalog and snapshots

The small shape popup shows the working collection. The optional expanded browser offers
**All collections**, **Built-in**, and **Mine** views, search, and the categories Controls, Logic, Displays,
Tools & time, and Drawing. Entries can be placed directly or kept in the working collection
for later use. A filled pin means the entry is in that collection; an outline pin means it is
outside. The pin toggles membership, as do **Keep in collection** / **Remove from collection**
in the details. Unpinning leaves its definition and placed objects unchanged. **Copy to mine**
creates an independent definition for authoring and pins that copy. **Edit details** updates a
user entry's name, category, description, and tags without changing its script.

Library format 2 retains the self-contained `shapes` definition table, adds stable entry IDs
and optional category/tag metadata, and records working membership in `workingCollection`.
Library-entry IDs are separate from the UIDs of canvas items and component bindings. Renaming
or categorizing an entry therefore does not change a placed component's connections.
Older flat `{shapes:[...]}` libraries remain readable and initially include every imported
entry in the working collection. Export includes every user entry and the definitions needed by saved references,
including snapshots of kept built-ins; an import must not silently substitute a newer definition.
Importing user entries does not replace the built-in catalog.

The catalog does not change the component API or placement lifecycle. Each placement clones its
definition, remaps internal component bindings, and initializes smart state and style. Existing
canvas instances and exported HTML retain their own definition snapshots. Library changes,
including working membership, require explicit library export; sketch autosave does not save them.

Deployment switches continue to separate authoring from use. `shapeLibrary` hides the library;
`shapeLibraryManagement` disables catalog changes and pins. Adding smart definitions to the working
collection or copying them into Mine requires `smartShapeAuthoring`, and API v2 definitions also
require `smartComponents`. The browser and direct placement remain available when management or
authoring is disabled. Those switches do not disable existing controls, connections, or HTML
playback. They do not grant network access to component scripts.

## Library previews

Library exports include a 128×128 PNG thumbnail and a versioned fingerprint of its source items.
The fingerprint detects stale previews; it does not certify a library's source or safety. PNG
headers, dimensions, and size are checked on import, and decoding failures become missing previews.
Ordinary shape previews are generated automatically. A missing imported smart-shape preview displays a
placeholder until you approve script execution. Opening an automatically loaded library asks once;
declining still lets you use the library. **Generate missing previews…** offers the choice again.
Automatic preview creation or recovery does not mark the library as having unexported changes.
Newly authored or replaced entries regenerate previews, and exporting retains generated PNGs so
future imports can display them without running scripts. Placing/editing a smart shape still runs
its hooks inside the sandbox. Built-in previews ship with the app. Renaming, categorizing,
tagging, or keeping an entry does not require a new picture; changing its drawing or script does.

A selection can combine ordinary shapes and components. If a component's input source is outside
the selection, its copied binding stays unresolved and the preview draws its unavailable state
alongside the other shapes. A component without `unavailableChildren()` uses the host status card;
missing inputs alone do not prevent thumbnail generation. Drawing-hook failures still report an error.

Thumbnails and cropped SVG/PNG exports include painted children outside the container, including
outside labels and thick outlines. The editable container and rotation pivots keep their geometry.

- [Seven-segment display](examples/seven-segment-display.js): authoring Input mode selects
  `number` (default) or `segments`. Number mode requires integer `value` in 0–9; segments mode
  exposes boolean `a`…`g` inputs, all default false. Both modes include boolean `decimalPoint`
  (false) and `enable` (true). Fixed boolean outputs `a`…`g` and `decimalPoint` describe the visible
  segments after enable is applied; disabling sets every output false. The drawing uses the
  conventional segment positions, the instance caption, dim off segments, and amber unavailable
  segments. Mode changes alter input declarations, not output names or types.
- [LED matrix (8×8)](examples/led-matrix.js): authoring Input mode selects `boolean` (default)
  or `rows`. Boolean mode exposes `row1`…`row8` and `col1`…`col8`, all default false;
  each LED is the AND of its row and column, with every active crossing shown. Row 1 is topmost
  and column 1 leftmost. Rows mode exposes numeric `r1`…`r8` (default 0), each an integer in
  0–255; `r1` is the top row, bit 128 is leftmost, and bit 1 rightmost. A row byte of 129 lights
  both ends, 255 lights every LED, and 0 lights none. Both modes include
  boolean `enable` (default true) and fixed numeric outputs `r1`…`r8` describing the visible row
  bytes, or eight zeros when disabled. Mode-specific input names keep row/column Boolean ports
  distinct from row-byte ports. The named display computes directly from current inputs, with
  no scan cycle or persistent frame buffer.
- [Compare](examples/compare.js): two live numeric operands and six selectable comparison operators.
- [Inverter (×−1)](examples/number-inverter.js): numeric negation, distinct from boolean NOT.
- [Math](examples/math.js): two numeric inputs and selectable arithmetic, minimum, or maximum.
- [Clamp](examples/clamp.js): limit a number to inclusive `min`/`max` bounds.
- [Range mapper](examples/range-map.js): linear input/output range conversion, clamped by default;
  increasing input bounds and reversed output bounds are supported.
- [Number function](examples/number-function.js): absolute value, nearest integer, floor, or ceiling.
  Nearest-integer rounding uses JavaScript's `Math.round` rule: half values toward positive infinity.
- [Selector (number)](examples/selector-number.js) and
  [Selector (Boolean)](examples/selector-boolean.js): false chooses A, true chooses B; both inputs
  must be available. The graph eagerly resolves every declared input; selection never suspends
  the unselected source.
- [Stepped switch (number)](examples/stepped-selector-number.js) and
  [Stepped switch (Boolean)](examples/stepped-selector-boolean.js): `in1`…`inN` route to `value`.
  Unbound channels default to 0/false; all declared channels still require valid values.
- [Stepped distributor (number)](examples/stepped-distributor-number.js) and
  [Stepped distributor (Boolean)](examples/stepped-distributor-boolean.js): required `value` routes
  to one of `out1`…`outN`; inactive outputs are 0/false.
  Both stepped families have a Channels setting (2–16, initially 4), boolean `pulse` and `reset`
  inputs, and numeric `position` output. Every rising pulse advances 1…N and wraps; held reset
  selects 1 and tracks the pulse. Saved position survives restoration without a phantom step.
  Changing Channels resets position to 1 and re-primes, using durable `configuredChannels` to
  detect the change even if transient memory was cleared.
- [Shift register (Boolean)](examples/shift-register-boolean.js) and
  [Shift register (number)](examples/shift-register-number.js): a Stages setting (1–16, initially
  4), required typed `value`, and boolean `pulse`/`reset` inputs (both default false). Each rising
  pulse shifts one snapshot of the old cells: data enters `q1`, old `q1` enters `q2`, and so on.
  Dynamic outputs `q1`…`qN` expose every cell; `value` aliases current `qN`. `shiftedOut` captures
  old `qN` on that edge and holds it between edges. For a shared-pulse cascade, wire `shiftedOut`
  to the next register's `value` and share pulse/reset. With independent clocks, `qN` can supply
  the current last cell instead. Numbers must be finite; they need not be integers.
  Reset clears cells and `shiftedOut` to false/0. Held reset tracks pulse so release-high does
  not shift; manual Reset works in editor and reader. Changing Stages clears storage and
  re-primes pulse detection. Reload/copy/undo preserve storage and start fresh observation;
  library placement initializes empty cells. Each cell is drawn individually alongside the
  instance name, with optional indicators. This bounded internal state does not permit graph cycles.
- [Trigger](examples/trigger.js): a pushbutton producing a 100 ms boolean pulse per click;
  queued presses have a 10 ms low gap. Transient observation prevents replay after restoration.
- [Pulse generator](examples/pulse-generator.js): boolean output with period `seconds` (0.02–3,600),
  high time `width`, and `enable`. High and low time are each at least 0.01 seconds. Starts low,
  first pulse after a full period; disable or timing changes restart low. Late wakes advance one
  phase from the wake time without a burst of missed periods.
- [Edge to pulse](examples/edge-pulse.js): rising, falling, or either observed edge produces a pulse
  of `seconds` (0.01–3,600). Initial level is primed without a pulse. Up to 64 waiting pulses have
  a minimum 10 ms low gap; reconfiguration/restoration discards pending pulses and re-primes.
- [Delay](examples/delay.js): preserve boolean transitions with a configured delay in seconds.
- [Counter](examples/counter.js): boolean `value` and `reset`; string `direction` with options
  `up`/`down` (default `up`); numeric `start` and `threshold` (both default 3, nonnegative safe
  integers). Up starts/resets at zero, increments per rising edge, and publishes `reached` when
  `count >= threshold`. Down starts/resets at start, decrements per rising edge, clamps at zero,
  and publishes `reached` when `count === 0`; threshold does not determine down-mode completion.
  Changing direction, or start while down, restarts and re-primes without counting that evaluation.
  Threshold changes and start changes while up keep the current count. Reload/copy/undo preserve
  the saved count and prime edge memory without replay. Held reset tracks the input; release
  during high does not count. Manual Reset uses the same baseline in editor and HTML. The drawing
  shows the direction arrow, an up-mode ≥ threshold or down-mode zero target, and the down start.
- [Random integer](examples/random-integer.js): inclusive integer range, one sample per second.
- [Sample & hold (integer)](examples/sample-hold-integer.js) and
  [Sample & hold (Boolean)](examples/sample-hold-boolean.js): sample immediately and hold for a
  configured duration, with fixed typed ports.
- [Tri-state buffer](examples/tri-state-buffer.js): boolean data and active-high enable; outputs
  the data when enabled or Z when disabled. Its purple Z indicator differs from amber missing inputs.

should be draggable, and whether it should follow the toolbar's own Fill/Stroke colors or use

Ask explicitly for the output to be **one script**, in the exact object
literal form these templates use, with synchronous hooks. The result should paste directly into
the Script field without instructions, a diff, or a `<script>` tag.
